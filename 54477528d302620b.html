二、同步 vs 异步 ⭐

2.1 同步调用的问题

以支付业务为例，OpenFeign 同步调用存在三大问题：

问题 说明
扩展性差 每新增下游服务（短信、积分）就要改支付代码，违反开闭原则
性能下降 调用链越长，响应越慢（3 个 50ms 服务 = 150ms+）
级联失败 下游某服务故障 → 整个事务回滚

2.2 异步调用的优势

text
支付服务 → Broker（MQ） ← 订阅 ← 通知服务
                        ← 订阅 ← 积分服务
                        ← 订阅 ← 交易服务
  • 解耦：支付服务只管发消息，不关心谁消费
  • 性能好：发完消息立即返回，不等下游
  • 扩展性强：新增消费者不改发送方代码
  • 故障隔离：下游故障不影响上游

⚠ 缺点：依赖 Broker 可靠性，架构复杂

2.3 MQ 技术选型

RabbitMQ ActiveMQ RocketMQ Kafka
语言 Erlang Java Java Scala/Java
吞吐量 一般 差 高 非常高
消息延迟 微秒级 毫秒级 毫秒级 毫秒内
可靠性 高 一般 高 一般

💡 国内使用最多 RabbitMQ：可靠性高、延迟低、生态成熟。

三、RabbitMQ 核心概念 ⭐⭐

3.1 架构图

text
Publisher（生产者）
      ↓
  Exchange（交换机）—— 负责路由
      ↓ routing
   Queue（队列）—— 存储消息
      ↓
Consumer（消费者）

3.2 核心组件

组件 作用
publisher 生产者，发送消息的一方
consumer 消费者，接收消息的一方
queue 队列，暂存消息
exchange 交换机，负责路由（本身不存消息）
virtual host 虚拟主机，数据隔离（类似命名空间）

⚠ 交换机不存储消息，消息未路由到队列就会丢失！

4.3 发送消息

java
@Autowired
private RabbitTemplate rabbitTemplate;

// 发送到指定队列（不经过交换机）
rabbitTemplate.convertAndSend("hello.queue1", "Hello, RabbitMQ!");

// 发送到交换机（带 routingKey）
rabbitTemplate.convertAndSend("hmall.direct", "red", "Hello, Red!");

4.4 接收消息

java
@Component
public class MqListener {

    @RabbitListener(queues = "hello.queue1")
    public void listenHelloQueue(String msg) {
        System.out.println("消费者1 收到消息：" + msg);
    }
}

五、WorkQueue 工作队列 ⭐

多个消费者共同消费同一个队列，每条消息只会被一个消费者处理。

java
// 消费者1
@RabbitListener(queues = "work.queue")
public void listenWorkQueue1(String msg) throws InterruptedException {
    System.out.println("消费者1：" + msg + " " + LocalTime.now());
    Thread.sleep(20);  // 处理快
}

// 消费者2
@RabbitListener(queues = "work.queue")
public void listenWorkQueue2(String msg) throws InterruptedException {
    System.err.println("消费者2：" + msg + " " + LocalTime.now());
    Thread.sleep(200); // 处理慢
}

5.1 能者多劳配置

默认情况下 RabbitMQ 平均分配消息（不管消费者处理速度），配置 prefetch 实现能者多劳：

yaml
spring:
  rabbitmq:
    listener:
      simple:
        prefetch: 1  # 每次只预取1条，处理完再取下一条

💡 prefetch=1 是关键！默认轮询分配，配置后快的消费者能拿到更多消息。

六、交换机类型 ⭐⭐⭐

6.1 Fanout（广播交换机）

消息发到所有绑定的队列，不做路由。

text
Exchange(fanout)
    ├──→ queue1 → consumer1
    └──→ queue2 → consumer2

声明（注解方式）：

java
@RabbitListener(bindings = @QueueBinding(
    value = @Queue(name = "fanout.queue1"),
    exchange = @Exchange(name = "hmall.fanout", type = ExchangeTypes.FANOUT)
))
public void listenFanoutQueue1(String msg) {
    System.out.println("消费者1：" + msg);
}

发送：

java
rabbitTemplate.convertAndSend("hmall.fanout", "", "Hello, Fanout!");
// routingKey 为空，Fanout 会忽略

6.2 Direct（路由交换机）

按 routingKey 精确匹配投递到对应队列。

text
Exchange(direct)
    ├── red  → queue1 → consumer1
    ├── blue → queue2 → consumer2
    └── red  → queue2 → consumer2（一个队列可绑多个key）
java
@RabbitListener(bindings = @QueueBinding(
    value = @Queue(name = "direct.queue1"),
    exchange = @Exchange(name = "hmall.direct", type = ExchangeTypes.DIRECT),
    key = {"red", "blue"}
))
public void listenDirectQueue1(String msg) {
    System.out.println("消费者1：" + msg);
}
java
// 发送 red 消息 → queue1 和 queue2
rabbitTemplate.convertAndSend("hmall.direct", "red", "Red Message!");

6.3 Topic（主题交换机）

按通配符匹配，routingKey 是 . 分隔的单词序列。

通配符 含义
* 匹配一个单词
# 匹配零个或多个单词
text
china.# → 匹配所有以 china 开头的 key
#.news  → 匹配所有以 news 结尾的 key
china.news → 精确匹配
java
@RabbitListener(bindings = @QueueBinding(
    value = @Queue(name = "topic.queue1"),
    exchange = @Exchange(name = "hmall.topic", type = ExchangeTypes.TOPIC),
    key = "china.#"
))
public void listenTopicQueue1(String msg) {
    System.out.println("消费者1（china.#）：" + msg);
}

6.4 三种交换机对比

交换机 路由规则 适用场景
Fanout 广播，不过滤 日志广播、群发通知
Direct 精确匹配 routingKey 按类型分发（订单、库存分开处理）
Topic 通配符匹配 按业务域分发，更灵活

七、声明队列和交换机 ⭐

7.1 基于 Bean 声明（代码方式）

java
@Configuration
public class FanoutConfig {

    // 声明交换机
    @Bean
    public FanoutExchange fanoutExchange() {
        return new FanoutExchange("hmall.fanout");
    }

    // 声明队列
    @Bean
    public Queue fanoutQueue1() {
        return new Queue("fanout.queue1");
    }

    // 绑定
    @Bean
    public Binding fanoutBinding1(Queue fanoutQueue1, FanoutExchange fanoutExchange) {
        return BindingBuilder.bind(fanoutQueue1).to(fanoutExchange);
    }
}

7.2 基于注解声明（推荐）

java
@RabbitListener(bindings = @QueueBinding(
    value = @Queue(name = "direct.queue1", durable = "true"),
    exchange = @Exchange(name = "hmall.direct", type = ExchangeTypes.DIRECT),
    key = {"red", "blue"}
))
public void listenDirectQueue1(String msg) {
    // ...
}

八、消息转换器 ⭐

8.1 默认转换器的问题

默认使用 Java 序列化（ObjectOutputStream），可读性差、体积大、安全性低。

8.2 配置 JSON 转换器

xml
<dependency>
    <groupId>com.fasterxml.jackson.dataformat</groupId>
    <artifactId>jackson-dataformat-xml</artifactId>
    <version>2.9.10</version>
</dependency>
java
@Bean
public MessageConverter messageConverter() {
    return new Jackson2JsonMessageConverter();
}
java
// 发送 Map 对象（自动转 JSON）
Map<String, Object> msg = new HashMap<>();
msg.put("name", "张三");
msg.put("age", 18);
rabbitTemplate.convertAndSend("object.queue", msg);

// 接收自动反序列化
@RabbitListener(queues = "object.queue")
public void listenObjectQueue(Map<String, Object> msg) {
    System.out.println(msg);
}

九、项目场景（实战导向）⭐

🎯 场景 1：支付成功异步通知

java
// 支付服务 - 支付成功后发消息
@Service
public class PaymentService {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void paySuccess(Long orderId) {
        // 更新支付流水状态
        // ...

        // 发送消息（异步通知其他服务）
        rabbitTemplate.convertAndSend("pay.topic", "pay.success", orderId);
    }
}

// 交易服务 - 监听支付成功
@Component
public class PayMessageListener {
    @RabbitListener(bindings = @QueueBinding(
        value = @Queue("trade.pay.success.queue"),
        exchange = @Exchange(name = "pay.topic", type = ExchangeTypes.TOPIC),
        key = "pay.success"
    ))
    public void listenPaySuccess(Long orderId) {
        // 更新订单状态
    }
}

十、面试常问 ⭐⭐

💡 RabbitMQ 的四种交换机类型？

  • Direct：精确匹配 routingKey
  • Fanout：广播，忽略 routingKey
  • Topic：通配符匹配（* 一词，# 多词）
  • Headers：按消息 Header 匹配（极少用）

💡 消息丢失怎么解决？ 见 MQ 高级篇：生产者确认 + 消息持久化 + 消费者确认

💡 WorkQueue 中如何实现能者多劳？ prefetch: 1，每次只预取一条，处理完再拉下一条

💡 Fanout 和 Direct 的区别？ Fanout 广播到所有绑定队列，Direct 按 routingKey 路由
