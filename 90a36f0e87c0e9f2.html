二、认识 Redis ⭐

2.1 NoSQL vs SQL

维度 关系型（MySQL） 非关系型（Redis）
数据结构 结构化表 灵活（KV/文档/图）
关联关系 外键约束 无，业务维护
查询方式 SQL 标准 各异
事务 完整 ACID 基本一致性
存储 磁盘 内存（快）
扩展 垂直扩展 水平扩展

2.2 Redis 特点

  • 键值型：key 是 String，value 支持多种结构
  • 单线程：每个命令原子性
  • 速度快：基于内存 + IO 多路复用
  • 持久化：RDB + AOF
  • 集群：主从 + 分片

Redis 全称：Remote Dictionary Server（远程词典服务器）

三、安装与配置

3.1 配置文件（redis.conf）

properties
# 允许任意 IP 访问（生产环境谨慎）
bind 0.0.0.0
# 后台守护进程运行
daemonize yes
# 访问密码
requirepass 123321
# 端口
port 6379
# 最大内存
maxmemory 512mb
# 日志文件
logfile "redis.log"
# 数据库数量（默认16个，编号0~15）
databases 16

3.2 启动与停止

bash
redis-server redis.conf       # 启动
redis-cli -h 127.0.0.1 -p 6379 -a 123321   # 连接
redis-cli -a 123321 shutdown   # 停止

3.3 Docker 安装（推荐）

bash
docker run -d \
  --name redis \
  -p 6379:6379 \
  redis:latest \
  redis-server --requirepass 123321

四、通用命令 ⭐⭐

bash
KEYS pattern        # 查找 key（生产不推荐，O(N)）
DEL key [key...]    # 删除
EXISTS key          # 判断是否存在（1存在，0不存在）
EXPIRE key seconds  # 设置过期时间
TTL key             # 查看剩余时间（-1永不过期，-2已过期）
TYPE key            # 查看 key 的类型

⚠ 生产环境禁用 KEYS *，key 过多时会阻塞 Redis！

五、五种数据类型 ⭐⭐⭐

5.1 String（字符串）⭐⭐⭐

value 可以是字符串 / 整数 / 浮点数。

bash
SET key value           # 设置（存在则覆盖）
GET key                 # 获取
MSET k1 v1 k2 v2       # 批量设置
MGET k1 k2             # 批量获取
SETNX key value         # 不存在才设置（分布式锁常用）
SETEX key seconds value # 设置并指定过期时间
SET key value EX seconds # 同上，推荐写法

INCR key               # 整数自增 1
INCRBY key num         # 整数自增 num
INCRBYFLOAT key num    # 浮点自增
DECR key               # 自减 1

Key 层级结构（推荐）：

bash
# 格式：项目名:类型:id
SET heima:user:1 '{"id":1,"name":"Jack","age":21}'
SET heima:order:101 '{"id":101,"amount":99.9}'

使用场景：

  • 缓存 JSON 对象
  • 计数器（浏览量、库存）
  • 分布式 ID（INCR id 生成唯一 ID）
  • 分布式锁（SETNX）

5.2 Hash（哈希）⭐⭐

value 是一个无序字典，适合存储对象的各个字段。

bash
HSET key field value        # 设置一个字段
HGET key field              # 获取一个字段
HMSET key f1 v1 f2 v2      # 批量设置
HMGET key f1 f2             # 批量获取
HGETALL key                 # 获取所有字段和值
HKEYS key                   # 获取所有字段名
HVALS key                   # 获取所有字段值
HLEN key                    # 字段数量
HDEL key field              # 删除字段
HSETNX key field value      # 字段不存在才设置
HINCRBY key field num       # 字段自增

String vs Hash 存对象对比：

String Hash
存储方式 整个对象序列化为 JSON 每个字段独立存储
修改字段 需要全量读写 直接修改单字段
适合场景 整体读取 频繁修改单字段

使用场景：购物车（HSET cart:uid itemId count）、用户信息缓存

5.3 List（列表）⭐⭐

双向链表，有序可重复，可从两端操作。

bash
LPUSH key v1 v2    # 左侧插入（结果：v2 v1）
RPUSH key v1 v2    # 右侧插入
LPOP key           # 左侧弹出
RPOP key           # 右侧弹出
LRANGE key 0 -1    # 查看所有（-1表示最后一个）
LLEN key           # 长度
BLPOP key timeout  # 阻塞等待弹出（超时返回nil）

常见模式：

模式 实现
栈（LIFO） LPUSH + LPOP
队列（FIFO） LPUSH + RPOP
阻塞队列 LPUSH + BLPOP

使用场景：消息队列（轻量）、朋友圈动态、最新文章列表

5.4 Set（集合）⭐⭐

无序、不重复，底层是 hash 表，查找 O(1)。

bash
SADD key m1 m2     # 添加元素
SREM key m1        # 删除元素
SCARD key          # 元素数量
SISMEMBER key m    # 判断是否存在（1存在）
SMEMBERS key       # 获取所有元素

# 集合运算
SINTER k1 k2       # 交集（共同好友）
SDIFF k1 k2        # 差集（k1有但k2没有）
SUNION k1 k2       # 并集

使用场景：

  • 共同好友（交集）
  • 抽奖（SRANDMEMBER 随机取）
  • UV 统计（用户 ID 去重计数）
  • 标签系统

5.5 SortedSet（有序集合）⭐⭐⭐

有序、不重复，每个元素带 score 分数，底层是跳表（SkipList）。

bash
ZADD key score member        # 添加元素
ZREM key member              # 删除
ZSCORE key member            # 获取分数
ZRANK key member             # 获取升序排名（从0开始）
ZREVRANK key member          # 获取降序排名
ZCARD key                    # 元素数量
ZINCRBY key increment member # 分数自增

# 范围查询
ZRANGE key min max           # 按排名范围查（升序）
ZREVRANGE key min max        # 按排名范围查（降序）
ZRANGEBYSCORE key min max    # 按分数范围查
ZRANGEBYSCORE key min max WITHSCORES  # 带分数

# 集合运算
ZDIFF / ZINTER / ZUNION

💡 降序命令规律：在 Z 后加 REV，如 ZREVRANK、ZREVRANGE

使用场景：

  • 排行榜（游戏、销售额）
  • 延迟队列（score 存时间戳）
  • 滑动窗口限流

六、五种数据类型对比 ⭐⭐

类型 特点 底层结构 典型场景
String 简单 KV SDS 缓存、计数、锁
Hash 字段独立 ziplist/hashtable 用户信息、购物车
List 有序可重复 ziplist/quicklist 消息队列、动态
Set 无序不重复 hashtable 标签、共同好友
SortedSet 有序不重复 ziplist/skiplist 排行榜

七、Java 客户端 ⭐⭐⭐

7.1 SpringDataRedis（推荐）

依赖：

xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

配置：

yaml
spring:
  redis:
    host: 192.168.150.101
    port: 6379
    password: 123321
    lettuce:
      pool:
        max-active: 8   # 最大连接数
        max-idle: 8
        min-idle: 0

使用：

java
@Autowired
private RedisTemplate<String, Object> redisTemplate;

// String
redisTemplate.opsForValue().set("name", "Jack");
String name = (String) redisTemplate.opsForValue().get("name");
redisTemplate.opsForValue().set("code", "1234", 5, TimeUnit.MINUTES);

// Hash
redisTemplate.opsForHash().put("user:1", "name", "Jack");
redisTemplate.opsForHash().put("user:1", "age", 21);
Map<Object, Object> user = redisTemplate.opsForHash().entries("user:1");

// List
redisTemplate.opsForList().leftPush("list", "a");
String val = (String) redisTemplate.opsForList().leftPop("list");

// Set
redisTemplate.opsForSet().add("tags", "java", "redis");
Boolean isMember = redisTemplate.opsForSet().isMember("tags", "java");

// ZSet
redisTemplate.opsForZSet().add("rank", "user1", 100);
Set<Object> top3 = redisTemplate.opsForZSet().reverseRange("rank", 0, 2);

7.2 配置 JSON 序列化器（重要）⭐

默认使用 Java 序列化（JDK），对象存入 Redis 后乱码。配置 JSON 序列化：

java
@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);

        // key 使用 String 序列化
        template.setKeySerializer(RedisSerializer.string());
        template.setHashKeySerializer(RedisSerializer.string());

        // value 使用 JSON 序列化
        template.setValueSerializer(RedisSerializer.json());
        template.setHashValueSerializer(RedisSerializer.json());

        template.afterPropertiesSet();
        return template;
    }
}

7.3 StringRedisTemplate（更简洁）

如果 value 自己手动转 JSON，直接用 StringRedisTemplate，无需配置序列化：

java
@Autowired
private StringRedisTemplate stringRedisTemplate;

@Autowired
private ObjectMapper objectMapper;

// 存对象
User user = new User("Jack", 18);
String json = objectMapper.writeValueAsString(user);
stringRedisTemplate.opsForValue().set("user:1", json);

// 取对象
String val = stringRedisTemplate.opsForValue().get("user:1");
User u = objectMapper.readValue(val, User.class);

💡 推荐 StringRedisTemplate + 手动 JSON 转换，更清晰可控。

八、项目场景（实战导向）⭐

🎯 场景 1：缓存查询

java
public Shop queryShopById(Long id) {
    // 1. 从 Redis 查
    String key = "cache:shop:" + id;
    String json = stringRedisTemplate.opsForValue().get(key);
    if (StrUtil.isNotBlank(json)) {
        return JSONUtil.toBean(json, Shop.class);  // 命中缓存
    }

    // 2. 查数据库
    Shop shop = shopMapper.selectById(id);
    if (shop == null) return null;

    // 3. 写入缓存（30 分钟过期）
    stringRedisTemplate.opsForValue().set(key, JSONUtil.toJsonStr(shop), 30, TimeUnit.MINUTES);
    return shop;
}

🎯 场景 2：计数器（商品浏览量）

java
// 每次访问 +1
stringRedisTemplate.opsForValue().increment("view:product:" + productId);

// 获取浏览量
String count = stringRedisTemplate.opsForValue().get("view:product:" + productId);

🎯 场景 3：排行榜

java
// 更新分数（销售额）
stringRedisTemplate.opsForZSet().incrementScore("rank:sales", "product_1", 100);

// 获取 TOP 10
Set<ZSetOperations.TypedTuple<String>> top = stringRedisTemplate.opsForZSet()
    .reverseRangeWithScores("rank:sales", 0, 9);

九、面试常问 ⭐⭐

💡 Redis 为什么快？

  1. 纯内存操作
  2. 单线程避免竞争
  3. IO 多路复用（epoll）
  4. 高效数据结构（SDS、跳表等）

💡 Redis 和 MySQL 的区别？ Redis 基于内存、访问快、数据结构丰富，用于缓存热点数据；MySQL 基于磁盘、持久可靠，存全量数据。

💡 五种数据类型的使用场景？

  • String：缓存、计数、锁
  • Hash：用户信息（字段级操作）
  • List：消息队列、时间线
  • Set：去重、共同好友
  • SortedSet：排行榜、延迟队列

💡 KEYS 为什么不能用于生产？ O(N) 操作，key 多时会阻塞 Redis，用 SCAN 替代。
