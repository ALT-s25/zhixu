## 欢迎来到营地

收藏了很多题单，却不知道从哪一道开始；看过一遍教程，真正动手时又忘了关键步骤——知序就是为这些时刻准备的小营地。

在这里，你可以沿专题练习，借助例题理解套路，把资料放进书房，再从完成记录中看到自己的积累。今天只弄懂一道题，也值得打一个认真的勾。

## 第一趟冒险，怎么走？

1. **选路线。** 跟课学习从课程题单开始；准备面试可以先练 Hot 100；系统补基础可以按灵神专题或代码随想录推进。
2. **先理解，再动手。** 卡住时去手册看同类例题，回到原题独立写一遍。题目链接会跳转到原平台，代码提交与评测在那里完成。
3. **留下脚印。** 完成后打勾，记下卡点，把还不熟的题收藏起来。成长页会展示逐步积累的练习记录。

笔记书房适合边学边查：先选大类，再进入 Java、MySQL、Redis、微服务等具体专题，不必在一长串资料里翻找。

## 把自己的资料装进来

在 **导入中心** 选择内容类型，选取文件、检查预览，然后确认导入。

| 内容 | 支持格式 | 导入后的位置 |
| --- | --- | --- |
| 学习笔记 | Markdown、TXT | 笔记书房的“我的导入”，可填写专题 |
| 练习题单 | JSON 数组、Markdown 链接 | 刷题页的“我的导入” |
| 导入资料备份 | 本工具导出的 JSON | 恢复到当前浏览器 |

JSON 题单示例：

```json
[
  {"title": "两数之和", "url": "https://leetcode.cn/problems/two-sum/"},
  {"title": "有效的括号", "url": "https://leetcode.cn/problems/valid-parentheses/"}
]
```

Markdown 题单示例：

```markdown
- [两数之和](https://leetcode.cn/problems/two-sum/)
- [有效的括号](https://leetcode.cn/problems/valid-parentheses/)
```

导入时会检查链接并去除重复题目；与现有题目匹配时复用题目编号，方便共享练习状态。目前暂不支持直接导入 Excel、Word 或 PDF 文件。

**导入资料保存在当前浏览器，不会自动发布到网站，也不会随账号同步。** 换设备前，请在导入中心导出备份，再到新设备恢复。

## 云端资料工作台

新增的 [资料工作台](library.html) 支持 Markdown／TXT／PDF／ZIP 上传、带图预览、缺图检查、内容去重、私人草稿、管理员发布、编辑与回收站恢复。全文搜索可以查找原有笔记正文和可访问的云端资料，并显示命中片段。

需先按 [资料库开通指南](backend/资料库开通指南.md) 执行数据库脚本并配置管理员。原有本地导入不会自动迁移，题单导入仍保存在浏览器。PDF 提取不包含 OCR，AI 讲解尚未接入。

## 我的记录保存在哪里？

| 数据 | 保存方式 |
| --- | --- |
| 游客刷题记录 | 当前浏览器本地保存；登录后可主动导入游客记录 |
| 登录后的刷题记录 | 通过 Supabase 同步到个人账号，请留意页面同步状态 |
| 旧导入中心的题单和笔记 | 当前浏览器本地保存，使用导入中心单独备份 |
| 资料工作台上传的笔记 | Supabase 云端保存，私人资料按账号隔离，管理员可发布 |
| 网站公开题单和笔记 | 随仓库发布，所有访问者可阅读 |

邮箱支持密码登录、验证码登录与找回密码，新邮箱完成验证码验证后可以创建账号。**手机短信和微信登录尚未接入。**

同一道题出现在多个专题时共享练习状态；历史导入记录不会被凭空补上练习日期。清理浏览器数据可能移除本地资料，请保留重要备份。

## 在本地搭起营地

项目采用原生 **HTML / CSS / JavaScript**，无需 npm 安装或构建。下载仓库后，在含 `index.html` 的目录启动静态服务：

```bash
python -m http.server 8765
```

浏览器打开 `http://localhost:8765/` 即可。账号功能需要联网，并配置有效的 Supabase 项目与认证回跳地址。

## 部署到自己的 GitHub Pages

1. 将网站文件放在仓库根目录，保持资源目录结构完整。
2. 在仓库 **Settings → Pages** 中选择从 `main` 分支的根目录发布。
3. 如需账号同步，创建自己的 Supabase 项目，执行 [数据库脚本](backend/schema.sql)。
4. 修改 `cloud-config.js`，填入自己的 Project URL 和公开 Publishable key。
5. 配置站点地址、认证回跳地址、SMTP 与验证码邮件模板，再验证登录及保存功能。

具体步骤见 [账号开通说明](backend/开通账号功能.md) 和 [验证码与其他登录方式说明](backend/验证码与其他登录方式.md)。

Fork 后请连接自己的 Supabase 项目。前端只放公开密钥，数据库密码、SMTP 授权码与服务端密钥不要提交到仓库。
