# 知序后端 · 小芽讲解室 🌱

让“这一段看不懂”，变成一次能继续往下学的小突破。

这是知序的第一版独立 Java 后端。保留现有 Supabase 登录和资料权限，在服务端连接模型，为用户选中的笔记段落生成讲解。

## 这一版能做什么

- 验证 Supabase 登录身份，继续使用网站已有账号。
- 支持站内索引收录的笔记、用户有阅读权限的云端资料。
- 检查选中段落确实来自该资料，不允许借接口读取他人的私人笔记。
- 提供类比讲解、代码例子、步骤拆解三个入口。
- 每人每天默认 20 次、每分钟最多 5 次，全站每天默认 500 次。
- H2 文件数据库保存额度和请求结果，重启不清零；重复请求编号可返回已完成的结果。
- 模型密钥只在 Java 服务端配置。网站只保存后端地址。

这是**单实例本地验证版**，不是已经部署好的云服务。没有配置模型时返回明确的“AI 尚未配置”，不会用固定文本冒充回答。

## 先启动，不用买服务器

需要 Java 21 或更高版本，以及 Maven。你这台电脑已安装 Java 25 和 Maven。

1. 解压后端包，进入包含 `pom.xml` 的目录。
2. 在此目录打开 PowerShell，运行：

```powershell
mvn test
mvn package
java -jar target/zhixu-backend-0.1.0.jar
```

也可以直接使用随附的 `zhixu-backend-0.1.0.jar`：在一个专用文件夹运行 `java -jar zhixu-backend-0.1.0.jar`。

浏览器打开 `http://127.0.0.1:8080/api/v1/health`。没有配模型时，应看到 `status: ok`、`aiConfigured: false`。

默认只监听本机，数据写入启动目录中的 `data/`。每次请从同一个目录启动，避免生成另一份空数据库。不要把运行产生的数据库上传 GitHub。

## 接入真实模型

选择提供 Chat Completions 兼容 API 的服务商，在它的控制台创建密钥。以下都是占位值，必须替换；不需要把密钥发到聊天中。

```powershell
$env:AI_BASE_URL = 'https://你的服务商地址/v1'
$env:AI_MODEL = '服务商提供的模型名称'
$secret = Read-Host '输入模型 API Key（不会回显）' -AsSecureString
$env:AI_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
java -jar target/zhixu-backend-0.1.0.jar
```

接口地址末尾只填 `/v1` 等服务商规定的前缀，不要再填 `/chat/completions`，程序会自动追加。当前适配器使用非流式请求和 `max_tokens: 1800`；并非所有号称兼容的模型都支持该参数，需要按服务商要求验证。

## 连上前端

将前端更新包内的文件覆盖到网站根目录，保持文件名与目录结构。

本地测试时，把 `ai-config.js` 中的地址改为：

```javascript
window.ZHIXU_AI = Object.freeze({ apiBaseUrl: 'http://127.0.0.1:8080' });
```

用本地静态服务打开网站，例如 `http://127.0.0.1:8765/library.html`。8765 是网页端口，8080 是 Java 后端端口，两者不同是正常的。Supabase 登录回跳地址添加网页地址，不是 Java API 地址。

打开一篇笔记 → 选中 5–5000 字正文 → 点击右下角“小芽讲解” → 登录 → 确认发送所选段落 → 生成讲解。登录切换后需重新选段落。

原有笔记的 AI 可用范围以随包的 `library-search-index.json` 为准，新增静态笔记后需要更新索引并重新打包后端；云端资料直接读取最新正文。扫描 PDF 不具备可选文字，本版没有 OCR。

## 上线前需要完成的事

GitHub Pages 只能托管前端，不能运行这个 Java 程序。正式上线需要单独的 Java 运行环境、HTTPS 后端地址和持久磁盘。

- 将 Java 服务部署到单台主机或提供持久磁盘的平台；必要时设置 `BIND_ADDRESS=0.0.0.0`，通过 HTTPS 反向代理开放服务。
- 在平台的环境变量中配置模型密钥，不提交 `.env`、密钥或数据库。
- 把网站 `ai-config.js` 改为真实 HTTPS 后端地址。线上 GitHub Pages 不应配置本机 HTTP 地址。
- 用 `ALLOWED_ORIGINS` 限制前端来源，逗号分隔；填写来源，不包含 `/zhixu/` 路径。
- 测试真实模型、真实 Supabase 账号、私人资料权限及移动端交互。当前自动化使用模拟认证/模型服务，不代表真实供应商已连通。
- 备份 `data/`。本版不支持多副本部署；扩容前将额度事务迁移到共享 PostgreSQL，并补齐运维监控、清理任务及数据库迁移管理。

## 数据、额度与费用

只向模型发送所选段落、提问和讲解偏好，不发送整份资料库或登录令牌。私有笔记也可能包含敏感内容，发送前由使用者确认。

数据库保留用户 ID、请求指纹、状态、时间和生成答案，用于额度及请求去重；不保存登录令牌、模型密钥或原始提问。答案可能包含原文内容，应按私人数据保护。当前没有自动清理答案，正式运营前应制定保留期限。

进入模型调用后，即使上游失败也计一次。调用次数限制不等于金额上限，仍需在模型服务商侧设置预算。自然日按北京时间计算；网络失败后对同一个请求重试不会重复调用已成功完成的请求。服务进程意外退出时，处理中请求保留已用额度，需要用户重新发起。

可配置：`AI_DAILY_LIMIT`、`AI_GLOBAL_LIMIT`、`PORT`、`BIND_ADDRESS`、`ALLOWED_ORIGINS`、`SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`、`DB_URL`（H2 文件地址）、`DB_PASSWORD`。

## 代码入口与后续扩展

- `AssistantController`：API、来源核验、讲解流程。
- `Gateway`：Supabase 身份/资料访问和模型调用。
- `Quota`：持久化额度与幂等请求。
- `WebConfig`：跨域来源配置。
- `src/test`：权限、重复请求、并发额度、模型失败等测试。

下一步适合做“讲解收藏 → 自测题 → 错题复习”。等单段讲解实际用起来，再考虑整库检索问答和引用溯源。
