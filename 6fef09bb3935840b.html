Seata 分布式事务 · 保姆级详解 ⭐⭐⭐

按章节学习你的知识，慢慢成林

难度：高 | 学习建议：2 天 对应黑马 SpringCloud 资料：day05-服务保护和分布式事务 项目导向：微服务跨服务数据一致性问题的核心解决方案

一、为什么需要分布式事务

1.1 单体事务 vs 分布式事务

单体应用（本地事务）：

java
@Transactional
public void placeOrder(Order order) {
    // 1. 扣减库存
    stockService.decreaseStock(order.getItemId(), order.getNum());
    // 2. 创建订单
    orderService.createOrder(order);
    // 3. 扣减余额
    accountService.deductBalance(order.getUserId(), order.getAmount());
    // 以上三步在同一个数据库事务里，要么都成功要么都失败
}

微服务（分布式）：

text
用户下单 → 订单服务（创建订单）
         → 库存服务（扣库存）    ← 不同的数据库！
         → 账户服务（扣余额）    ← 不同的数据库！

问题：如果扣库存成功，但扣余额失败，订单数据就不一致了！

分布式事务的难点：多个服务、多个数据库，无法用单机的 @Transactional。

二、Seata 是什么

Seata（Simple Extensible Autonomous Transaction Architecture）是阿里开源的分布式事务解决方案。

Seata 三大角色：

text
TC（Transaction Coordinator）事务协调者：Seata Server，协调全局事务
TM（Transaction Manager）事务管理者：发起全局事务的服务（订单服务）
RM（Resource Manager）资源管理者：参与全局事务的服务（库存、账户服务）

三、Seata 的四种模式

模式 全称 原理 优点 缺点
XA X/Open XA 协议 两阶段提交 强一致性，回滚安全 锁表时间长，性能差
AT Auto Transaction 自动记录 undo log 无侵入，性能好（推荐） 有短暂不一致
TCC Try-Confirm-Cancel 手动实现三阶段 高性能，高定制 实现复杂，代码量大
Saga - 长事务补偿 适合长流程 有补偿逻辑

💡 生产推荐：AT 模式，无侵入，性能最好，满足大多数场景。

四、AT 模式详解（重点）⭐⭐⭐

4.1 原理

AT 模式在每次 DML 操作时，自动记录 undo log（回滚日志）。

text
第一阶段（执行）：
  1. 执行业务 SQL（扣库存）
  2. 记录 undo log（原始数据快照）
  3. 向 TC 报告：执行成功

第二阶段（提交/回滚）：
  - 全部成功：TC 通知 RM 删除 undo log，提交事务
  - 任意失败：TC 通知 RM 根据 undo log 回滚

好处：

  • 业务代码无需修改（无侵入）
  • 自动管理事务

坏处：

  • 存在"脏写"风险（全局锁解决）
  • 多读一次数据库（记录 undo log）

4.2 undo_log 表

每个参与 AT 模式的数据库需要建 undo_log 表：

sql
CREATE TABLE `undo_log` (
  `branch_id`     BIGINT       NOT NULL COMMENT 'branch transaction id',
  `xid`           VARCHAR(128) NOT NULL COMMENT 'global transaction id',
  `context`       VARCHAR(128) NOT NULL COMMENT 'undo_log context',
  `rollback_info` LONGBLOB     NOT NULL COMMENT 'rollback info',
  `log_status`    INT(11)      NOT NULL COMMENT '0:normal status,1:defense status',
  `log_created`   DATETIME(6)  NOT NULL COMMENT 'create datetime',
  `log_modified`  DATETIME(6)  NOT NULL COMMENT 'modify datetime',
  UNIQUE KEY `ux_undo_log` (`xid`, `branch_id`)
) ENGINE = InnoDB COMMENT = 'AT transaction mode undo table';

五、快速入门 ⭐⭐

5.1 部署 Seata Server

bash
# Docker 部署
docker run -d \
  --name seata \
  -p 8099:8099 \
  -p 7099:7099 \
  seataio/seata-server:1.5.2

或者使用 Nacos 作为注册中心，让各微服务发现 Seata Server。

5.2 引入依赖

xml
<!-- 每个参与分布式事务的服务都要引入 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-seata</artifactId>
</dependency>

5.3 配置

yaml
seata:
  registry:
    type: nacos
    nacos:
      server-addr: 127.0.0.1:8848
      namespace: ""
      group: DEFAULT_GROUP
      application: seata    # Seata Server 在 Nacos 的服务名
  tx-service-group: hmall   # 事务组名称，要与 Server 配置一致
  service:
    vgroup-mapping:
      hmall: "default"       # 映射到 Seata Server 的集群
  data-source-proxy-mode: AT  # 数据源代理模式

5.4 使用（极简！）

java
// 在事务发起方（TM）的方法上加 @GlobalTransactional
@GlobalTransactional  // 开启全局事务（就这一个注解！）
public void placeOrder(OrderFormDTO orderFormDTO) {
    // 1. 创建订单（本地事务）
    Order order = createOrder(orderFormDTO);

    // 2. 扣减库存（Feign 调用库存服务）
    itemClient.deductStock(orderFormDTO.getItemId(), orderFormDTO.getNum());

    // 3. 扣减余额（Feign 调用账户服务）
    accountClient.deductBalance(orderFormDTO.getUserId(), order.getPayAmount());
}

💡 参与方（RM）不需要任何改动，Seata 自动代理数据源，拦截 SQL，记录 undo log。

六、TCC 模式（进阶了解）

TCC 需要手动实现三个方法：

java
@LocalTCC
public interface AccountTCCService {

    // Try：预留资源（冻结金额）
    @TwoPhaseBusinessAction(
        name = "deductAccount",
        commitMethod = "confirm",
        rollbackMethod = "cancel"
    )
    void tryDeductBalance(BusinessActionContext ctx,
                          @BusinessActionContextParameter("userId") Long userId,
                          @BusinessActionContextParameter("amount") Integer amount);

    // Confirm：确认提交（真正扣除冻结金额）
    boolean confirm(BusinessActionContext ctx);

    // Cancel：回滚（解冻金额）
    boolean cancel(BusinessActionContext ctx);
}

三个阶段：

  1. Try：预留资源（不真正执行）
  2. Confirm：确认执行（全部 Try 成功后调用）
  3. Cancel：回滚（任意 Try 失败后调用）

七、常见报错

报错 1：could not find service provider for seata

text
原因：Seata Server 没有注册到 Nacos，或服务名配置不一致
解决：检查 seata.registry 配置，确认 application 名称正确

报错 2：Failed to commit global transaction

text
原因：undo_log 表不存在
解决：在每个参与 AT 模式的数据库中创建 undo_log 表

报错 3：GlobalTransactional 不生效

text
原因：方法不是 public，或在同一个类中调用（Spring 代理失效）
解决：确保方法是 public，跨类调用（注入后调用）

八、面试常问 ⭐⭐

💡 什么是分布式事务？ 跨多个服务/数据库的事务，要保证所有操作要么都成功，要么都回滚。

💡 Seata 的 AT 模式原理？ 第一阶段：执行业务 SQL，记录 undo log（before image + after image）。 第二阶段：全部成功删 undo log；任意失败根据 undo log 反向补偿回滚。

💡 AT 模式 vs TCC 模式的区别？ | | AT | TCC | |-|-----|-----| | 侵入性 | 无侵入 | 有侵入（写三个方法）| | 性能 | 中等 | 高 | | 适用 | 通用场景 | 高性能要求 |

💡 AT 模式的"脏写"问题？ 全局事务 A 修改数据，未提交；本地事务 B 也修改了同一数据，A 回滚时会覆盖 B 的修改。 Seata 通过全局锁（GlobalLock）解决：RM 在 Try 阶段获取全局锁，其他事务必须等全局锁释放才能操作同一行。
