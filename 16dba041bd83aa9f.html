第一章 File 类

1.1 什么是 File 类

java
// 概述：java.io.File 代表文件或文件夹（目录）的抽象路径名对象

生活类比： File 对象就像一张地图上标注的地点，你可以在地图上标注一个地方，但这个地方不一定真的建好了。

1.2 计算机常识

text
1. 以 .jpg 结尾的文件一定是图片吗？
   答：不一定，扩展名可以骗人，有可能是文件夹命名成了 xxx.jpg

2. 什么是文本文档？
   答：用记事本打开后人能看懂的文件，比如 .txt .html .css 等

3. 路径分隔符：
   - 路径名称分隔符（文件夹层级之间的分隔）：
     Windows: \
     Linux/Mac: /
   - 路径分隔符（多个路径之间分隔）：;（分号）

1.3 File 的静态成员

java
// File 有两个静态常量，用来获取当前操作系统的分隔符

public class Demo01File {
    public static void main(String[] args) {

        // static String pathSeparator：路径和路径之间的分隔符（多路径场景，如 classpath）
        // Windows 下是 ;（分号）
        String pathSeparator = File.pathSeparator;
        System.out.println("pathSeparator = " + pathSeparator); // 输出: ;

        // static String separator：路径名称分隔符（文件夹层级之间的分隔符）
        // Windows 下是 \（反斜杠）
        String separator = File.separator;
        System.out.println("separator = " + separator); // 输出: \

        // =========================================
        // 实际开发建议：路径使用 File.separator 拼接，保证跨平台
        // 下面两种写法效果相同，但第二种能跨 Windows/Linux 运行
        String path1 = "E:\\Idea\\io";                              // 只在 Windows 有效
        String path2 = "E:" + File.separator + "Idea" + File.separator + "io"; // 跨平台写法
        System.out.println(path1);
        System.out.println(path2);
    }
}

1.4 File 的三种构造方法

java
// 三种创建 File 对象的方式，路径可以不存在（只是描述）

public class Demo02File {
    public static void main(String[] args) {

        // 方式1：File(String parent, String child) - 父路径+子路径分开传
        // parent：父路径（文件夹部分）
        // child：子路径（文件名部分）
        File file1 = new File("E:\\Idea\\io", "1.jpg");
        System.out.println("file1 = " + file1); // 输出: E:\Idea\io\1.jpg

        // 方式2：File(File parent, String child) - 父路径是 File 对象
        // 好处：可以对父路径做判断、操作，更灵活
        File parent = new File("E:\\Idea\\io");     // 父路径先封装成 File 对象
        File file2 = new File(parent, "1.jpg");     // 再和子路径合并
        System.out.println("file2 = " + file2);    // 输出: E:\Idea\io\1.jpg

        // 方式3：File(String pathname) - 直接写完整路径
        File file3 = new File("E:\\Idea\\io\\1.jpg");
        System.out.println("file3 = " + file3);    // 输出: E:\Idea\io\1.jpg
    }
}

细节： 创建 File 对象时，传入不存在的路径也不会报错！但调用创建、读写等操作时才会出问题。

1.6 File 的获取方法

java
// File 的 4 个获取方法

private static void file01() {
    // getAbsolutePath()：获取绝对路径（带盘符的完整路径）
    File file1 = new File("1.txt");                   // 相对路径创建
    System.out.println(file1.getAbsolutePath());      // 输出: 当前项目根目录\1.txt

    File file2 = new File("io\\1.txt");
    System.out.println(file2.getPath());              // 输出: io\1.txt（原样返回）

    File file3 = new File("E:\\Idea\\io\\1.jpg");
    System.out.println(file3.getName());              // 输出: 1.jpg

    // length()：获取文件长度（字节数）
    // 注意：如果 File 对象代表文件夹，length() 返回 0
    File file4 = new File("E:\\Idea\\io\\1.txt");
    System.out.println(file4.length());               // 输出: 文件的字节数
}

1.7 File 的创建方法

java
// 两个创建方法

private static void file02() throws IOException {
    // createNewFile()：创建文件（不是文件夹）
    // 文件已存在 → 创建失败，返回 false
    // 文件不存在 → 创建成功，返回 true
    // 注意：如果父文件夹不存在，会抛出 IOException（找不到路径）
    File file1 = new File("E:\\Idea\\io\\1.txt");
    System.out.println(file1.createNewFile()); // true（第一次运行）/ false（已存在）

    // mkdirs()：创建文件夹（目录）
    // 可以一次创建多级文件夹（推荐使用 mkdirs 而不是 mkdir）
    // 文件夹已存在 → 创建失败，返回 false
    // 文件夹不存在 → 创建成功，返回 true
    File file2 = new File("E:\\Idea\\io\\haha\\heihei\\hehe"); // 一次创建3层文件夹
    System.out.println(file2.mkdirs()); // true（成功创建多级文件夹）
}

常见报错： java.io.IOException: 系统找不到指定的路径 → 通常是父文件夹不存在，先用 mkdirs() 创建父文件夹再调用 createNewFile()。

1.8 File 的删除方法

java
// delete()：删除文件或文件夹

1.10 File 的遍历方法

java
// 两个遍历方法

private static void file05() {
    File file = new File("E:\\Idea\\io\\aa"); // 要遍历的文件夹

    // list()：遍历文件夹，返回 String[] 数组（只有名字，没有路径信息）
    String[] list = file.list();
    for (String s : list) {
        System.out.println(s); // 只打印文件名，如：1.jpg、2.txt
    }

    System.out.println("==============");

    // listFiles()：遍历文件夹，返回 File[] 数组（推荐用这个！）
    // 底层：先调用 list() 得到名字数组，再把每个名字封装成 File 对象返回
    // 优势：每个 File 对象包含完整路径，可以继续调用各种方法
    File[] files = file.listFiles();
    for (File file1 : files) {
        System.out.println(file1); // 打印完整路径，如：E:\Idea\io\aa\1.jpg
    }
}

listFiles() 的底层原理：

  1. 先调用 list() 获取文件名 String 数组
  2. 遍历数组，把每个名字和父路径拼接，封装成 File 对象
  3. 返回 File 数组

综合练习：递归遍历所有 .jpg 文件

java
// 需求：遍历指定文件夹下（含子文件夹）所有的 .jpg 文件

public class Demo04File {
    public static void main(String[] args) {
        // 第1步：创建 File 对象，指定要遍历的顶层文件夹
        File file = new File("E:\\Idea\\io\\aa");
        method(file); // 调用递归方法
    }

    private static void method(File file) {
        // 第2步：调用 listFiles() 获取当前层所有文件/文件夹
        File[] files = file.listFiles();

        // 第3步：遍历数组，逐个判断
        for (File file1 : files) {
            if (file1.isFile()) {
                // 是文件：判断文件名是否以 .jpg 结尾
                String name = file1.getName();
                if (name.endsWith(".jpg")) {
                    System.out.println(name); // 找到了！打印出来
                }
            } else {
                // 是文件夹：递归调用自己，继续向下遍历
                method(file1); // 递归
            }
        }
    }
}
// 递归原理：方法自己调用自己，每次深入一层文件夹，直到没有子文件夹为止

第二章 字节流

2.1 IO流是什么，为什么要学

text
1. IO流 = Input/Output，数据在设备（硬盘/内存/网络）之间传输的技术

2. 为什么需要 IO 流？
   - 数组、集合只能临时保存数据（程序结束，数据消失）
   - IO 流可以把数据写到硬盘，实现"永久保存"
   - 网络传输数据也需要 IO 流

3. 流向理解：
   - 输入流（Input）：硬盘 → 内存（读文件）
   - 输出流（Output）：内存 → 硬盘（写文件）

生活类比：

  • 输出流 = 你把东西从家（内存）打包寄出去（写到硬盘）
  • 输入流 = 快递来了，从快递站（硬盘）取回家（读到内存）

2.2 IO流的四大基类

text
字节流（万能流，可操作任意文件）：
  - 字节输出流：OutputStream（抽象类）→ 子类 FileOutputStream
  - 字节输入流：InputStream（抽象类） → 子类 FileInputStream

字符流（专门处理文本文档）：
  - 字符输出流：Writer（抽象类）→ 子类 FileWriter
  - 字符输入流：Reader（抽象类）→ 子类 FileReader

2.3 FileOutputStream 字节输出流

java
// 作用：把数据（字节）从内存写出到硬盘文件

// ===== 构造方法 =====
// FileOutputStream(File file)   —— 传 File 对象
// FileOutputStream(String name) —— 传文件路径字符串
// FileOutputStream(String name, boolean append) —— append=true 时追加写，不覆盖原文件

// ===== 特点 =====
// 1. 指定的文件如果不存在，输出流会自动创建该文件
// 2. 默认情况（append=false）：每次运行都会重新创建文件，覆盖旧内容

// ===== 写一个字节 =====
private static void method01() throws IOException {
    FileOutputStream fos = new FileOutputStream("module21\\1.txt");
    fos.write(97); // 写入字节 97，对应 ASCII 字符 'a'，文件里会看到 a
    fos.close();   // 关流（必须关！否则资源泄漏）
}

// ===== 写一个字节数组 =====
private static void method02() throws IOException {
    FileOutputStream fos = new FileOutputStream("module21\\1.txt");
    byte[] bytes = {97, 98, 99, 100, 101, 102, 103}; // 对应 a b c d e f g
    fos.write(bytes);  // 一次写入整个数组
    fos.close();
}

// ===== 写字节数组的一部分 =====
private static void method03() throws IOException {
    FileOutputStream fos = new FileOutputStream("module21\\1.txt");
    byte[] bytes = {97, 98, 99, 100, 101, 102, 103}; // a b c d e f g
    fos.write(bytes, 0, 2); // 从索引 0 开始，写 2 个字节 → 文件里只有 ab
    fos.close();
}

// ===== 写字符串（先转字节数组）=====
private static void method04() throws IOException {
    FileOutputStream fos = new FileOutputStream("module21\\1.txt");
    fos.write("abcde".getBytes()); // String.getBytes() 把字符串转为字节数组
    fos.close();
}

// ===== 追加写 + 换行 =====
private static void method05() throws IOException {
    // append=true：追加续写，不覆盖原有内容
    FileOutputStream fos = new FileOutputStream("module21\\1.txt", true);
    fos.write("床前明月光\r\n".getBytes()); // \r\n 是 Windows 换行符（占2字节）
    fos.write("疑是地上霜\n".getBytes());   // \n 是 Linux/通用换行符
    fos.write("举头望明月\n".getBytes());
    fos.write("低头思故乡\n".getBytes());
    fos.close();
}

换行符说明：

系统 换行符 占用字节
Windows \r\n 2字节
Linux \n 1字节
Mac OS \r 1字节

2.4 FileInputStream 字节输入流

java
// 作用：把文件数据从硬盘读取到内存

// 构造方法：
// FileInputStream(File file)
// FileInputStream(String path)

// 方法：
// int read()                   —— 一次读一个字节，返回读到的字节值；到文件末尾返回 -1
// int read(byte[] b)           —— 一次读一个字节数组，返回实际读到的字节个数；到末尾返回 -1
// int read(byte[] b,int off,int len) —— 一次读数组的一部分
// void close()                 —— 关流

// ===== 一次读一个字节 =====
private static void method01() throws Exception {
    FileInputStream fis = new FileInputStream("module21\\1.txt");

    // 定义变量 len 接收每次读到的字节值
    int len;
    while ((len = fis.read()) != -1) {  // 读到 -1 表示文件末尾，循环结束
        System.out.println((char) len);  // 把字节转成字符打印
    }

    fis.close(); // 关流
}

// ===== 一次读一个字节数组（高效） =====
private static void method02() throws Exception {
    FileInputStream fis = new FileInputStream("module21\\1.txt");

    // 创建缓冲数组，每次最多读 2 个字节（实际开发用 1024 或 1024 的倍数）
    byte[] bytes = new byte[2];
    int len; // 接收本次实际读到的字节个数

    while ((len = fis.read(bytes)) != -1) {
        // new String(bytes, 0, len)：只转换实际读到的字节，避免最后一次读不满时出现残留
        System.out.println(new String(bytes, 0, len));
    }
    fis.close();
}

关于 -1 的解释： 每个文件末尾都有一个看不见的"结束标记"，当 read() 读到这个标记时，就返回 -1 告诉你"文件读完了"。

常见报错：

text
java.io.IOException: Stream Closed

原因：流关闭后（调用了 close()）还继续调用 read() 就会报此错误。记住：关流之后不能再使用该流对象。

2.5 字节流实现文件复制

java
// 需求：把 E:\Idea\io\24.jpg 复制一份到 E:\Idea\io\大姐.jpg

public class Demo01CopyFile {
    public static void main(String[] args) throws Exception {
        // 第1步：创建输入流，指向源文件（要复制谁）
        FileInputStream fis = new FileInputStream("E:\\Idea\\io\\24.jpg");

        // 第2步：创建输出流，指向目标位置（要复制到哪里）
        FileOutputStream fos = new FileOutputStream("E:\\Idea\\io\\大姐.jpg");

        // 第3步：定义缓冲数组（1024 字节 = 1KB，每次读写 1KB）
        byte[] bytes = new byte[1024];

        // 第4步：边读边写（循环，直到读完）
        int len;
        while ((len = fis.read(bytes)) != -1) {
            fos.write(bytes, 0, len); // 读了多少就写多少，避免末尾多余数据
        }

        // 第5步：关流（先开的后关，后开的先关）
        fos.close();
        fis.close();
    }
}

第三章 字符流

3.1 为什么要有字符流

text
字节流读中文的问题：
  - UTF-8：一个汉字占 3 个字节
  - GBK：  一个汉字占 2 个字节
  - 如果用字节流一个字节一个字节地读，读到汉字时会读"半个汉字"，直接输出就是乱码

解决方案：使用字符流（以字符为单位读写，不会把汉字拆开）
注意：字符流只适合操作文本文档，复制图片/视频必须用字节流

3.2 FileReader 字符输入流

java

flush() 和 close() 的区别：

方法 操作 后续能否使用流
flush() 把缓冲区数据写入文件 可以继续使用
close() 先 flush，再关闭流 不能再使用

        FileWriter fw = null; // 在 try 外声明，以便 finally 中访问
        try {
            fw = new FileWriter("module21\\3.txt"); // 可能抛出 IOException
            fw.write("你好");

            e.printStackTrace(); // 打印异常堆栈信息
        } finally {
            // finally 块无论如何都会执行（即使 try 里抛异常也执行）
            if (fw != null) { // 先判断不为 null，再关闭（防止 new 失败后 close 空指针）

                    fw.close(); // close() 本身也可能抛异常，需要再套一层 try-catch
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}

第四章 缓冲流（提升性能的关键）

4.1 为什么需要缓冲流？（原理非常重要！）

text
基本流（FileInputStream / FileOutputStream）的问题：
  - read() / write() 是 native 方法（底层直接和操作系统/硬盘打交道）
  - 每次调用都是一次磁盘 I/O 操作
  - 磁盘速度 << 内存速度，大量磁盘操作 = 效率极低

缓冲流的解决方案：
  - 缓冲流底层自带一个长度为 8192 字节（8KB）的数组（缓冲区）
  - 读写操作在内存的缓冲区之间完成，大幅减少磁盘操作次数
  - 读：一次性从磁盘读 8192 字节到输入缓冲区，程序再从缓冲区取数据
  - 写：程序先把数据写入输出缓冲区，缓冲区满了再一次性写到磁盘

生活类比：

不用缓冲流 = 每写一个字就跑一趟快递站寄出去。 用缓冲流 = 先把东西攒起来，攒满一箱再统一去一趟快递站，效率高 N 倍。

缓冲流读写过程详解：

text
读过程：
1. 调用 bis.read() —— 程序向缓冲输入流要数据
2. 缓冲输入流底层调用基本流 fis.read()，一次性从硬盘读 8192 字节到 【输入缓冲区】
3. 程序从【输入缓冲区】取数据（内存操作，极快）
4. 【输入缓冲区】空了，再次触发第2步从磁盘读

写过程：
1. 调用 bos.write() —— 程序向缓冲输出流写数据
2. 数据进入【输出缓冲区】（内存操作，极快）
3. 【输出缓冲区】满了（8192字节），底层调用基本流 fos.write()，一次性写到磁盘
4. 关流时会强制把剩余缓冲区数据 flush 到磁盘

4.2 字节缓冲流

java
// 字节缓冲输出流：BufferedOutputStream
// 构造：BufferedOutputStream(OutputStream out) —— 传入基本字节输出流
// 用法：和 FileOutputStream 完全一样，只是效率更高

// 字节缓冲输入流：BufferedInputStream
// 构造：BufferedInputStream(InputStream in) —— 传入基本字节输入流
// 用法：和 FileInputStream 完全一样，只是效率更高

public class Demo01BufferedInputStream_OutputStream {
    public static void main(String[] args) throws Exception {
        method02(); // 测试缓冲流复制文件的速度
    }

    // ===== 用基本流复制文件（慢） =====
    private static void method01() throws Exception {
        long start = System.currentTimeMillis(); // 记录开始时间

        FileInputStream fis = new FileInputStream("E:\\Idea\\io\\1.avi");   // 基本输入流
        FileOutputStream fos = new FileOutputStream("E:\\Idea\\io\\2.avi"); // 基本输出流

        int len;
        while ((len = fis.read()) != -1) { // 每次从磁盘读 1 字节（！极慢）
            fos.write(len);                 // 每次向磁盘写 1 字节（！极慢）
        }

        long end = System.currentTimeMillis();
        System.out.println("基本流耗时: " + (end - start) + "ms"); // 可能几十秒

        fos.close();
        fis.close();
    }

    // ===== 用缓冲流复制文件（快）=====
    private static void method02() throws Exception {
        long start = System.currentTimeMillis(); // 记录开始时间

        FileInputStream fis = new FileInputStream("E:\\Idea\\io\\1.avi");
        FileOutputStream fos = new FileOutputStream("E:\\Idea\\io\\2.avi");

        // 把基本流"包装"成缓冲流（装饰器模式）
        BufferedInputStream bis = new BufferedInputStream(fis);
        BufferedOutputStream bos = new BufferedOutputStream(fos);

        int len;
        while ((len = bis.read()) != -1) { // 表面是读1字节，底层其实是从8KB缓冲区取数据
            bos.write(len);                 // 写到输出缓冲区，缓冲区满了才写磁盘
        }

        long end = System.currentTimeMillis();
        System.out.println("缓冲流耗时: " + (end - start) + "ms"); // 快很多！

        bos.close(); // 关缓冲流，底层会自动关基本流（不需要单独关 fos/fis）
        bis.close();
    }
}

两个细节问题：

Q1：为什么只关缓冲流，不用单独关基本流？

缓冲流的 close() 底层会自动调用包装的基本流的 close()，所以不需要手动关基本流。

Q2：缓冲流 len 变量的作用是什么？

len 是在两个缓冲区之间来回"倒腾"数据的桥梁：

  • 把输入缓冲区的数据一个一个取出来（赋值给 len）
  • 再把 len 写入输出缓冲区
  • 当输入缓冲区空了，底层再从磁盘读 8192 字节填充
  • 当输出缓冲区满了，底层再一次性写到磁盘

第五章 转换流

5.1 字符编码和字符集基础

text
编码：按照某种规则，把字符存储为计算机能识别的二进制数
解码：把计算机中的二进制数，按照某种规则解析回字符
乱码原因：编码和解码用的规则不一样！

常见字符集对比：

字符集 说明 中文占用字节
ASCII 只有英文+数字+符号，128个字符 不支持中文
ISO-8859-1 西欧字符，单字节编码 不支持中文
GB2312 简体中文，7000+汉字 2字节
GBK 最常用中文编码，21003个汉字，兼容 GB2312 2字节
GB18030 最新中文编码，70244个汉字 1/2/4字节
UTF-8 万国码，支持所有语言，互联网首选 中文3字节
UTF-16 大多数字符2字节 2字节
text
核心结论：
1. 想要不乱码，编码和解码遵循的规则必须一致
   → 文件用 GBK 存的，读取时也要用 GBK；用 UTF-8 存的，读取也用 UTF-8
2. UTF-8 中一个汉字占 3 个字节
3. GBK 中一个汉字占 2 个字节

5.2 什么时候会乱码？

text
情况1：用字节流读中文
  → 一次读1字节，把汉字拆成多个字节分开输出，肯定乱码
  → 解决：用字符流读

情况2：用字符流，但编码不匹配
  → 比如文件是 GBK 编码存的，但用默认 UTF-8 的 FileReader 读
  → 解决：用转换流，手动指定编码

转换流就是为了解决"编码不一致"的乱码问题！

5.3 InputStreamReader（读时指定编码）

java
// 概述：字节流 → 字符流的桥梁（读数据时使用）
// 构造：InputStreamReader(InputStream in, String charsetName)
//        charsetName：指定编码，不区分大小写，如 "gbk" "GBK" "UTF-8" 都可以
// 作用：按照指定编码去读取文件内容，解决乱码问题
// 用法：和 FileReader 完全一样（其实 FileReader 就是 InputStreamReader 的子类）

public class Demo01InputStreamReader {
    public static void main(String[] args) throws Exception {
        // 读取一个用 GBK 编码保存的文件
        // 用 FileReader 默认 UTF-8 读 GBK 文件 → 乱码
        // 用 InputStreamReader 指定 GBK → 正常
        InputStreamReader isr =
                new InputStreamReader(new FileInputStream("E:\\Idea\\io\\1.txt"), "gbk");
        // 底层：FileInputStream 负责读字节，InputStreamReader 负责按 GBK 把字节转字符

        int data = isr.read(); // 读一个字符（返回字符对应的 int 值）
        System.out.println((char) data); // 转成字符打印
        isr.close();
    }
}

5.4 OutputStreamWriter（写时指定编码）

java
// 概述：字符流 → 字节流的桥梁（写数据时使用）
// 构造：OutputStreamWriter(OutputStream out, String charsetName)
// 作用：按照指定编码把字符写入文件

流 方向 解决的问题
InputStreamReader 字节流→字符流（读） 读取特定编码的文件不乱码
OutputStreamWriter 字符流→字节流（写） 按特定编码写出文件

第六章 序列化流

6.1 什么是序列化？

text
序列化：把 Java 对象转换成字节序列，写到文件/网络（持久化）
反序列化：从文件/网络读取字节序列，重新还原成 Java 对象

应用场景：
  - 游戏存档：人物对象（角色属性、等级、血量）→ 写入文件 → 下次启动读回来
  - 网络传输：对象 → 字节 → 通过网络发送 → 对方接收字节 → 还原对象
  - Session 持久化：Web 中用户会话对象存到磁盘

生活类比： 序列化就像把家具拆散（对象→字节），装箱运输（写入文件/网络），到达目的地再重新组装（字节→对象）。

text
注意：序列化后的文件是二进制，直接打开看不懂，这是正常的！
      这正是我们想要的效果——保护数据不被随意篡改

6.2 ObjectOutputStream 序列化流（写对象）

java
// 作用：把 Java 对象写入文件（序列化）
// 构造：ObjectOutputStream(OutputStream out)
// 方法：writeObject(Object obj) —— 写对象

// 前置条件：被序列化的类必须实现 Serializable 接口！
// Serializable 是标记接口（没有任何方法），只是作为"允许被序列化"的标志

public class Person implements Serializable {

    // 作用：标识这个类的版本，序列化和反序列化时用来校验类是否一致
    public static final long serialVersionUID = 42L; // 值可以随意定，保持唯一即可

    private String name;
    public Integer age;

    public Person() {}

    public Person(String name, Integer age) {
        this.name = name;
        this.age = age;
    }

    // getter/setter 省略...

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + '}';
    }
}

// ===== 第2步：序列化对象到文件 =====
private static void write() throws Exception {
    // 创建序列化流（包装一个 FileOutputStream）
    ObjectOutputStream oos =
            new ObjectOutputStream(new FileOutputStream("module22\\person.txt"));

    Person p1 = new Person("涛哥", 12); // 创建要存储的对象
    oos.writeObject(p1); // 把对象序列化写入文件（文件内容是二进制，看不懂是正常的）
    oos.close(); // 关流

6.5 InvalidClassException 序列化版本冲突问题

text
问题描述：
  1. 对 Person 对象进行了序列化，存到文件中
  2. 修改了 Person.java（比如加了个字段）
  3. 没有重新序列化，直接反序列化读取
  → 报错：InvalidClassException: local class incompatible: stream classdesc serialVersionUID = X, local class serialVersionUID = Y

原因分析：
  Java 序列化机制会根据类的结构自动生成一个 serialVersionUID（版本号）
  类结构改变后，自动生成的 serialVersionUID 也会改变
  文件里存的是旧版本号，当前类是新版本号，两者不匹配 → 报错

解决方案：
  手动固定 serialVersionUID，不让它自动变化
  → 在类中声明：public static final long serialVersionUID = 42L;
  → 这样不管类怎么改，版本号都是 42L，不会再出现版本冲突
java
public class Person implements Serializable {
    // 手动固定版本号，以后无论怎么修改类，这个号不变，就不会再有版本冲突
    public static final long serialVersionUID = 42L;

    private String name;
    public Integer age;
    // 以后加字段也没问题了
}

6.6 EOFException：循环读取对象

text
问题描述：
  文件里存了多个对象，循环反序列化时次数和对象个数不对，就会报：
  EOFException: Unexpected end of ZLIB input stream（文件意外到达结尾）

原因：
  比如文件里只有 3 个对象，但循环写了 for(int i=0; i<4; i++)，第4次读无数据

解决方案：
  将多个对象先放到集合（如 ArrayList）中，再序列化整个集合
  反序列化时读出来就是一个集合，直接遍历集合即可，不需要多次 readObject
java
public class Demo02Serializable {
    public static void main(String[] args) throws Exception {
        // write(); // 先序列化
        read();     // 再反序列化
    }

    // 序列化：将多个对象放入集合，整体序列化
    private static void write() throws Exception {
        ObjectOutputStream oos =
                new ObjectOutputStream(new FileOutputStream("module22\\person.txt"));

        // 创建集合，存多个 Person 对象
        ArrayList<Person> list = new ArrayList<>();
        list.add(new Person("涛哥", 12));
        list.add(new Person("三上", 30));
        list.add(new Person("金莲", 24));

        oos.writeObject(list); // 序列化整个集合（一次 writeObject）
        oos.close();
    }

    // 反序列化：读出集合，遍历集合
    private static void read() throws Exception {
        ObjectInputStream ois =
                new ObjectInputStream(new FileInputStream("module22\\person.txt"));

        // 读出来就是一个集合，强转
        ArrayList<Person> list = (ArrayList<Person>) ois.readObject();
        // 遍历集合即可，不需要多次 readObject，不会出现 EOFException
        for (Person person : list) {
            System.out.println(person);
        }
        ois.close();
    }
}

第八章 Properties 集合配合 IO 流

8.1 Properties 回顾

java
// Properties 是 Hashtable 的子类
// 特点：
//   - 无序，无索引
//   - key 唯一，value 可重复
//   - 线程安全
//   - key 和 value 默认都是 String 类型（！不需要泛型）

// 特有方法：
// setProperty(String key, String value)  —— 存键值对
// getProperty(String key)                —— 根据 key 获取 value
// stringPropertyNames()                  —— 获取所有 key，存入 Set 集合
// load(InputStream in)                   —— 从 IO 流中加载键值对到集合

public class Demo01Properties {
    public static void main(String[] args) {
        Properties properties = new Properties();
        properties.setProperty("username", "root"); // 存入键值对
        properties.setProperty("password", "1234");

        // 获取所有 key（放到 Set 中）
        Set<String> set = properties.stringPropertyNames();
        for (String key : set) {
            System.out.println(key + " = " + properties.getProperty(key)); // 根据 key 取 value
        }
    }
}

8.2 为什么要用 Properties 读配置文件？

text
实际开发中，数据库的用户名/密码等配置信息不能硬编码（写死）在源码里！
原因：
  - 一旦修改配置，就要改源码、重新编译、重新部署 —— 麻烦，而且危险
  - 源码可能被多人看到，密码暴露

正确做法：
  - 把配置数据写在 .properties 文件中
  - 程序启动时用 Properties + IO 流读取配置文件
  - 以后改配置只需修改 .properties 文件，源码不用动

8.3 .properties 配置文件规范

properties
# 这是注释（# 开头的行是注释，不会被读取）
# 配置文件格式规范：
# 1. 每行一个键值对，格式：key=value
# 2. key 和 value 都是字符串，不要加双引号
# 3. 每个键值对写完后换行
# 4. 键值对之间最好不要有空格（有也能用，但不建议）
# 5. 建议不要用中文（会乱码，需要用转换流处理）

jdbc.username=root
jdbc.password=1234

public class Demo02Properties {

        }
    }

            }

常见报错汇总与解决方法

报错 原因 解决方法
FileNotFoundException 路径写错，或者文件/父文件夹不存在（读取时） 检查路径是否正确；写操作自动创建文件，读操作需文件已存在
IOException: Stream Closed 流已关闭后还在使用 检查代码，确保关流前完成所有读写操作
InvalidClassException 序列化和反序列化的 serialVersionUID 不匹配 在类中手动声明 public static final long serialVersionUID = 42L;
EOFException 反序列化循环次数超过文件中对象个数 把多个对象放到集合再序列化，反序列化时读整个集合
NotSerializableException 被序列化的类没有实现 Serializable 接口 给类添加 implements Serializable
中文乱码 文件编码和读取编码不一致 用转换流 InputStreamReader/OutputStreamWriter 指定正确编码
NullPointerException listFiles() 返回 null（路径不存在或不是文件夹） 先判断 file.exists() && file.isDirectory()

面试常问

Q1：字节流和字符流的区别是什么？分别用于什么场景？

  • 字节流（InputStream/OutputStream）：以字节为单位，可操作任意文件（图片、视频、文档等），万能流。
  • 字符流（Reader/Writer）：以字符为单位，底层会自动处理字符编码，专门用于文本文档读写。
  • 场景：文件复制用字节流；读写文本内容用字符流（防止乱码）。

Q2：缓冲流为什么能提升性能？底层原理是什么？

缓冲流底层维护了一个 8192 字节（8KB）的数组缓冲区。读时，一次从磁盘读 8KB 存入缓冲区，程序再从缓冲区取，减少磁盘访问次数。写时，程序先写到缓冲区，缓冲区满了才一次性写到磁盘。内存操作比磁盘操作快几个数量级，所以效率大幅提升。

Q3：序列化时为什么要声明 serialVersionUID？

Java 序列化默认会根据类结构自动生成 serialVersionUID，类结构改变后 ID 会变，导致旧序列化文件无法反序列化（InvalidClassException）。手动声明一个固定值后，类怎么改 ID 都不变，保证兼容性。

Q4：Serializable 接口有什么方法？为什么没有方法也要实现它？

Serializable 是标记接口（marker interface），没有任何方法。实现它只是给 JVM 一个"标志"，告诉 JVM 这个类允许被序列化。JVM 在序列化时会检查该标志，没有实现则抛 NotSerializableException。

Q5：transient 关键字有什么作用？

transient 修饰的字段不参与序列化，反序列化后该字段为默认值（引用类型为 null，基本类型为 0/false）。常用于密码、敏感信息、可从其他字段计算出来的字段等。

Q6：flush() 和 close() 有什么区别？

  • flush()：把缓冲区数据强制写入目标（文件/网络），流对象之后还能继续使用。
  • close()：先执行 flush，再释放系统资源，流对象关闭后不能再使用。
  • 建议：用 try-with-resources 语法，自动调用 close()。

Q7：try-with-resources 语法是什么？有什么好处？

JDK 7 引入的语法糖：try(Resource r = new Resource()) { ... }，括号中声明的资源会在 try 块结束后自动调用 close()，即使发生异常也会关闭。好处：代码简洁，不会忘记关流，不用写 finally。

Q8：Properties 类的 load() 方法做了什么？

load(InputStream) 读取 .properties 文件（流中的文本数据），自动按 key=value 格式解析每一行，把键值对存入 Properties 集合。之后可以用 getProperty(key) 直接取值，无需手动解析。

Q9：InputStreamReader 和 FileReader 有什么关系？

FileReader 是 InputStreamReader 的子类。FileReader 使用的是系统默认编码（通常是 UTF-8），如果文件是 GBK 编码就会乱码。InputStreamReader 可以手动指定编码，更灵活。需要指定编码时用 InputStreamReader，系统默认编码时可以直接用 FileReader。

本章小结

text
IO流知识体系总结：

1. File 类 —— 操作文件/文件夹（增删改查），但不负责文件内容的读写

2. 字节流 —— 万能，适合复制任何文件
   FileOutputStream（写）/ FileInputStream（读）

3. 字符流 —— 专门处理文本，防止中文乱码
   FileWriter（写）/ FileReader（读）
   
4. 缓冲流 —— 在基本流外面包一层，提升效率（内存缓冲区 8192 字节）
   字节缓冲：BufferedOutputStream / BufferedInputStream
   字符缓冲：BufferedWriter（特有 newLine()）/ BufferedReader（特有 readLine()）

5. 转换流 —— 解决编码不一致导致的乱码，可以手动指定编码
   InputStreamReader / OutputStreamWriter

6. 序列化流 —— 把对象持久化到文件/网络传输
   ObjectOutputStream（序列化，写对象）/ ObjectInputStream（反序列化，读对象）
   注意：类必须 implements Serializable，建议声明 serialVersionUID

7. 打印流 PrintStream —— 原样输出，可改变输出流向（System.setOut）

8. Properties —— 专门读取 .properties 配置文件，解耦配置和代码

9. try-with-resources —— JDK7+ 的 IO 异常处理推荐写法，自动关流

选流原则：
  - 操作文本文件（边读边看内容）→ 字符流
  - 复制文件（任意类型）→ 字节流 + 缓冲流
  - 文件编码不一致 → 转换流
  - 读写 Java 对象 → 序列化流
  - 读配置文件 → Properties.load()
