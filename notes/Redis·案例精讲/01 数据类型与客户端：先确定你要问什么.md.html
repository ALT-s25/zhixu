01 数据类型与客户端：先确定你要问什么

约 3 分钟阅读你的知识，慢慢成林

先用一个类比理解

Redis像前台的快速取物柜，key是柜号，value是柜内物品；不同柜型适合不同操作。类比的边界：它不是永不丢失的保险箱，也不能因为读取快就替代关系数据库的约束和事务。

课程入门篇先讲String、Hash、List、Set、SortedSet，再用Jedis和SpringDataRedis操作。学习时不要先背所有命令，先把业务问题翻译成数据操作。

你要回答的问题 类型 关键操作 不适合直接承担什么
验证码是什么、还剩多久 String+TTL SET、GET、TTL 永久用户档案
用户的昵称和头像是什么 Hash HSET、HGETALL 跨表关联查询
谁排在前面 SortedSet ZADD、ZRANGE 自动解决并列排名规则
两人共同关注了谁 Set SADD、SINTER 关注时间排序
按顺序取待办项 List LPUSH、RPOP 完整可靠消息投递

一次可以看懂的练习

在独立Redis练习实例的redis-cli中逐行执行，前缀统一使用learn:，不要粘贴到正式数据实例。

redis
SET learn:code:demo 827361 EX 120
GET learn:code:demo
TTL learn:code:demo
HSET learn:user:7 nickname 小芽 level 1
HGETALL learn:user:7
SADD learn:follow:7 10 20
SADD learn:follow:8 20 30
SINTER learn:follow:7 learn:follow:8
ZADD learn:score 80 alice 95 bob
ZREVRANGE learn:score 0 1 WITHSCORES

预期：验证码是字符串827361，TTL是不断减少的秒数；共同关注只有20；积分榜先bob后alice。Hash字段的输出顺序不应作为业务保证。

从命令连接到Java

课程StringRedisTemplate让key/value都按字符串理解；保存对象时可先转JSON，读取后还原。RedisTemplate使用什么序列化器必须与读写端一致。遇到命令行看见“乱码key”，先查序列化，不要先怀疑数据库坏了。

java
// 片段：在已注入 StringRedisTemplate 的 Spring Bean 中使用
String key = "learn:shop:1";
template.opsForValue().set(key, "{\"id\":1,\"name\":\"小芽店\"}",
        java.time.Duration.ofMinutes(5));
String json = template.opsForValue().get(key); // 过期后可能为 null

Jedis实例不要随意跨线程共享，按课程通过池借还；客户端连接池、Redis服务本身、序列化是三件不同的事。

自测与答案

题目：积分排行榜为什么不用Set？

答案：Set只表达“在不在”，不保存用于排序的分数；SortedSet同时保存成员和score。若按多个指标排名，还要明确合成分数或同分处理规则。

完成标准：不看表也能为验证码、共同关注、排行榜各选一种类型，并解释原因。
