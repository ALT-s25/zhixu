02 Web开发：请求参数、响应、静态资源与异常

约 2 分钟阅读你的知识，慢慢成林

原文：第28—77页。优先级：必学。

把Controller看作接待窗口：读取请求、校验格式、交给业务层、返回明确结果。边界：接待窗口不应包办所有数据库操作，也不等于安全权限已经完成。

按这条路线读原文：静态资源与路径 → 参数与内容协商 → 模板引擎 → 拦截器与异常 → Web定制 → ProblemDetail与函数式路由。第一次以JSON接口为主，模板引擎是另一种页面渲染选择，函数式路由可稍后学习。

请求中的位置 常见接收方式 例子
路径中的标识 @PathVariable /students/1
URL查询参数 @RequestParam /students?page=1
JSON请求体 @RequestBody POST新增学生
java
// 补充教学片段：参数转换失败由框架先处理
@GetMapping("/students/{id}")
Map<String,Object> find(@PathVariable("id") long id) {
    return Map.of("id",id,"name","示例学生");
}

404先查路径与扫描，405查HTTP方法，400查参数类型和校验，415查Content-Type，500再查服务端异常。不要用“接口不通”概括所有问题。内容协商里的Accept说明想要的响应格式，Content-Type说明发来的内容格式，两者不是同一件事。

练习：同一路径分别用GET、POST、错误id访问，记录状态码。再增加统一异常响应，区分用户输入错误与服务异常；不能一律返回200加“失败”字符串。课程原文对旧表单过滤器的说明不要误读成所有PUT/DELETE请求体都不能接收。
