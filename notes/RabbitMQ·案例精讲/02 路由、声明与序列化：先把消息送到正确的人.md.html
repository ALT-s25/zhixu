把交换机当作分拣规则

Fanout像群发公告，忽略routing key；Direct按精确标签分拣；Topic按点分隔的主题词匹配。边界：规则匹配成功不保证消费者已完成工作，甚至不保证当前有消费者在线。

类型 绑定规则 测试routing key 结果
Direct order.paid order.paid 匹配
Direct order.paid order.closed 不匹配
Topic order.* order.paid 匹配
Topic order.* order.vip.paid 不匹配
Topic order.# order.vip.paid 匹配

*匹配一个词，#匹配零个或多个词；点分词规则不是任意字符正则表达式。

声明顺序与消息结构

先声明交换机、队列和绑定，再发送。课程既展示Bean声明也展示注解绑定；选一种一致组织方式，避免多个地方声明同名队列却使用不同参数。

java
// 片段：放在课程使用的@Configuration类中
@Bean
public DirectExchange learnExchange() {
    return new DirectExchange("learn.pay", true, false);
}
@Bean
public Queue learnQueue() {
    return new Queue("learn.order.paid", true);
}
@Bean
public Binding learnBinding() {
    return BindingBuilder.bind(learnQueue()).to(learnExchange()).with("order.paid");
}

代码中Queue指Spring AMQP的Queue，不是java.util.Queue。同名已存在但参数不同，Broker可能拒绝声明；不能靠不停重启解决。

JSON转换器解决什么

课程用JSON替代Java默认对象序列化，便于观察和跨服务协作。生产者与消费者要约定字段、类型、事件版本；不要直接把整个数据库实体发送过去。

json
{"eventId":"pay-1001-v1","orderId":1001,"type":"ORDER_PAID","version":1}

eventId识别同一个事件，orderId识别业务对象；重发同一个事件应保留可去重标识。消费者只需要订单ID时，不必附带密码、完整用户档案等无关字段。

自测与答案

题目：一个队列绑定两个能匹配同一消息的规则，就应靠收到两次来做两种业务吗？

答案：不应依赖这种设计。按业务划分队列，各自幂等处理；路由规则只是把事件送到目标队列。

完成标准：做出一条匹配和一条不匹配消息，能解释它们在管理界面中的去向。
