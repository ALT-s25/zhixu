第一章：Docker 解决了什么问题

1.1 "在我电脑上能跑"的问题

开发场景：

text
开发机：Windows + JDK 8 + MySQL 5.7 + Redis 3.0
测试服务器：CentOS + JDK 11 + MySQL 8.0 + Redis 6.0

代码在开发机能跑，放到服务器跑不了。每次部署都要花大量时间配环境。

Docker 的解决方案：

把应用和它所有的依赖（JDK版本、库文件、配置）打包成一个镜像，拿到哪里运行都是同样的环境。

类比：

  • 没有 Docker：搬家时家具要拆散，到了新家重新组装
  • 有 Docker：整个房间集装箱打包，到哪里直接搬进去住

1.2 Docker vs 虚拟机

虚拟机 Docker
技术原理 硬件虚拟化（完整 OS） 进程隔离（共享 OS 内核）
启动时间 分钟级 秒级
占用空间 GB 级 MB 级
性能损耗 大（模拟硬件） 小（接近原生）
隔离性 强 较强

💡 虚拟机就像在办公室里建了一栋独立房子；Docker 容器就像在办公室里用隔断分出的一个工位——共用电力和空调，但各自独立工作。

第二章：Docker 核心概念

2.1 三大概念

镜像（Image）：只读的模板文件，包含应用和所有依赖。

类比：饺子馅的配方（只是配方，不是饺子）。

容器（Container）：镜像运行起来的实例，可以启动、停止、删除。

类比：按照配方包出来的饺子（实际存在的饺子）。

仓库（Registry）：存储和分发镜像的地方，类似 GitHub，但存的是镜像。

类比：菜谱网站（大家把配方传上去，别人可以下载）。

2.2 Docker 架构

text
┌─────────────────────────────────────────────────────┐
│                   Docker Host（服务器）               │
│                                                      │
│  镜像仓库（本地）                                    │
│  mysql:5.7   nginx:latest   redis:6.0                │
│      ↓ run                                           │
│  容器                                               │
│  [mysql-c1]  [nginx-c1]  [redis-c1]                 │
│                                                      │
└──────────────────────────────────────────────────────┘
              ↑ 拉取 / 推送
      Docker Hub（远程仓库）

2.3 安装 Docker（CentOS 7）

步骤 1：卸载旧版本（如果有）

bash
yum remove docker docker-common docker-selinux docker-engine

步骤 2：安装依赖

bash
yum install -y yum-utils device-mapper-persistent-data lvm2

步骤 3：配置 Docker 仓库（用阿里云镜像，速度快）

bash
yum-config-manager --add-repo http://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

步骤 4：安装 Docker

bash
yum install -y docker-ce docker-ce-cli containerd.io

步骤 5：启动 Docker

bash
systemctl start docker    # 启动
systemctl enable docker   # 开机自启

步骤 6：验证

bash
docker --version
# Docker version 20.10.17, build 100c701
docker info

步骤 7：配置镜像加速（国内必配）

bash
# 创建配置文件
mkdir -p /etc/docker
tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://镜像加速地址.mirror.aliyuncs.com"
  ]
}
EOF

# 重启 Docker
systemctl daemon-reload
systemctl restart docker

💡 阿里云镜像加速地址：登录 aliyun.com → 容器镜像服务 → 镜像加速器，可以看到你自己的加速地址。

第三章：镜像操作

3.1 镜像命名规则

text
仓库地址/命名空间/镜像名:标签
mysql:5.7                    ← 官方镜像（省略了仓库地址和命名空间）
nginx:latest                 ← latest 是默认标签
192.168.150.101:8080/mysql:5.7  ← 私有仓库

3.2 常用命令

bash
# 拉取镜像（从 Docker Hub 下载）
docker pull nginx            # 拉取最新版
docker pull nginx:1.23       # 拉取指定版本
docker pull mysql:5.7        # 拉取 MySQL 5.7

# 查看本地所有镜像
docker images
# REPOSITORY   TAG       IMAGE ID       CREATED       SIZE
# nginx        latest    abc123...      2 weeks ago   142MB
# mysql        5.7       def456...      3 weeks ago   448MB

# 删除镜像
docker rmi nginx              # 删除 nginx:latest
docker rmi nginx:1.23         # 删除指定版本
docker rmi nginx mysql        # 删除多个

# 保存镜像到文件（离线传输用）
docker save -o nginx.tar nginx:latest
# -o：指定输出文件名

# 从文件加载镜像
docker load -i nginx.tar
# -i：指定输入文件

# 搜索镜像
docker search redis

第四章：容器操作

4.1 运行容器（最重要）

bash
docker run [选项] 镜像名 [命令]

常用选项：

选项 说明
-d 后台运行（不占终端）
--name 容器名 给容器起名字
-p 宿主端口:容器端口 端口映射
-e 变量=值 设置环境变量
-v 宿主路径:容器路径 挂载数据卷
--network 网络名 指定网络
--rm 容器停止后自动删除

示例：运行 nginx

bash
docker run -d \
  --name my-nginx \          # 容器名 my-nginx
  -p 80:80 \                 # 宿主机 80 映射到容器 80
  nginx                      # 镜像名

运行后，访问 http://服务器IP:80 就能看到 nginx 页面。

示例：运行 MySQL

bash
docker run -d \
  --name mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \    # 设置 root 密码（必须）
  -v /data/mysql:/var/lib/mysql \    # 数据持久化
  mysql:5.7

4.2 管理容器

bash
# 查看运行中的容器
docker ps
# CONTAINER ID  IMAGE   COMMAND  CREATED  STATUS  PORTS  NAMES
# abc123       nginx   ...       1 min    Up      80/tcp my-nginx

# 查看所有容器（包含停止的）
docker ps -a

# 停止容器
docker stop my-nginx

# 启动已停止的容器
docker start my-nginx

# 重启容器
docker restart my-nginx

# 删除容器（必须先停止）
docker rm my-nginx

# 强制删除（不需要先停止）
docker rm -f my-nginx

# 删除所有停止的容器
docker container prune

4.3 查看日志

bash
# 查看容器日志
docker logs my-nginx

# 持续输出日志（类似 tail -f）
docker logs -f my-nginx

# 看最新 100 行
docker logs --tail 100 my-nginx

4.4 进入容器

bash
# 进入容器（最常用）
docker exec -it my-nginx bash
# -i：交互模式
# -t：分配终端
# bash：进入后执行的命令（有些镜像要用 sh）

# 进去后，可以像在 Linux 里一样操作
ls
cat /etc/nginx/nginx.conf
# exit 退出（不会停止容器）

⚠ 注意：exit 只是退出交互，容器还在运行。要停止用 docker stop。

第五章：数据卷（持久化）⭐⭐

5.1 为什么需要数据卷

问题：

  • 容器删除 → 容器内数据也丢失
  • 在容器外部无法修改容器内的配置文件

解决：数据卷（Volume），把宿主机的目录/文件挂载到容器中。

5.2 两种挂载方式

方式一：具名数据卷（Docker 管理）

bash
# 创建数据卷
docker volume create html

# 查看数据卷
docker volume ls
docker volume inspect html   # 查看具体路径

# 使用数据卷（挂载到容器）
docker run -d \
  --name my-nginx \
  -p 80:80 \
  -v html:/usr/share/nginx/html \   # html 是 volume 名
  nginx

# 删除数据卷
docker volume rm html
docker volume prune    # 删除未使用的数据卷

特点：

  • Docker 自动管理（路径在 /var/lib/docker/volumes/）
  • 路径较长，不直观
  • 适合容器间共享数据

方式二：绑定挂载（Bind Mount，推荐）

bash
docker run -d \
  --name my-nginx \
  -p 80:80 \
  -v /home/nginx/html:/usr/share/nginx/html \   # 宿主机路径:容器路径
  nginx

特点：

  • 直接指定宿主机路径，直观
  • 修改宿主机文件，容器内立刻生效
  • 推荐开发和部署使用

5.3 数据卷实战

挂载 nginx 配置文件：

bash
docker run -d \
  --name my-nginx \
  -p 80:80 \
  -v /home/nginx/conf:/etc/nginx/conf.d \    # 挂载配置目录
  -v /home/nginx/html:/usr/share/nginx/html \ # 挂载静态文件目录
  -v /home/nginx/logs:/var/log/nginx \         # 挂载日志目录
  nginx

现在修改 /home/nginx/conf 下的配置文件，重启容器就能生效：

bash
# 修改 nginx 配置
vi /home/nginx/conf/default.conf

# 重启使配置生效
docker restart my-nginx

挂载 MySQL 数据：

bash
docker run -d \
  --name mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v /data/mysql/data:/var/lib/mysql \          # 数据目录
  -v /data/mysql/conf:/etc/mysql/conf.d \       # 配置目录
  -v /data/mysql/init:/docker-entrypoint-initdb.d \  # 初始化 SQL
  mysql:5.7

💡 初始化 SQL：把 .sql 文件放到 /data/mysql/init/，容器首次启动会自动执行。

第六章：Dockerfile 自定义镜像 ⭐⭐

6.1 镜像的分层结构

镜像是一层一层叠加的：

text
运行结果镜像
    └── 设置 ENTRYPOINT 层（启动命令）
         └── COPY app.jar 层
              └── 安装 JRE 层
                   └── 配置时区层
                        └── Ubuntu 20.04 基础层

相同的层可以复用，节省空间。

6.2 Dockerfile 语法

dockerfile
# 基础镜像
FROM ubuntu:20.04

# 构建者信息（可选）
LABEL maintainer="xxx@xxx.com"

# 在镜像里执行命令（安装软件等）
RUN apt-get update && apt-get install -y openjdk-8-jdk

# 设置工作目录（后续命令都在这个目录执行）
WORKDIR /app

# 拷贝文件（从宿主机 → 镜像）
# COPY 源路径 目标路径
COPY app.jar /app/app.jar

# ADD 和 COPY 类似，但 ADD 会自动解压 tar 包
# ADD app.tar.gz /app/

# 设置环境变量
ENV JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
ENV TZ=Asia/Shanghai

# 声明容器要用的端口（只是声明，不是真的映射）
EXPOSE 8080

# 容器启动时执行的命令
# ENTRYPOINT：不会被 docker run 后面的命令覆盖（推荐）
ENTRYPOINT ["java", "-jar", "app.jar"]
# CMD：会被 docker run 后面的命令覆盖
# CMD ["java", "-jar", "app.jar"]

常用指令说明：

指令 说明
FROM 基础镜像（必须，第一行）
RUN 构建时执行命令
COPY 拷贝文件（不解压）
ADD 拷贝文件（会解压 tar）
WORKDIR 设置工作目录
ENV 设置环境变量
EXPOSE 声明端口
ENTRYPOINT 容器启动命令（不可覆盖）
CMD 容器启动命令（可覆盖）

6.3 构建 Java 应用镜像

方式 1：基于 Ubuntu（麻烦但灵活）

dockerfile
FROM ubuntu:20.04

# 安装 JRE
RUN apt-get update && apt-get install -y openjdk-8-jdk-headless

# 设置时区
ENV TZ=Asia/Shanghai
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone

WORKDIR /app
COPY app.jar /app/app.jar

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

方式 2：基于 java:8-alpine（推荐，更小）

dockerfile
FROM java:8-alpine     # 已经装好了 JDK 8，体积小

COPY ./app.jar /tmp/app.jar

EXPOSE 8080

ENTRYPOINT java -jar /tmp/app.jar

构建命令：

bash
# 在 Dockerfile 所在目录执行
docker build -t myapp:1.0 .
# -t：指定镜像名和标签
# .：Dockerfile 在当前目录

# 查看构建好的镜像
docker images | grep myapp

# 运行
docker run -d --name myapp -p 8080:8080 myapp:1.0

6.4 Dockerfile 注意事项

  1. 每个 RUN 指令都是一层，层太多会导致镜像大。用 && 合并多条命令：
dockerfile
# ❌ 不好（3层）
RUN apt-get update
RUN apt-get install -y wget
RUN apt-get clean

# ✅ 好（1层）
RUN apt-get update && \
    apt-get install -y wget && \
    apt-get clean
  1. 把不常变动的放前面（利用缓存），把经常变动的（代码）放后面。

第七章：Docker Compose ⭐⭐⭐

7.1 什么是 Docker Compose

问题：一个微服务项目需要启动十几个容器（MySQL、Redis、Nacos、各种服务），每次都手敲一堆命令。

Docker Compose 解决：用一个 docker-compose.yml 文件定义所有容器，一条命令启停整个项目。

类比：

  • 没有 Compose：每个乐手自己调音、自己上台
  • 有 Compose：指挥一声令下，所有乐手同时上台演奏

7.2 docker-compose.yml 语法

yaml
version: "3.8"   # Compose 版本

services:         # 定义各个容器
  mysql:          # 服务名（容器名默认是 "目录名_服务名_序号"）
    image: mysql:5.7           # 使用哪个镜像
    container_name: mysql      # 自定义容器名
    ports:                     # 端口映射
      - "3306:3306"
    environment:               # 环境变量
      MYSQL_ROOT_PASSWORD: "123456"
    volumes:                   # 数据卷
      - /data/mysql:/var/lib/mysql
    networks:                  # 加入的网络
      - my-net
    restart: always            # 总是自动重启

  redis:
    image: redis:latest
    container_name: redis
    ports:
      - "6379:6379"
    networks:
      - my-net

  user-service:
    build: ./user-service      # 通过 Dockerfile 构建（指定目录）
    container_name: user-service
    ports:
      - "8081:8081"
    networks:
      - my-net
    depends_on:                # 等 mysql 和 redis 启动后再启动
      - mysql
      - redis
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/db?...
      # 注意：用容器名代替 IP（同一网络内可以互访）

networks:         # 定义网络
  my-net:
    driver: bridge

volumes:          # 定义具名数据卷（可选）
  mysql-data:

7.3 常用命令

bash
# 启动所有容器（-d 后台运行）
docker-compose up -d

# 停止并删除容器（不删数据卷）
docker-compose down

# 只停止（不删除）
docker-compose stop

# 重新构建（代码更新后）
docker-compose build
docker-compose up -d --build   # 构建并启动

# 查看日志
docker-compose logs            # 所有容器
docker-compose logs user-service  # 指定容器
docker-compose logs -f user-service  # 持续输出

# 查看状态
docker-compose ps

# 重启某个服务
docker-compose restart user-service

7.4 实战：部署微服务项目

目录结构：

text
deploy/
├── docker-compose.yml
├── mysql/
│   └── init/
│       └── hm.sql        # 初始化 SQL
└── gateway/
    └── Dockerfile

docker-compose.yml：

yaml
version: "3.8"

services:
  mysql:
    image: mysql:5.7
    container_name: mysql
    environment:
      MYSQL_ROOT_PASSWORD: "123456"
    ports:
      - "3306:3306"
    volumes:
      - /data/mysql/data:/var/lib/mysql
      - /data/mysql/init:/docker-entrypoint-initdb.d
    networks:
      - hm-net
    healthcheck:
      test: [ "CMD", "mysqladmin", "ping", "-h", "localhost" ]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:latest
    container_name: redis
    ports:
      - "6379:6379"
    networks:
      - hm-net

  nacos:
    image: nacos/nacos-server:v2.1.0-slim
    container_name: nacos
    environment:
      MODE: standalone
    ports:
      - "8848:8848"
      - "9848:9848"
    networks:
      - hm-net
    depends_on:
      mysql:
        condition: service_healthy   # 等 MySQL 健康检查通过

  user-service:
    build: ./user-service
    container_name: user-service
    ports:
      - "8081:8081"
    networks:
      - hm-net
    depends_on:
      - nacos
      - mysql
      - redis

  gateway:
    build: ./gateway
    container_name: gateway
    ports:
      - "10010:10010"
    networks:
      - hm-net
    depends_on:
      - nacos

networks:
  hm-net:
    driver: bridge

第八章：常见报错与解决

报错 1：Cannot connect to the Docker daemon

text
原因：Docker 没有启动
解决：systemctl start docker

报错 2：port is already allocated

text
原因：宿主机的端口已被其他进程占用
解决：
1. netstat -nltp | grep 3306   查看占用端口的进程
2. 换一个宿主机端口，如 -p 3307:3306

报错 3：No space left on device

text
原因：磁盘空间不够
解决：
1. df -h 查看磁盘
2. docker system prune -a   清理没用的镜像、容器、数据卷

报错 4：容器启动后立刻退出

text
原因 1：应用启动报错
解决：docker logs 容器名  查看日志

原因 2：前台命令改成了后台（daemon）
解决：确保应用前台运行（不能加 -d 参数给应用本身）

原因 3：Dockerfile 中 ENTRYPOINT 写错了
解决：检查命令语法

报错 5：Compose 文件格式错误

text
原因：YAML 缩进不对
解决：
1. 用 docker-compose config  验证文件语法
2. YAML 用空格缩进，不能用 Tab

第九章：面试常问（附答案）

Q1：Docker 和虚拟机的区别？

答：

  • 虚拟机：完整 OS 虚拟化，GB 级、分钟启动、隔离性强
  • Docker：进程级隔离，共享 OS 内核，MB 级、秒级启动、性能好

Q2：Docker 镜像和容器的关系？

答：镜像是只读的模板，容器是镜像运行的实例。一个镜像可以启动多个容器。

Q3：数据卷的作用？

答：持久化容器数据（容器删了数据不丢），以及宿主机和容器间共享文件。

Q4：COPY 和 ADD 的区别？

答：ADD 会自动解压 tar 包，其他与 COPY 相同。推荐用 COPY（更清晰）。

Q5：ENTRYPOINT 和 CMD 的区别？

答：

  • CMD：可被 docker run 后面的命令覆盖
  • ENTRYPOINT：不可覆盖，docker run 后面的命令作为参数

Q6：Docker Compose 的作用？

答：用 YAML 文件定义多容器应用，一条命令批量启停，简化微服务部署。

⚠ 新手易踩的坑

  1. 端口映射格式：宿主机端口:容器端口（顺序不要搞错）
  2. exec -it 进容器，exit 退出不会停容器
  3. 删容器前要先 stop，或用 rm -f
  4. 数据卷删容器不会删，volume prune 才删
  5. Compose 文件用空格缩进，不能用 Tab
  6. 容器互访用容器名作为主机名（不用 IP）

💡 学习建议：Docker 是工具，重点是动手。先把 MySQL 和 Redis 用 Docker 跑起来，再学 Compose 编排多容器，最后练习打包自己的项目。每个命令都跑一遍，才能真正掌握。
