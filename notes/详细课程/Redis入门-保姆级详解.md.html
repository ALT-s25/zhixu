第一章：什么是 Redis（用大白话讲）

1.1 先讲个故事

想象你开了一家餐厅：

  • 厨房是数据库（MySQL），做菜慢但菜品全
  • 服务员是程序，负责接单和上菜
  • 客人是用户，点菜后等着上菜

问题来了：

  • 每次客人都问"今天有什么菜"，服务员都要跑厨房问一遍，厨房烦死了
  • 每次客人都问"WiFi 密码"，服务员跑厨房问，厨房更烦

Redis 就是"菜单牌"：

  • 常问的问题写在菜单牌上（Redis）
  • 服务员先看菜单牌，有答案直接回答，不用跑厨房
  • 菜牌内容偶尔更新，保证和厨房一致

Redis = 内存里的快速查询表，比数据库快得多（因为数据在内存，不用读磁盘）。

1.2 Redis 官方定义

Redis 全称：Remote Dictionary Server（远程词典服务器）

简单说：一个基于内存的、键值对存储的数据库。

核心特点：

  • 快：数据在内存里，读写速度极快（微秒级）
  • 简单：键值对结构，5 种数据类型
  • 持久化：内存数据可以存到磁盘（防断电丢失）
  • 单线程：一条命令一条命令执行，不会互相打架

1.3 为什么用 Redis（对比 MySQL）

用一个表格直观看：

对比项 MySQL（数据库） Redis（缓存）
数据放哪 磁盘 内存
速度 慢（毫秒级） 快（微秒级）
容量 大（TB 级） 小（GB 级）
用途 存全量数据 存热点数据、临时数据
断电 数据还在 默认丢失（需持久化）

💡 新手提示：Redis 不是替代 MySQL 的，而是配合 MySQL 用。MySQL 存所有数据，Redis 存经常要查的数据（缓存）。

1.4 关系型 vs 非关系型数据库

Redis 属于 NoSQL（Not Only SQL，非关系型数据库）。

关系型（MySQL） 非关系型（Redis）
数据结构 表格（行和列） 键值对
关联 外键关联 无关联，业务自己维护
事务 完整 ACID 基本一致性
查询 SQL 标准语法 各自不同
存储 磁盘 内存

第二章：安装 Redis（手把手）

2.1 Windows 安装（不推荐，但能用）

⚠ Redis 官方不支持 Windows，但学习可以用。

  1. 下载：去 GitHub 搜 "Redis Windows"，下载 .zip 或 .msi
  2. 解压到 D:\Redis 之类目录
  3. 双击 redis-server.exe 启动服务
  4. 双击 redis-cli.exe 打开命令行客户端

2.2 Linux 安装（推荐，生产环境）

步骤 1：安装依赖

Redis 用 C 语言写的，需要 gcc 编译器：

bash
# CentOS
yum install -y gcc tcl

# Ubuntu
apt install -y gcc tcl

步骤 2：下载并解压

bash
# 下载（或用 XFTP 上传安装包）
cd /usr/local/src
wget https://download.redis.io/releases/redis-6.2.6.tar.gz

# 解压
tar -xzf redis-6.2.6.tar.gz

# 进入目录
cd redis-6.2.6

步骤 3：编译安装

bash
# 编译并安装（默认装到 /usr/local/bin）
make && make install

安装成功后，/usr/local/bin 下会有：

  • redis-server：服务端启动脚本
  • redis-cli：命令行客户端
  • redis-sentinel：哨兵脚本（后面高级篇讲）

步骤 4：修改配置文件

bash
# 备份配置（养成好习惯）
cp redis.conf redis.conf.bck

# 编辑配置
vi redis.conf

修改这几个关键配置：

properties
# 允许哪些 IP 访问。127.0.0.1 只能本机访问
# 改成 0.0.0.0 表示所有 IP 都能访问（学习用，生产慎用）
bind 0.0.0.0

# 是否后台运行。yes 表示后台运行（推荐）
daemonize yes

# 访问密码（不设就是没密码）
requirepass 123321

# 端口（默认 6379）
port 6379

# 最大内存（学习可以不设，生产一定要设）
maxmemory 512mb

# 日志文件
logfile "redis.log"

步骤 5：启动 Redis

bash
# 进入 Redis 安装目录
cd /usr/local/src/redis-6.2.6

# 启动（指定配置文件）
redis-server redis.conf

步骤 6：连接 Redis

bash
# 连接（带密码）
redis-cli -h 127.0.0.1 -p 6379 -a 123321

# 测试（输入 ping，返回 pong 说明成功）
127.0.0.1:6379> ping
PONG

步骤 7：停止 Redis

bash
# 方法 1：在 redis-cli 中
127.0.0.1:6379> shutdown

# 方法 2：在终端
redis-cli -a 123321 shutdown

2.3 Docker 安装（最简单，强烈推荐）⭐

如果装了 Docker，一行命令搞定：

bash
docker run -d \
  --name redis \                        # 容器名
  -p 6379:6379 \                        # 端口映射：宿主机:容器
  redis:latest \                        # 镜像名
  redis-server --requirepass 123321    # 启动时设置密码

命令解读：

  • -d：后台运行
  • --name：给容器起个名字
  • -p 6379:6379：把容器的 6379 端口映射到宿主机的 6379 端口（这样外部能访问）
  • --requirepass：设置密码

启动后连接：

bash
# 进入容器内的 redis-cli
docker exec -it redis redis-cli -a 123321

2.4 常见安装报错 ⚠

报错 1：gcc: command not found

bash
# 原因：没装 gcc
# 解决：
yum install -y gcc       # CentOS
apt install -y gcc        # Ubuntu

报错 2：make: *** No targets specified

bash
# 原因：不在 redis 源码目录
# 解决：cd 到解压后的目录
cd /usr/local/src/redis-6.2.6

报错 3：Could not connect to Redis at 127.0.0.1:6379

bash
# 原因 1：Redis 没启动
# 解决：redis-server redis.conf

# 原因 2：密码不对
# 解决：redis-cli -a 你的密码

报错 4：NOAUTH Authentication required

bash
# 原因：连上了但没认证（没输密码）
# 解决：
127.0.0.1:6379> auth 123321    # 输入密码
OK

第三章：Redis 通用命令（先学这几个）

通用命令 = 对所有数据类型都适用的命令。先记住这 5 个，够用了：

3.1 KEYS：查找 key

bash
# 查所有 key（生产环境千万别用！会卡死）
127.0.0.1:6379> KEYS *
1) "name"
2) "age"

# 查以 a 开头的 key
127.0.0.1:6379> KEYS a*
1) "age"

⚠ 重要警告：KEYS * 在生产环境绝对不能用！key 多的时候会阻塞 Redis 几秒甚至几分钟，所有请求都卡住。生产用 SCAN 替代。

3.2 DEL：删除 key

bash
# 删一个
127.0.0.1:6379> DEL name
(integer) 1    # 返回成功删除的数量

# 删多个
127.0.0.1:6379> DEL k1 k2 k3
(integer) 3    # 成功删了 3 个

3.3 EXISTS：判断 key 是否存在

bash
127.0.0.1:6379> EXISTS age
(integer) 1    # 1 表示存在

127.0.0.1:6379> EXISTS name
(integer) 0    # 0 表示不存在

3.4 EXPIRE：设置过期时间

bash
# 给 age 设置 10 秒过期
127.0.0.1:6379> EXPIRE age 10
(integer) 1    # 1 表示设置成功

10 秒后再查 age，就找不到了（自动删除）。

3.5 TTL：查看剩余过期时间

bash
# 刚设了 10 秒，立刻查
127.0.0.1:6379> TTL age
(integer) 8    # 还剩 8 秒

# 等一会儿再查
127.0.0.1:6379> TTL age
(integer) 3    # 还剩 3 秒

# 过期后再查
127.0.0.1:6379> TTL age
(integer) -2   # -2 表示 key 已过期（不存在了）

TTL 返回值含义：

返回值 含义
正数 还剩多少秒
-1 永不过期（没设过期时间）
-2 已过期或不存在

💡 类比记忆：TTL = Time To Live，剩余寿命。-1 = 永生，-2 = 已经死了。

第四章：5 种数据类型（核心中的核心）

Redis 的 value 有 5 种类型，每种适合不同场景。这是 Redis 的灵魂。

4.1 String（字符串）⭐⭐⭐

最简单的类型：value 就是一个字符串。

但根据内容不同，又分 3 种：

  • 普通字符串："hello"
  • 整数："123"（可以做加减）
  • 浮点："3.14"（可以做加减）

常用命令

bash
# 设置（key 不存在就是新增，存在就是修改）
127.0.0.1:6379> SET name Rose    # 新增 name
OK
127.0.0.1:6379> GET name
"Rose"

127.0.0.1:6379> SET name Jack    # 修改 name
OK
127.0.0.1:6379> GET name
"Jack"

# 批量设置和获取
127.0.0.1:6379> MSET k1 v1 k2 v2 k3 v3   # 一次设 3 个
OK
127.0.0.1:6379> MGET k1 k2 k3            # 一次取 3 个
1) "v1"
2) "v2"
3) "v3"

# 整数自增（要求 value 是数字）
127.0.0.1:6379> SET age 10
OK
127.0.0.1:6379> INCR age        # 自增 1
(integer) 11
127.0.0.1:6379> INCRBY age 5    # 自增 5
(integer) 16
127.0.0.1:6379> INCRBY age -2   # 减 2（加负数）
(integer) 14

# SETNX：不存在才设置（重要！分布式锁用）
127.0.0.1:6379> SETNX name lisi    # name 已存在，失败
(integer) 0
127.0.0.1:6379> SETNX name2 lisi   # name2 不存在，成功
(integer) 1

# SETEX：设置并指定过期时间
127.0.0.1:6379> SETEX code 60 123456   # 验证码 60 秒过期
OK

Key 的层级命名（重要习惯）⭐

Redis 没有 MySQL 的"表"概念，怎么区分不同类型的数据？

用 : 分层级命名：

text
项目名:数据类型:ID

比如：

bash
# 用户数据
SET heima:user:1 '{"id":1,"name":"Jack","age":21}'
SET heima:user:2 '{"id":2,"name":"Rose","age":20}'

# 商品数据
SET heima:product:1 '{"id":1,"name":"小米11","price":3999}'

这样在可视化工具里会自动形成树状结构，一目了然：

text
heima
├── user
│   ├── 1
│   └── 2
└── product
    └── 1

String 使用场景

场景 怎么用
缓存对象 SET user:1 '{"name":"Jack"}'（存 JSON）
计数器 INCR article:read:1（文章阅读量）
分布式锁 SETNX lock:order:1 true
验证码 SETEX code:13800138000 60 123456
全局 ID INCR id:order（生成唯一 ID）

4.2 Hash（哈希）⭐⭐

类比：Hash 就像 Java 的 HashMap，一个 key 对应一个对象，对象里有多个字段。

text
key = "user:1"
value = {
    "name": "Jack",
    "age": 21,
    "city": "北京"
}

String vs Hash 存对象

String Hash
存储方式 整个对象转 JSON 每个字段独立存
修改某个字段 读取整个 JSON，改完再存 直接 HSET 改一个字段
适合 整体读写 频繁改单字段

常用命令

bash
# 设置一个字段
127.0.0.1:6379> HSET user:1 name Jack
(integer) 1
127.0.0.1:6379> HSET user:1 age 21
(integer) 1

# 获取一个字段
127.0.0.1:6379> HGET user:1 name
"Jack"

# 批量设置
127.0.0.1:6379> HMSET user:2 name Rose age 20 city "上海"
OK

# 批量获取
127.0.0.1:6379> HMGET user:2 name age city
1) "Rose"
2) "20"
3) "上海"

# 获取所有字段和值
127.0.0.1:6379> HGETALL user:2
1) "name"
2) "Rose"
3) "age"
4) "20"
5) "city"
6) "上海"

# 获取所有字段名
127.0.0.1:6379> HKEYS user:2
1) "name"
2) "age"
3) "city"

# 获取所有值
127.0.0.1:6379> HVALS user:2
1) "Rose"
2) "20"
3) "上海"

# 删除一个字段
127.0.0.1:6379> HDEL user:2 city
(integer) 1

# 字段自增
127.0.0.1:6379> HINCRBY user:1 age 2
(integer) 23

# 字段不存在才设置
127.0.0.1:6379> HSETNX user:1 gender male
(integer) 1    # gender 不存在，成功
127.0.0.1:6379> HSETNX user:1 name Tom
(integer) 0    # name 已存在，失败

Hash 使用场景

场景 怎么用
用户信息缓存 HSET user:1 name Jack age 21
购物车 HSET cart:用户ID 商品ID 数量（改数量方便）
商品库存 HSET stock:product:1 总库存 100 已售 20

4.3 List（列表）⭐⭐

类比：像 Java 的 LinkedList，双向链表。

特点：

  • 有序：按插入顺序排列
  • 可重复：相同元素可以多次出现
  • 从两端操作：左插、右插、左取、右取
text
LPUSH（左插）→ [3, 2, 1] → RPUSH（右插）→ [3, 2, 1, 4, 5, 6]

常用命令

bash
# 左侧插入（结果：3 2 1）
127.0.0.1:6379> LPUSH users 1 2 3
(integer) 3

# 右侧插入（结果：3 2 1 4 5 6）
127.0.0.1:6379> RPUSH users 4 5 6
(integer) 6

# 查看所有（0 到 -1 表示第一个到最后一个）
127.0.0.1:6379> LRANGE users 0 -1
1) "3"
2) "2"
3) "1"
4) "4"
5) "5"
6) "6"

# 左侧弹出（取出并删除）
127.0.0.1:6379> LPOP users
"3"

# 右侧弹出
127.0.0.1:6379> RPOP users
"6"

# 长度
127.0.0.1:6379> LLEN users
(integer) 4

List 的三种模式（重要）

模式 实现 应用
栈（后进先出 LIFO） LPUSH + LPOP 撤销操作
队列（先进先出 FIFO） LPUSH + RPOP 消息队列
阻塞队列 LPUSH + BRPOP 等待消息

List 使用场景

  • 消息队列（轻量级）：生产者 LPUSH，消费者 BRPOP
  • 最新动态：朋友圈、微博的最新 N 条
  • 文章列表：博客最新文章列表

4.4 Set（集合）⭐⭐

类比：像 Java 的 HashSet，无序、不重复。

特点：

  • 无序：不保证插入顺序
  • 不重复：相同元素只存一次
  • 支持集合运算：交集、并集、差集

常用命令

bash
# 添加元素
127.0.0.1:6379> SADD zs_friends lisi wangwu zhaoliu
(integer) 3

127.0.0.1:6379> SADD ls_friends wangwu mazi ergou
(integer) 3

# 查看所有元素
127.0.0.1:6379> SMEMBERS zs_friends
1) "lisi"
2) "wangwu"
3) "zhaoliu"

# 元素个数
127.0.0.1:6379> SCARD zs_friends
(integer) 3

# 判断是否包含
127.0.0.1:6379> SISMEMBER zs_friends lisi
(integer) 1    # 1 = 包含
127.0.0.1:6379> SISMEMBER zs_friends mazi
(integer) 0    # 0 = 不包含

# 删除元素
127.0.0.1:6379> SREM zs_friends lisi
(integer) 1

# 求交集（共同好友）
127.0.0.1:6379> SINTER zs_friends ls_friends
1) "wangwu"    # 两人共同的好友

# 求差集（张三有但李四没有的）
127.0.0.1:6379> SDIFF zs_friends ls_friends
1) "zhaoliu"

# 求并集（两人所有好友）
127.0.0.1:6379> SUNION zs_friends ls_friends
1) "wangwu"
2) "zhaoliu"
3) "mazi"
4) "ergou"

Set 使用场景

场景 怎么用
共同好友 SINTER 两个用户的 Set
去重 SADD 后自动去重
抽奖 SRANDMEMBER key n 随机取 n 个
标签 用户加标签，文章加标签，求交集

4.5 SortedSet（有序集合）⭐⭐⭐

类比：像 Java 的 TreeSet，但每个元素带一个 score（分数），按分数排序。

特点：

  • 有序：按 score 排序
  • 不重复：元素不重复
  • 查询快：底层是跳表（SkipList）
text
SortedSet
┌──────────┬───────┬──────────┐
│ 元素     │ score │ 排名    │
├──────────┼───────┼──────────┤
│ user1    │ 100   │ 1       │
│ user2    │ 90    │ 2       │
│ user3    │ 80    │ 3       │
└──────────┴───────┴──────────┘
按 score 降序排列

常用命令

bash
# 添加元素（带 score）
127.0.0.1:6379> ZADD rank 100 user1 90 user2 80 user3
(integer) 3

# 查看所有（升序，0 到 -1）
127.0.0.1:6379> ZRANGE rank 0 -1
1) "user3"    # 80 分，第 1 名（升序）
2) "user2"    # 90 分
3) "user1"    # 100 分

# 查看所有（降序）
127.0.0.1:6379> ZREVRANGE rank 0 -1
1) "user1"    # 100 分，第 1 名（降序）
2) "user2"
3) "user3"

# 查看所有（带分数）
127.0.0.1:6379> ZRANGE rank 0 -1 WITHSCORES
1) "user3"
2) "80"
3) "user2"
4) "90"
5) "user1"
6) "100"

# 获取某元素的分数
127.0.0.1:6379> ZSCORE rank user1
"100"

# 获取排名（升序，从 0 开始）
127.0.0.1:6379> ZRANK rank user1
(integer) 2

# 获取排名（降序）
127.0.0.1:6379> ZREVRANK rank user1
(integer) 0    # 降序第 1 名

# 元素个数
127.0.0.1:6379> ZCARD rank
(integer) 3

# 分数自增
127.0.0.1:6379> ZINCRBY rank 5 user2
"95"    # user2 从 90 变成 95

# 按分数范围查
127.0.0.1:6379> ZRANGEBYSCORE rank 80 95
1) "user3"
2) "user2"

# 统计分数范围内的元素数
127.0.0.1:6379> ZCOUNT rank 80 95
(integer) 2

💡 规律：想要降序，在命令的 Z 后面加 REV。ZRANK → ZREVRANK，ZRANGE → ZREVRANGE

第五章：Java 操作 Redis（SpringDataRedis）

5.1 为什么用 Java 客户端

命令行敲命令很爽，但项目中是用代码操作 Redis。

Java 操作 Redis 有几种方式：

  • Jedis：最古老的客户端，API 和 Redis 命令一一对应
  • Lettuce：基于 Netty，支持异步，性能好
  • SpringDataRedis：Spring 封装的，对 Jedis 和 Lettuce 做了抽象（推荐）

5.4 序列化问题（新手必看）⚠

问题：直接用 RedisTemplate<String, Object>，存到 Redis 的数据会变成乱码！

text
# 存进去的：Jack
# Redis 里显示：\xac\xed\x00\x05t\x00\x04Jack  ← 这是 Java 序列化的结果

原因：默认用 Java 的 ObjectOutputStream 序列化，可读性差、体积大、不安全。

解决：配置 JSON 序列化 ⭐

java
@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        // 1. 创建 RedisTemplate
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);   // 设置连接工厂

        // 2. 定义 JSON 序列化器
        GenericJackson2JsonRedisSerializer jsonSerializer =
            new GenericJackson2JsonRedisSerializer();

        // 3. key 用 String 序列化（key 都是字符串，不需要 JSON）
        template.setKeySerializer(RedisSerializer.string());
        template.setHashKeySerializer(RedisSerializer.string());

        // 4. value 用 JSON 序列化
        template.setValueSerializer(jsonSerializer);
        template.setHashValueSerializer(jsonSerializer);

        // 5. 生效配置
        template.afterPropertiesSet();
        return template;
    }
}

配置后，存对象会自动转 JSON：

java
// 存对象
User user = new User("Jack", 21);
redisTemplate.opsForValue().set("user:1", user);

// Redis 里显示（可读）：
// {"@class":"com.itheima.User","name":"Jack","age":21}

5.5 StringRedisTemplate（更推荐）⭐⭐

RedisTemplate 配置序列化虽然能用，但存对象时会带一个 @class 字段，比较占空间。

更推荐用 StringRedisTemplate（默认 String 序列化，不会乱码），存取时手动转 JSON：

java
@Autowired
private StringRedisTemplate stringRedisTemplate;

// 工具：JSON 转换（用 Hutool 或 Jackson）
// 存对象 → 转 JSON 字符串 → 存
User user = new User("Jack", 21);
String json = JSONUtil.toJsonStr(user);          // 对象转 JSON
stringRedisTemplate.opsForValue().set("user:1", json);

// 取 → JSON 字符串 → 转回对象
String val = stringRedisTemplate.opsForValue().get("user:1");
User u = JSONUtil.toBean(val, User.class);       // JSON 转对象

💡 两种方式对比：

  • RedisTemplate + JSON 序列化：自动转，但有 @class 字段
  • StringRedisTemplate + 手动转 JSON：可控，推荐

第六章：项目实战场景

🎯 场景 1：缓存商品信息

最经典的用法，每个项目都有：

java
@Service
public class ShopService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    public Shop queryShopById(Long id) {
        // 1. 拼 key
        String key = "cache:shop:" + id;

        // 2. 从 Redis 查
        String json = redisTemplate.opsForValue().get(key);

        // 3. 命中缓存：直接返回
        if (StrUtil.isNotBlank(json)) {
            return JSONUtil.toBean(json, Shop.class);   // JSON 转 Shop
        }

        // 4. 未命中：查数据库
        Shop shop = shopMapper.selectById(id);
        if (shop == null) {
            return null;    // 数据库也没有，返回 null
        }

        // 5. 写入缓存（30 分钟过期）
        redisTemplate.opsForValue().set(
            key,
            JSONUtil.toJsonStr(shop),
            30, TimeUnit.MINUTES
        );

        return shop;
    }
}

第七章：面试常问（附答案）

Q1：Redis 为什么快？

答：

  1. 纯内存操作：数据在内存，读写不用碰磁盘
  2. 单线程：避免多线程切换开销和锁竞争
  3. IO 多路复用：一个线程处理多个连接（epoll）
  4. 高效数据结构：SDS、跳表等

Q2：Redis 和 MySQL 的区别？

答：

  • Redis 在内存，快但容量小，用于缓存热点数据
  • MySQL 在磁盘，慢但容量大，用于存全量数据
  • 两者配合：MySQL 存全量，Redis 缓存热点

Q3：五种数据类型分别适合什么场景？

答：

  • String：缓存、计数器、分布式锁
  • Hash：用户信息（字段级修改）
  • List：消息队列、最新动态
  • Set：去重、共同好友
  • SortedSet：排行榜、延迟队列

Q4：为什么生产环境不能用 KEYS *？

答：KEYS * 是 O(N) 操作，key 多时会阻塞 Redis 几秒到几分钟，期间所有请求都卡住。用 SCAN 替代（分批扫描）。

Q5：TTL 返回 -1 和 -2 什么区别？

答：

  • -1：key 存在但永不过期（没设过期时间）
  • -2：key 不存在（已过期或从未创建）

Q6：String 存对象用 String 还是 Hash？

答：

  • 整体读写多 → String（存 JSON）
  • 频繁改单字段 → Hash
