第一章：从单体到微服务

1.1 单体架构（Monolith）

类比：一栋多功能大楼——用餐、购物、娱乐、住宿都在里面。

text
单体应用
└── 一个 Jar/War
    ├── 用户模块
    ├── 订单模块
    ├── 商品模块
    └── 支付模块

优点：

  • 开发简单（都在一个项目里）
  • 部署简单（一个 jar 包）
  • 适合小团队、小项目

缺点：

  • 代码越来越多，启动慢、维护难
  • 任一模块出 bug，整个应用崩溃
  • 只能整体扩容，浪费资源

1.2 微服务架构（Microservices）

类比：商业综合体——餐厅、超市、KTV 分别独立运营，各自有自己的员工和管理。

text
微服务架构
├── user-service（用户服务）→ 独立部署
├── order-service（订单服务）→ 独立部署
├── product-service（商品服务）→ 独立部署
└── payment-service（支付服务）→ 独立部署

优点：

  • 独立开发、独立部署
  • 一个服务崩溃不影响其他
  • 按需扩容（订单访问量大，只扩容订单服务）

缺点：

  • 架构复杂，需要注册中心、网关等
  • 分布式事务难处理
  • 运维难度高

1.3 什么时候用微服务

单体 微服务
团队规模 小（< 10 人） 大（> 10 人）
业务复杂度 简单 复杂
访问量 低 高
推荐 创业初期 成熟产品

1.4 SpringCloud 是什么

SpringCloud = 微服务的全家桶工具包

它不是一个单独的框架，而是一堆框架的集合：

功能 SpringCloud 组件
注册中心 Nacos（新版推荐）/ Eureka（老版）
配置中心 Nacos
远程调用 Feign
网关 Gateway
服务保护 Sentinel
分布式事务 Seata

第二章：服务拆分与远程调用

2.1 服务拆分原则

  • 单一职责：每个服务只做一件事（用户服务只管用户）
  • 服务自治：每个服务有独立的数据库、代码库
  • 面向服务：通过 API 对外提供服务

2.2 问题：服务之间怎么通信

场景：订单服务需要查询用户信息。

用户服务在 localhost:8081，订单服务在 localhost:8080，两个服务怎么通信？

方法 1：RestTemplate（原始方式）

java
@Configuration
public class RestTemplateConfig {
    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}

@Service
public class OrderService {

    @Autowired
    private RestTemplate restTemplate;

    public Order queryOrderById(Long orderId) {
        Order order = orderMapper.findById(orderId);

        // 拼接 URL，硬编码 IP 和端口（不推荐！）
        String url = "http://localhost:8081/user/" + order.getUserId();

        // 发 GET 请求，返回 User 对象
        User user = restTemplate.getForObject(url, User.class);
        order.setUser(user);
        return order;
    }
}

问题：IP 和端口硬编码，服务扩容就崩了。需要注册中心。

第三章：Nacos 注册中心 ⭐⭐⭐

3.1 注册中心是什么

类比：外卖平台的商家管理系统。

  • 餐厅（服务）开门后，把地址和营业时间注册到外卖平台（注册中心）
  • 用户（服务消费者）打开外卖 App，从外卖平台拉取附近餐厅列表
  • 外卖平台定时检查餐厅是否还在营业（心跳检测）
text
服务A启动 → 注册到 Nacos（告诉 Nacos："我在 192.168.1.1:8081"）
服务B启动 → 注册到 Nacos
服务C要调用服务A → 从 Nacos 拉取服务A的地址列表 → 负载均衡选一个 → 发请求

3.2 安装 Nacos（Docker）

bash
docker run -d \
  --name nacos \
  --env-file ./nacos/custom.env \  # 配置文件
  -p 8848:8848 \
  -p 9848:9848 \
  -p 9849:9849 \
  --restart=always \
  nacos/nacos-server:v2.1.0-slim

properties

MYSQL_SERVICE_PORT=3306

访问：浏览器打开 http://服务器IP:8848/nacos，用 nacos/nacos 登录。

3.3 服务注册到 Nacos

步骤 1：添加依赖

xml
<!-- pom.xml -->
<!-- 如果用 Eureka 就换成 eureka 的依赖 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>

步骤 2：配置 Nacos 地址

yaml
# application.yaml
spring:
  application:
    name: user-service    # 服务名（其他服务通过这个名字找到你）
  cloud:
    nacos:
      server-addr: localhost:8848   # Nacos 地址

步骤 3：启动服务

服务启动后，去 Nacos 控制台 → 服务管理 → 服务列表，能看到 user-service 就说明注册成功。

3.4 服务发现（RestTemplate + 负载均衡）

有了注册中心，就不用硬编码 IP 了：

java
// 1. 给 RestTemplate 加 @LoadBalanced（开启负载均衡）
@Bean
@LoadBalanced   // 添加这个！
public RestTemplate restTemplate() {
    return new RestTemplate();
}

// 2. URL 中用服务名代替 IP:端口
// 原来：http://localhost:8081/user/1
// 现在：http://user-service/user/1
@Service
public class OrderService {

    @Autowired
    private RestTemplate restTemplate;

    public Order queryOrderById(Long orderId) {
        Order order = orderMapper.findById(orderId);

        // 用服务名，不用 IP！
        String url = "http://user-service/user/" + order.getUserId();
        User user = restTemplate.getForObject(url, User.class);
        order.setUser(user);
        return order;
    }
}

工作原理：

  1. 请求到 http://user-service/user/1
  2. @LoadBalanced 拦截请求，把 user-service 替换为实际 IP
  3. 通过负载均衡选一个实例（如 192.168.1.2:8081）
  4. 发送实际请求

3.5 Nacos 服务分级模型

类比：外卖平台按城市区分商家。

text
服务（user-service）
  └── 集群（HZ 杭州机房）
  │      ├── 实例1（192.168.1.1:8081）
  │      └── 实例2（192.168.1.2:8081）
  └── 集群（BJ 北京机房）
         └── 实例3（10.0.0.1:8081）

意义：同城调用（延迟低），跨城调用（延迟高）。优先同集群调用。

配置集群：

yaml
spring:
  cloud:
    nacos:
      discovery:
        cluster-name: HZ    # 所属集群名

同集群优先负载均衡：

yaml
# 针对 user-service 配置负载均衡策略
user-service:
  ribbon:
    NFLoadBalancerRuleClassName: com.alibaba.cloud.nacos.ribbon.NacosRule
    # NacosRule：同集群优先，同集群内随机，本集群挂了再跨集群

3.6 Nacos vs Eureka（面试常问）⭐

Nacos Eureka
实例类型 临时实例 + 永久实例 只有临时实例
心跳检测 客户端心跳 + 服务端主动检测 只有客户端心跳
变更推送 主动推送给客户端 客户端定时拉取
配置中心 ✅ 内置 ❌ 没有
CAP 临时 AP，永久 CP AP

💡 CAP 理论：一个分布式系统无法同时满足一致性（C）、可用性（A）、分区容错性（P）三个要求。

  • AP：追求可用性（保证服务可用，可能返回旧数据）
  • CP：追求一致性（数据要准，服务可能暂时不可用）

第四章：Feign 远程调用 ⭐⭐⭐（推荐）

4.1 为什么要用 Feign

用 RestTemplate 写 URL 太麻烦：

java
// RestTemplate：繁琐，URL 拼接容易出错
String url = "http://user-service/user/" + order.getUserId();
User user = restTemplate.getForObject(url, User.class);

用 Feign：

java
// Feign：简洁，像调本地方法一样
User user = userClient.findById(order.getUserId());

4.2 Feign 快速入门

步骤 1：添加依赖

xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>

步骤 2：启动类加注解

java
@SpringBootApplication
@EnableFeignClients   // 开启 Feign 客户端
public class OrderApplication {
    public static void main(String[] args) {
        SpringApplication.run(OrderApplication.class, args);
    }
}

步骤 3：定义 Feign 客户端接口

java
// 在 order-service 里定义，调用 user-service 的接口
@FeignClient("user-service")   // 指定要调用的服务名
public interface UserClient {

    // 映射 user-service 的 /user/{id} 接口
    @GetMapping("/user/{id}")
    User findById(@PathVariable("id") Long id);
}

步骤 4：注入并使用

java
@Service
public class OrderService {

    @Autowired
    private UserClient userClient;    // 注入 Feign 客户端

    public Order queryOrderById(Long orderId) {
        Order order = orderMapper.findById(orderId);

        // 调用 Feign 客户端，像调本地方法一样！
        User user = userClient.findById(order.getUserId());
        order.setUser(user);
        return order;
    }
}

工作原理：

text
userClient.findById(1L)
    ↓ Feign 动态代理
拼接 URL：http://user-service/user/1
    ↓ Ribbon 负载均衡
替换为实际地址：http://192.168.1.1:8081/user/1
    ↓ HttpClient 发请求
解析响应 JSON → User 对象
    ↓
返回给调用方

4.3 Feign 自定义配置

配置日志级别

yaml
feign:
  client:
    config:
      default:                 # default = 所有服务，或填服务名 = 针对某服务
        loggerLevel: FULL      # 日志级别
日志级别 记录内容
NONE 不记录（默认）
BASIC 请求方法、URL、响应码、时间
HEADERS BASIC + 请求头
FULL 所有（请求头、响应头、请求体、响应体）

💡 调试时用 FULL，生产环境用 NONE 或 BASIC（避免日志太多）。

配置超时时间

yaml
feign:
  client:
    config:
      default:
        connectTimeout: 5000     # 连接超时：5 秒
        readTimeout: 5000         # 读取超时：5 秒

4.4 Feign 性能优化（连接池）

默认用 URLConnection（不支持连接池），每次请求都新建 TCP 连接，性能差。

改用 HttpClient（支持连接池）：

xml
<dependency>
    <groupId>io.github.openfeign</groupId>
    <artifactId>feign-httpclient</artifactId>
</dependency>
yaml
feign:
  httpclient:
    enabled: true          # 开启 HttpClient
    max-connections: 200   # 最大连接数
    max-connections-per-route: 50  # 每个路由的最大连接

4.5 Feign 最佳实践（抽取公共模块）

问题：多个服务都需要调用 user-service，每个服务都定义一遍 UserClient，重复代码。

解决：抽取一个独立的 feign-api 模块，放公共的 Feign 接口和实体类。

text
项目结构
├── user-service（提供接口）
├── order-service（使用 feign-api）
├── payment-service（使用 feign-api）
└── feign-api（⭐ 公共模块）
    ├── UserClient.java
    └── User.java

order-service 启动类：

java
// 方式 1：指定扫描包（推荐）
@EnableFeignClients(basePackages = "cn.itcast.feign")

// 方式 2：指定 Feign 客户端类
@EnableFeignClients(clients = {UserClient.class})

第五章：Nacos 配置管理 ⭐⭐⭐

5.1 为什么要统一配置

问题：每个微服务有自己的 application.yaml，修改配置需要重启服务。有 100 个服务实例怎么办？

Nacos 配置中心解决：

  • 配置集中管理（在 Nacos 控制台修改）
  • 修改后不用重启，服务自动热更新

5.2 在 Nacos 中添加配置

进入 Nacos 控制台 → 配置管理 → 配置列表 → 新建配置

text
Data ID：user-service-dev.yaml
Group：DEFAULT_GROUP
配置格式：YAML
配置内容：
pattern:
  dateformat: yyyy-MM-dd HH:mm:ss

Data ID 命名规则：

text
${服务名}-${环境}.${文件扩展名}
user-service-dev.yaml     ← 开发环境
user-service-prod.yaml    ← 生产环境
user-service.yaml         ← 所有环境共享

5.3 微服务拉取 Nacos 配置

步骤 1：添加依赖

xml
<!-- Nacos 配置中心 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>

步骤 2：创建 bootstrap.yaml

⚠ 重要：必须用 bootstrap.yaml，不能用 application.yaml！ 因为 bootstrap.yaml 在 application.yaml 之前加载，要先从 Nacos 拉配置，再加载 application.yaml。

yaml
# bootstrap.yaml（优先级最高，最先加载）
spring:
  application:
    name: user-service    # 服务名（Nacos 配置文件名用这个）
  profiles:
    active: dev           # 环境（dev/prod/test）
  cloud:
    nacos:
      server-addr: localhost:8848
      config:
        file-extension: yaml  # 配置文件格式

步骤 3：使用配置

java
@RestController
@RequestMapping("/user")
public class UserController {

    // 读取 Nacos 配置（pattern.dateformat）
    @Value("${pattern.dateformat}")
    private String dateformat;

    @GetMapping("/now")
    public String now() {
        return LocalDateTime.now()
            .format(DateTimeFormatter.ofPattern(dateformat));
    }
}

配置优先级（从高到低）：

text
Nacos [user-service-dev.yaml]
    > Nacos [user-service.yaml]（所有环境共享）
        > 本地 application-dev.yaml
            > 本地 application.yaml

5.4 配置热更新 ⭐⭐

修改 Nacos 中的配置后，服务不需要重启，自动生效。

方式 1：@RefreshScope（逐个添加）

java
@RestController
@RequestMapping("/user")
@RefreshScope   // 加这个注解！（类上的注解）
public class UserController {

    @Value("${pattern.dateformat}")
    private String dateformat;
}

方式 2：@ConfigurationProperties（推荐）

java
// 专门接收配置的类（会自动热更新，无需 @RefreshScope）
@Component
@ConfigurationProperties(prefix = "pattern")
@Data
public class PatternProperties {
    private String dateformat;
    private String envSharedValue;  // 共享配置
}

// 使用
@RestController
@RequestMapping("/user")
public class UserController {

    @Autowired
    private PatternProperties properties;  // 注入配置类

    @GetMapping("/now")
    public String now() {
        return LocalDateTime.now()
            .format(DateTimeFormatter.ofPattern(properties.getDateformat()));
    }
}

💡 推荐方式 2：

  • 不需要 @RefreshScope，自动热更新
  • 配置集中管理，代码更整洁
  • 可以用 @Validated 做配置校验

第六章：Gateway 服务网关 ⭐⭐⭐

6.1 为什么要用网关

问题：微服务有几十个，每个都有自己的 IP 和端口，前端怎么访问？

没有网关：

text
前端 → user-service:8081
     → order-service:8082
     → product-service:8083
...
前端要知道所有服务的地址

有网关：

text
前端 → Gateway:10010
            ↓ 路由
       user-service:8081
       order-service:8082
       product-service:8083
...
前端只需要知道网关的地址

网关的作用：

  • 路由：把请求转发给对应的服务
  • 负载均衡：自动负载均衡
  • 权限认证：统一鉴权（JWT）
  • 限流：防止服务被打挂
  • 日志：统一记录访问日志

6.2 快速入门

步骤 1：创建 gateway-service 模块，添加依赖

xml
<!-- pom.xml -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>
<dependency>
    <!-- Nacos 注册发现（让网关能找到服务） -->
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>

步骤 2：配置路由规则

yaml
# application.yaml
server:
  port: 10010   # 网关端口

spring:
  application:
    name: gateway   # 服务名
  cloud:
    nacos:
      server-addr: localhost:8848   # 注册到 Nacos
    gateway:
      routes:   # 路由规则列表
        # 路由 1：user-service
        - id: user-service            # 路由 ID（唯一，自定义）
          uri: lb://user-service      # lb:// 表示负载均衡，user-service 是服务名
          predicates:                 # 路由条件（满足才转发）
            - Path=/user/**          # 路径以 /user/ 开头

        # 路由 2：order-service
        - id: order-service
          uri: lb://order-service
          predicates:
            - Path=/order/**

步骤 3：测试

原来访问：http://192.168.1.1:8081/user/1 现在访问：http://192.168.1.1:10010/user/1（通过网关）

6.3 路由断言（Predicates）

断言 = 路由条件，满足才转发。

断言 示例 含义
Path - Path=/user/** 路径匹配
After - After=2037-01-20T... 只在某时间之后
Before - Before=2031-04-13T... 只在某时间之前
Header - Header=X-Request-Id,\d+ 请求头匹配
Query - Query=name 有这个查询参数
Method - Method=GET,POST 请求方式

6.4 过滤器（Filters）⭐⭐

过滤器 = 在请求转发前/后做的处理。

内置过滤器示例：

yaml
spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://user-service
          predicates:
            - Path=/user/**
          filters:
            - AddRequestHeader=X-Request-From,gateway    # 添加请求头
            - RemoveRequestHeader=Authorization           # 删除请求头
            - StripPrefix=1                               # 去掉路径前缀
            - SetStatus=404                               # 设置响应状态码
      default-filters:   # 对所有路由生效
        - AddRequestHeader=X-From,gateway

6.5 自定义全局过滤器（实现认证）⭐⭐⭐

java
@Component
@Order(-1)   // 优先级，数字越小越先执行
@Slf4j
public class AuthorizeFilter implements GlobalFilter {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        // 1. 获取请求信息
        ServerHttpRequest request = exchange.getRequest();

        // 2. 从请求头获取 token
        String token = request.getHeaders().getFirst("authorization");

        // 3. 判断是否是登录请求（不需要认证的路径直接放行）
        String path = request.getPath().toString();
        if (path.contains("/login") || path.contains("/register")) {
            return chain.filter(exchange);  // 放行
        }

        // 4. 判断 token 是否有效（这里简化了，实际要解析 JWT）
        if (StrUtil.isBlank(token)) {
            // 没有 token，返回 401 未授权
            exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED);
            return exchange.getResponse().setComplete();  // 结束请求
        }

        // 5. 解析 token，获取用户信息
        // Long userId = jwtUtils.parseToken(token);
        // 把用户 ID 放到请求头，传给下游服务
        // request = request.mutate().header("user-info", userId.toString()).build();

        // 6. 放行
        return chain.filter(exchange);
    }
}

6.6 过滤器执行顺序

text
请求进入网关
    ↓
GlobalFilter（全局过滤器，按 order 排序）
    ↓
DefaultFilter（default-filters）
    ↓
RouteFilter（routes 下的 filters）
    ↓
转发请求到下游服务
    ↓
RouteFilter（返回时）
    ↓
DefaultFilter（返回时）
    ↓
GlobalFilter（返回时）
    ↓
响应客户端

💡 order 越小越先执行（@Order(-1) 比 @Order(0) 先执行）。

6.7 跨域配置（CORS）

前端 localhost:3000 调网关 localhost:10010，域名不同，浏览器报跨域错误。

yaml
spring:
  cloud:
    gateway:
      globalcors:
        add-to-simple-url-handler-mapping: true   # 允许 OPTIONS 请求
        cors-configurations:
          '[/**]':    # 对所有路径
            allowedOrigins:    # 允许的源
              - "http://localhost:3000"
              - "http://www.xxx.com"
            allowedMethods:    # 允许的请求方式
              - "GET"
              - "POST"
              - "PUT"
              - "DELETE"
              - "OPTIONS"
            allowedHeaders: "*"      # 允许的请求头
            allowCredentials: true   # 允许携带 cookie
            maxAge: 360000           # 预检请求缓存时间

第七章：Ribbon 负载均衡

7.1 什么是负载均衡

多个实例时，请求打到哪个实例？负载均衡算法决定。

text
user-service 有 3 个实例：
  - 192.168.1.1:8081
  - 192.168.1.2:8081
  - 192.168.1.3:8081

Ribbon 决定请求打哪个

7.2 负载均衡策略

策略类 策略
RoundRobinRule 轮询（1→2→3→1→...）默认
RandomRule 随机
RetryRule 重试（轮询 + 失败重试）
BestAvailableRule 请求量最少的
NacosRule Nacos 权重 + 同集群优先

配置策略（全局）：

java
// 配置类中
@Bean
public IRule randomRule() {
    return new RandomRule();   // 换成随机策略
}

配置策略（针对某服务）：

yaml
user-service:
  ribbon:
    NFLoadBalancerRuleClassName: com.netflix.loadbalancer.RandomRule

7.3 饥饿加载

默认第一次请求时才初始化 Ribbon，导致第一次超慢。配置饥饿加载，启动时初始化：

yaml
ribbon:
  eager-load:
    enabled: true
    clients:
      - user-service
      - order-service

第八章：常见报错与解决

报错 1：No instances available for user-service

text
原因：user-service 没有注册到 Nacos，或 Nacos 地址配置错误
解决：
1. 检查 user-service 是否启动
2. 检查 spring.cloud.nacos.server-addr 配置
3. 进 Nacos 控制台确认服务是否在线

报错 2：Feign 调用 404

text
原因：Feign 接口的路径和实际接口路径不匹配
解决：
1. 检查 @FeignClient 的服务名是否正确
2. 检查 @GetMapping 的路径是否与 user-service 的接口一致
3. 注意 @PathVariable 参数名要加上名称

示例（常见错误）：

java
// ❌ 错误：@PathVariable 没写参数名
User findById(@PathVariable Long id);

// ✅ 正确：必须写参数名
User findById(@PathVariable("id") Long id);

报错 3：配置热更新不生效

text
原因 1：用的 @Value 但没加 @RefreshScope
解决：加 @RefreshScope，或改用 @ConfigurationProperties

原因 2：bootstrap.yaml 没有创建（或拼写错误）
解决：在 resources 下创建 bootstrap.yaml（不是 application.yaml）

原因 3：Nacos 中的 Data ID 不匹配
解决：Data ID = 服务名-环境.后缀，检查三者是否匹配

报错 4：Gateway 转发 503

text
原因：下游服务没有注册到 Nacos，或网关 Nacos 地址配置错误
解决：
1. 检查下游服务是否注册到 Nacos
2. 检查 uri 中 lb://后面的服务名是否正确

第九章：面试常问（附答案）

Q1：为什么要用微服务？

答：单体应用代码庞大、维护难、扩容不灵活。微服务可以独立开发、独立部署、按需扩容，适合大型业务。

Q2：Nacos 和 Eureka 的区别？

答：

  • Nacos 支持临时/永久实例，可主动推送变更；Eureka 只有临时实例，定时拉取
  • Nacos 内置配置中心；Eureka 没有
  • Nacos 临时实例 AP（高可用），永久实例 CP（强一致）；Eureka 只有 AP

Q3：Feign 是怎么实现远程调用的？

答：Feign 基于动态代理，启动时扫描所有 @FeignClient 接口，生成代理对象。调用时自动拼接 URL，通过 Ribbon 负载均衡，用 HttpClient 发送请求，解析响应。

Q4：为什么配置中心要用 bootstrap.yaml？

答：bootstrap.yaml 比 application.yaml 先加载。需要先从 Nacos 拉配置，所以 Nacos 配置要放在 bootstrap.yaml 里。

Q5：Gateway 的核心功能？

答：路由转发、负载均衡、身份认证、限流、跨域处理。

Q6：Gateway 过滤器的执行顺序？

答：同 order 时：Default > Route > Global。order 越小越先执行。

第十章：本章小结

✅ 你已经掌握

  • 微服务 vs 单体架构
  • Nacos 注册中心（服务注册与发现）
  • Ribbon 负载均衡策略（NacosRule）
  • 服务分级 + 同集群优先
  • Feign 远程调用（声明式，像调本地方法）
  • Feign 日志 + 连接池优化
  • Nacos 配置中心（bootstrap.yaml）
  • 配置热更新（@ConfigurationProperties 推荐）
  • Gateway 路由 + 断言 + 过滤器
  • Gateway 全局过滤器（认证）
  • 跨域 CORS 配置

⚠ 新手易踩的坑

  1. @PathVariable 必须写参数名：@PathVariable("id")
  2. Nacos 配置要放在 bootstrap.yaml，不是 application.yaml
  3. Gateway 的 uri: lb:// 后面是服务名，不是 IP
  4. 不同 Namespace 的服务无法互相调用
  5. @RefreshScope 加在类上，不是方法上

💡 学习建议： SpringCloud 章节内容较多，建议分三天学：

  • Day 1：Nacos 注册中心 + RestTemplate
  • Day 2：Feign + Nacos 配置中心
  • Day 3：Gateway 网关

每学完一块就动手搭一个 demo 跑通，比看 10 遍笔记效果好。
