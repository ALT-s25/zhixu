第一章：为什么要用 Elasticsearch

1.1 MySQL 搜索的问题

场景：电商网站搜索商品"小米手机"。

用 MySQL：

sql
SELECT * FROM product
WHERE name LIKE '%小米手机%'
  OR description LIKE '%小米手机%'

问题：

  1. 速度慢：LIKE '%...%' 无法使用索引，全表扫描，百万数据要几秒
  2. 不智能：搜"小米手机"找不到"手机 小米 新款"（词序不同）
  3. 不能按相关度排序：关键词出现 10 次的和出现 1 次的结果一样

Elasticsearch 解决：

  1. 速度快：基于倒排索引，O(1) 查找
  2. 智能分词：先分词再搜，"小米手机" = ["小米", "手机"]
  3. 相关度排序：关键词出现越多、位置越重要，排名越靠前

1.2 倒排索引（ES 的灵魂）⭐⭐

正向索引（MySQL）：

  • 结构：文档 → 包含的词
  • 查询：遍历所有文档，看哪个包含关键词
text
文档1: "小米手机发布新品"
文档2: "苹果手机降价"
文档3: "小米电视新款"

搜"手机"，要扫描所有文档，O(N)。

倒排索引（ES）：

  • 结构：词 → 包含该词的文档列表
  • 查询：直接查词，O(1)
text
词         文档列表
"小米"  → [文档1, 文档3]
"手机"  → [文档1, 文档2]
"苹果"  → [文档2]
"电视"  → [文档3]
"新品"  → [文档1]

搜"手机"→ 直接找"手机"这个词 → 返回[文档1, 文档2]。

搜"小米手机"的流程：

  1. 分词：["小米", "手机"]
  2. 查"小米"→ [文档1, 文档3]
  3. 查"手机"→ [文档1, 文档2]
  4. 求交集 → [文档1]（包含两个词）
  5. 或者并集，按相关度排序

1.3 ES vs MySQL

MySQL Elasticsearch
Table（表） Index（索引库）
Row（行） Document（文档），JSON 格式
Column（列） Field（字段）
Schema（约束） Mapping（映射）
SQL DSL（JSON 查询语言）

💡 两者不是竞争，而是互补！MySQL 存全量数据（持久可靠），ES 存搜索数据（查询快）。

第二章：索引库操作（mapping 映射）⭐⭐

2.1 mapping 是什么

类比：MySQL 建表前要定义表结构（字段名、字段类型）。 ES 也需要定义"索引库结构"，这就是 mapping。

2.2 常见字段类型

类型 说明 适合
text 可分词文本，参与全文搜索 商品名称、描述
keyword 不分词，精确匹配 品牌、ID、状态
long / integer / short / byte 整数 价格、库存
float / double 浮点 评分、金额
boolean 布尔 是否上架
date 日期 创建时间
geo_point 地理坐标（经纬度） 位置信息
object 嵌套对象 用户地址

重要区别：

  • text：会被分词，然后建倒排索引，支持全文搜索
  • keyword：不分词，存原始值，支持精确查询（term 查询）

⚠ 新手易错：用 term（精确查询）查 text 类型字段，查不到！因为 text 存的是分词后的内容，不是原文。

2.3 创建索引库

在 Kibana 的 Dev Tools 里执行（或用 Postman）：

json
PUT /hotel
{
  "mappings": {
    "properties": {
      "id": {
        "type": "keyword"       // 酒店 ID，精确匹配
      },
      "name": {
        "type": "text",          // 酒店名，参与全文搜索
        "analyzer": "ik_max_word",   // 写入时分词器（细粒度）
        "copy_to": "all"             // 同时复制到 all 字段
      },
      "address": {
        "type": "keyword",       // 地址，精确匹配
        "index": false           // 不建索引，不参与搜索
      },
      "price": {
        "type": "integer"        // 价格
      },
      "score": {
        "type": "integer"        // 评分
      },
      "brand": {
        "type": "keyword"        // 品牌，精确匹配
      },
      "city": {
        "type": "keyword"        // 城市
      },
      "starName": {
        "type": "keyword"        // 星级
      },
      "business": {
        "type": "keyword"        // 商圈
      },
      "location": {
        "type": "geo_point"      // 地理坐标（经纬度）
      },
      "pic": {
        "type": "keyword",       // 图片 URL
        "index": false           // 不建索引
      },
      "all": {
        "type": "text",          // 组合字段，把名称、商圈等放一起，方便全文搜索
        "analyzer": "ik_max_word"
      }
    }
  }
}

关键配置解析：

  • analyzer: ik_max_word：用 IK 分词器，细粒度分词（"小米手机" → "小米", "手机", "小米手机"）
  • copy_to: all：把这个字段的值复制到 all 字段，all 字段统一搜索，提高性能
  • index: false：不建倒排索引，存储但不搜索（节省空间）

2.4 索引库 CRUD

json
// 查看索引库
GET /hotel

// 修改（只能添加字段，不能修改已有字段！）
PUT /hotel/_mapping
{
  "properties": {
    "新字段": { "type": "keyword" }
  }
}

// 删除索引库（慎用！数据全没）
DELETE /hotel

⚠ 重要：ES 的 mapping 一旦定义不能修改！只能追加新字段。 要修改字段，只能：1. 新建索引库 2. 数据迁移 3. 切换索引别名。

第四章：DSL 查询（核心）⭐⭐⭐

4.1 查询语法结构

json
GET /hotel/_search
{
  "query": {       // 查询条件
    ...
  },
  "from": 0,       // 分页：从第几条开始
  "size": 20,      // 每页几条
  "sort": [ ... ], // 排序规则
  "highlight": {   // 高亮配置
    ...
  }
}

查询结果结构：

json
{
  "hits": {
    "total": { "value": 100 },   // 总数
    "hits": [                      // 命中的文档列表
      {
        "_id": "1",
        "_score": 1.5,             // 相关性得分
        "_source": { ... }          // 文档原始内容
      }
    ]
  }
}

4.2 全文检索查询（match）⭐⭐⭐

match 查询：先分词，然后查。

json
// 搜索 name 中包含 "如家" 的酒店
GET /hotel/_search
{
  "query": {
    "match": {
      "name": "如家酒店"
      // 分词后：["如家", "酒店"]
      // 匹配 name 中含有 "如家" OR "酒店" 的文档
    }
  }
}

multi_match 查询：在多个字段中搜索。

json
GET /hotel/_search
{
  "query": {
    "multi_match": {
      "query": "如家",
      "fields": ["name", "business"]    // 在 name 和 business 中搜
    }
  }
}

💡 建议：用 copy_to 把多个字段合并到 all 字段，然后只搜 all，性能比 multi_match 好。

json
// 搜 all 字段（推荐）
{
  "query": {
    "match": { "all": "如家" }
  }
}

4.3 精确查询（term / range）⭐⭐

term 查询：精确匹配（不分词，用于 keyword 类型）。

json
// 查询城市是上海的酒店
{
  "query": {
    "term": {
      "city": "上海"    // 精确匹配，不分词
    }
  }
}

range 查询：范围查询。

json
// 查询价格在 100~300 之间的酒店
{
  "query": {
    "range": {
      "price": {
        "gte": 100,    // greater than or equal（大于等于）
        "lte": 300     // less than or equal（小于等于）
      }
    }
  }
}

⚠ 新手易错：text 类型不能用 term 精确查询！ text 字段存的是分词后的内容，原文不完整。 精确查询必须用 keyword 类型。

4.4 地理查询

附近商家（geo_distance）：

json
// 查找距离指定坐标 5km 内的酒店
{
  "query": {
    "geo_distance": {
      "distance": "5km",
      "location": "31.2047, 121.4489"   // 中心坐标（纬度,经度）
    }
  }
}

4.5 复合查询（bool）⭐⭐⭐（最重要）

bool 查询：组合多个查询条件。

json
{
  "query": {
    "bool": {
      "must": [                           // 必须满足（参与算分）
        { "match": { "all": "如家" } }
      ],
      "should": [                         // 满足则加分（非必须）
        { "term": { "brand": "如家" } }
      ],
      "must_not": [                       // 必须不满足（过滤，不算分）
        { "range": { "price": { "gt": 500 } } }
      ],
      "filter": [                         // 必须满足（过滤，不算分，性能好）
        { "range": { "score": { "gte": 45 } } }
      ]
    }
  }
}

四个子句的区别：

子句 是否必须满足 是否参与算分 用途
must ✅ 必须 ✅ 参与 核心搜索条件
should ❌ 可选 ✅ 参与 加分条件
must_not ✅ 必须不满足 ❌ 不参与 排除条件
filter ✅ 必须满足 ❌ 不参与 过滤条件（性能最好）

💡 建议：

  • 搜索关键词用 must（参与算分）
  • 筛选条件用 filter（不算分，性能好）
  • 价格、城市这类过滤用 filter，不用 must

实战例子：搜索"酒店"，过滤城市为"上海"，价格 100-300，评分 45 分以上：

json
{
  "query": {
    "bool": {
      "must": [
        { "match": { "all": "酒店" } }    // 搜关键词，参与算分
      ],
      "filter": [
        { "term": { "city": "上海" } },   // 过滤城市，不算分
        { "range": {
          "price": { "gte": 100, "lte": 300 }  // 过滤价格
        }},
        { "range": {
          "score": { "gte": 45 }               // 过滤评分
        }}
      ]
    }
  }
}

4.6 算分函数查询（function_score）⭐

应用：广告位的酒店，让它排在前面。

json
{
  "query": {
    "function_score": {
      "query": {               // 基础查询
        "match": { "all": "外滩" }
      },
      "functions": [
        {
          "filter": {          // 满足这个条件的...
            "term": { "brand": "如家" }
          },
          "weight": 10         // ...分数 × 10
        }
      ],
      "boost_mode": "multiply"   // 原始分 × weight
    }
  }
}

第五章：搜索结果处理

5.1 排序

json
// 按评分降序（默认是相关性得分，这里改成按字段排序）
{
  "sort": [
    { "score": { "order": "desc" } },    // 评分降序
    { "price": { "order": "asc" } }       // 价格升序（评分相同时按价格）
  ]
}

// 按距离排序（附近优先）
{
  "sort": [
    {
      "_geo_distance": {
        "location": "31.2047, 121.4489",   // 我的位置
        "order": "asc",
        "unit": "km"
      }
    }
  ]
}

5.2 分页

json
{
  "from": 0,    // 从第几条开始（0 = 第一页）
  "size": 20    // 每页 20 条
}

// 第 2 页：from=20, size=20
// 第 3 页：from=40, size=20

⚠ 深度分页问题： from + size > 10000 时性能急剧下降（ES 默认限制 10000）。 大数据量的分页用 search_after：

json
{
  "search_after": ["上次最后一条的sort值"],
  "size": 20,
  "sort": [{"score": "desc"}, {"id": "asc"}]
}

5.3 高亮

原理：把搜索关键词在结果中用 HTML 标签标注（前端显示时渲染为高亮色）。

json
{
  "query": { "match": { "all": "如家" } },
  "highlight": {
    "fields": {
      "name": {
        "pre_tags": "<em>",         // 高亮前标签
        "post_tags": "</em>",        // 高亮后标签
        "require_field_match": false  // 允许不同字段高亮
      }
    }
  }
}

返回结果：

json
{
  "_source": { "name": "上海如家酒店" },
  "highlight": {
    "name": ["上海<em>如家</em>酒店"]   // 高亮后的名称
  }
}

前端用高亮名称替换原名称即可显示红色关键词。

6.2 文档 CRUD

java
@Autowired
private RestHighLevelClient client;

// 新增/修改文档
public void addDocument(Hotel hotel) throws IOException {
    // 1. 创建 Request（指定索引库和文档 ID）
    IndexRequest request = new IndexRequest("hotel").id(hotel.getId().toString());

    // 2. 设置文档内容（JSON 字符串）
    HotelDoc hotelDoc = new HotelDoc(hotel);
    request.source(JSON.toJSONString(hotelDoc), XContentType.JSON);

    // 3. 发送请求
    client.index(request, RequestOptions.DEFAULT);
}

// 查询文档
public HotelDoc getDocumentById(Long id) throws IOException {
    // 1. 创建 Request
    GetRequest request = new GetRequest("hotel", id.toString());

    // 2. 发送请求
    GetResponse response = client.get(request, RequestOptions.DEFAULT);

    // 3. 解析结果
    String json = response.getSourceAsString();
    return JSON.parseObject(json, HotelDoc.class);
}

// 删除文档
public void deleteDocument(Long id) throws IOException {
    DeleteRequest request = new DeleteRequest("hotel", id.toString());
    client.delete(request, RequestOptions.DEFAULT);
}

// 批量新增（导入数据用）
public void bulkAddDocuments(List<Hotel> hotels) throws IOException {
    // 1. 创建批量 Request
    BulkRequest request = new BulkRequest();

    // 2. 添加每条数据
    for (Hotel hotel : hotels) {
        HotelDoc hotelDoc = new HotelDoc(hotel);
        request.add(new IndexRequest("hotel")
            .id(hotel.getId().toString())
            .source(JSON.toJSONString(hotelDoc), XContentType.JSON));
    }

    // 3. 发送批量请求
    client.bulk(request, RequestOptions.DEFAULT);
}

6.3 搜索文档 ⭐⭐⭐

java
// 完整搜索示例（含 bool 查询、分页、高亮）
public PageResult search(RequestParams params) throws IOException {
    // 1. 创建 SearchRequest
    SearchRequest request = new SearchRequest("hotel");

    // 2. 构建查询条件
    BoolQueryBuilder boolQuery = QueryBuilders.boolQuery();

    // 2.1 关键词搜索
    if (StrUtil.isNotBlank(params.getKey())) {
        boolQuery.must(QueryBuilders.matchQuery("all", params.getKey()));
    } else {
        boolQuery.must(QueryBuilders.matchAllQuery());   // 无关键词，查全部
    }

    // 2.2 过滤条件
    if (StrUtil.isNotBlank(params.getCity())) {
        boolQuery.filter(QueryBuilders.termQuery("city", params.getCity()));
    }
    if (StrUtil.isNotBlank(params.getBrand())) {
        boolQuery.filter(QueryBuilders.termQuery("brand", params.getBrand()));
    }
    if (params.getMinPrice() != null && params.getMaxPrice() != null) {
        boolQuery.filter(QueryBuilders.rangeQuery("price")
            .gte(params.getMinPrice())
            .lte(params.getMaxPrice()));
    }

    // 2.3 算分函数（广告）
    FunctionScoreQueryBuilder functionScoreQuery = QueryBuilders.functionScoreQuery(
        boolQuery,
        new FunctionScoreQueryBuilder.FilterFunctionBuilder[]{
            new FunctionScoreQueryBuilder.FilterFunctionBuilder(
                QueryBuilders.termQuery("isAD", true),
                ScoreFunctionBuilders.weightFactorFunction(10)  // 广告 ×10
            )
        }
    );
    request.source().query(functionScoreQuery);

    // 3. 分页
    int page = params.getPage();
    int size = params.getSize();
    request.source().from((page - 1) * size).size(size);

    // 4. 高亮
    request.source().highlighter(
        new HighlightBuilder()
            .field("name")
            .requireFieldMatch(false)
    );

    // 5. 执行查询
    SearchResponse response = client.search(request, RequestOptions.DEFAULT);

    // 6. 解析结果
    return handleResponse(response);
}

// 解析响应
private PageResult handleResponse(SearchResponse response) {
    SearchHits searchHits = response.getHits();

    // 总数
    long total = searchHits.getTotalHits().value;

    // 文档列表
    List<HotelDoc> hotels = new ArrayList<>();
    for (SearchHit hit : searchHits.getHits()) {
        // 解析 JSON
        HotelDoc hotelDoc = JSON.parseObject(hit.getSourceAsString(), HotelDoc.class);

        // 处理高亮
        Map<String, HighlightField> highlights = hit.getHighlightFields();
        if (highlights.containsKey("name")) {
            // 用高亮名称替换原名称
            String highlightName = highlights.get("name").getFragments()[0].string();
            hotelDoc.setName(highlightName);
        }

        hotels.add(hotelDoc);
    }

    return new PageResult(total, hotels);
}

6.4 聚合查询

java
// 获取所有品牌列表（Bucket 聚合）
public List<String> getBrands() throws IOException {
    SearchRequest request = new SearchRequest("hotel");

    // 1. 不返回文档（只要聚合结果）
    request.source().size(0);

    // 2. 添加聚合
    request.source().aggregation(
        AggregationBuilders.terms("brandAgg")    // 按品牌分组
            .field("brand")
            .size(100)
    );

    // 3. 执行
    SearchResponse response = client.search(request, RequestOptions.DEFAULT);

    // 4. 解析聚合结果
    Terms brandTerms = response.getAggregations().get("brandAgg");
    return brandTerms.getBuckets()
        .stream()
        .map(Terms.Bucket::getKeyAsString)
        .collect(Collectors.toList());
}

第七章：数据同步（MySQL → ES）⭐⭐

7.1 为什么需要同步

问题：MySQL 是数据源，ES 是搜索数据。MySQL 数据变了，ES 要同步更新。

三种方案：

方案 原理 耦合 实时性 复杂度
同步调用 修改 MySQL 后直接调 ES API 高 强 低
异步通知 修改 MySQL 发 MQ，ES 消费 中 较强 中
监听 binlog Canal 监听 MySQL binlog 推 ES 低 较弱 高

推荐：中等规模用异步通知（解耦，不复杂）；大规模用 Canal + binlog。

7.2 异步通知方案实现

java
// 酒店服务：数据变动时发 MQ
@Service
public class HotelService {

    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void saveHotel(Hotel hotel) {
        // 1. 保存到 MySQL
        save(hotel);

        // 2. 发消息（通知 ES 同步）
        rabbitTemplate.convertAndSend("hotel.topic", "hotel.insert", hotel.getId());
    }

    public void deleteHotel(Long id) {
        removeById(id);
        rabbitTemplate.convertAndSend("hotel.topic", "hotel.delete", id);
    }
}

// ES 服务（搜索服务）：监听消息，同步 ES
@Component
public class HotelListener {

    @Autowired
    private HotelService hotelService;   // ES 操作服务

    // 新增/修改
    @RabbitListener(bindings = @QueueBinding(
        value = @Queue("hotel.insert.queue"),
        exchange = @Exchange("hotel.topic"),
        key = "hotel.insert"
    ))
    public void onHotelInsert(Long hotelId) {
        // 从酒店服务查数据，然后写入 ES
        hotelService.syncHotelToEs(hotelId);
    }

    // 删除
    @RabbitListener(bindings = @QueueBinding(
        value = @Queue("hotel.delete.queue"),
        exchange = @Exchange("hotel.topic"),
        key = "hotel.delete"
    ))
    public void onHotelDelete(Long hotelId) {
        hotelService.deleteHotelFromEs(hotelId);
    }
}

第八章：常见报错与解决

报错 1：term 查询查不到数据

text
原因：查询的字段是 text 类型（已被分词），用 term 精确查询查不到
解决：
1. 改用 match 查询
2. 或者把字段类型改为 keyword

报错 2：Fielddata is disabled on text fields by default

text
原因：在 text 类型字段上做聚合或排序
解决：
1. 在 mapping 中启用 fielddata（不推荐，占内存）
2. 或者在字段里加 keyword 子字段：
   "name": {
     "type": "text",
     "fields": {
       "keyword": {"type": "keyword"}
     }
   }
   然后对 name.keyword 做聚合

报错 3：Result window is too large

text
原因：from + size 超过 10000
解决：
1. 修改 max_result_window 设置（不推荐，消耗内存）
2. 改用 search_after 实现深度分页

报错 4：mapping 修改报错

text
原因：已存在的字段不能修改类型
解决：
1. 只能追加新字段
2. 要修改只能重新创建索引 + 数据迁移

第九章：面试常问（附答案）

Q1：ES 为什么搜索快？

答：倒排索引。把词条 → 文档的关系预先建好，查询时直接找词条，O(1)。而 MySQL 的 LIKE 要全表扫描，O(N)。

Q2：ES 和 MySQL 的区别？

答：

  • MySQL 存全量数据，事务可靠，适合复杂关联查询
  • ES 基于倒排索引，适合全文搜索和聚合分析
  • 两者互补：MySQL 是数据源，ES 是搜索加速层

Q3：text 和 keyword 的区别？

答：

  • text：写入时分词，参与全文搜索
  • keyword：不分词，原始值存储，用于精确匹配、排序、聚合

Q4：bool 查询的 must 和 filter 的区别？

答：

  • must：参与相关性算分（影响排序），性能略差
  • filter：不算分，只过滤，有缓存，性能更好

Q5：ES 如何实现分页？

答：

  • 普通分页：from + size，但超过 10000 性能急剧下降
  • 深度分页：用 search_after（游标分页），性能好
  • 滚动分页：用 scroll（适合批量导出数据）

Q6：ES 如何保证和 MySQL 数据一致？

答：三种方案：

  1. 同步调用（简单，但耦合高）
  2. 异步通知（MQ + 解耦，推荐中等规模）
  3. 监听 binlog（Canal，适合大规模，完全解耦）

第十章：本章小结

✅ 你已经掌握

  • 倒排索引原理（ES 为什么快）
  • ES vs MySQL 对比
  • mapping 映射（text/keyword 区别）
  • 文档 CRUD（增删改查）
  • DSL 查询（match / term / range / bool）
  • bool 查询（must / should / filter / must_not）
  • 排序、分页、高亮
  • 聚合查询（Bucket / Metric）
  • Java RestClient 完整搜索实现
  • MySQL → ES 数据同步（三种方案）

⚠ 新手易踩的坑

  1. text 类型不能用 term 精确查询
  2. mapping 字段类型一旦定义，不能修改，只能追加
  3. filter 不参与算分，性能优于 must（过滤条件优先用 filter）
  4. 深度分页 from+size > 10000 性能急剧下降
  5. 高亮结果要用 hit 里的 highlight 字段替换 _source 里的原字段

💡 学习建议： Elasticsearch 学习分三步：

  1. 先在 Kibana Dev Tools 里用 DSL 语言练各种查询（2天）
  2. 再用 Java RestClient 把 DSL 翻译成代码（1天）
  3. 最后做完整项目（搜索 + 高亮 + 聚合筛选）（1天）

DSL 和 Java 代码是对应关系，DSL 学会了，Java 代码只是翻译而已。
