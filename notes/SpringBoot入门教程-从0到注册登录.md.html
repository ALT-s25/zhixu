# Spring Boot 入门教程 —— 从 0 到独立写注册登录

> 目标：看完这篇，你能自己用 Spring Boot + MySQL 写一个用户注册登录接口。
> 原则：不讲原理，只讲怎么用。每个知识点都有代码，跟着敲一遍就会。

---

## 一、Spring Boot 是什么？为什么用它？

### 一句话解释

**Spring Boot 是一个「快速搭建 Java Web 项目」的工具。** 你不用自己配置一堆 XML，不用自己导一堆 jar 包，它帮你都做好了，你只需要写业务代码。

### 通俗理解

想象你要开一家奶茶店：
- **没有 Spring Boot**：你要自己装修、自己买设备、自己办营业执照、自己接水电…… 开店前要忙一个月。
- **有了 Spring Boot**：给你一个精装商铺，设备都装好了，营业执照也代办了，你直接进去做奶茶卖就行。

### 它解决了什么问题

| 痛点 | Spring Boot 的解决方案 |
|---|---|
| 导包麻烦，版本冲突 | 起步依赖（starter），一个依赖搞定一整套 |
| 配置文件一大堆 XML | 自动配置，默认就帮你配好了 |
| 部署要装 Tomcat | 内置 Tomcat，直接 `java -jar` 运行 |
| 项目结构混乱 | 约定大于配置，大家都用一样的结构 |

### 你现在要知道的就这些

不用管 IOC、AOP、Bean 这些概念，**先会用，后面再理解**。

### 3.3 认识启动类

打开 `HelloDemoApplication.java`，你会看到：

```java
package com.example.hellodemo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication   // ← 这个注解标记这是一个 Spring Boot 启动类
public class HelloDemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(HelloDemoApplication.class, args);  // ← 启动项目
    }
}
```

**就这两行核心代码**，你不用管它内部干了什么，知道「运行 main 方法 = 启动项目」就行。

### 3.4 写第一个接口

在 `com.example.hellodemo` 包下新建一个包叫 `controller`，然后在里面新建一个类 `HelloController.java`：

```java
package com.example.hellodemo.controller;

import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController          // ← 标记这是一个控制器，里面的方法返回的数据直接给客户端
@RequestMapping("/hello") // ← 这个类里所有接口的路径前缀都是 /hello
public class HelloController {

    @RequestMapping("/world")  // ← 这个方法的路径是 /hello/world
    public String hello() {
        return "Hello World!";  // ← 返回给客户端的内容
    }
}
```

1. 打开 `HelloDemoApplication.java`，点 main 方法左边的绿色三角，选「Run」
2. 看控制台输出，看到类似下面的内容就说明启动成功了：
   ```

   Started HelloDemoApplication in 2.345 seconds
   ```
   注意：**默认端口是 8080**。

3. 打开 Postman（或浏览器），访问：
   ```
   GET http://localhost:8080/hello/world
   ```
4. 你会看到返回：`Hello World!`

🎉 **恭喜，你的第一个 Spring Boot 接口跑通了！**

### 3.6 刚才发生了什么？（简单理解）

```
你在浏览器输入 http://localhost:8080/hello/world
    ↓
请求到达 Spring Boot 内置的 Tomcat（端口8080）
    ↓
Tomcat 把请求交给 Spring MVC 处理
    ↓
Spring MVC 看路径 /hello/world，找到 HelloController 的 hello() 方法
    ↓
执行 hello() 方法，返回 "Hello World!"
    ↓
Spring MVC 把返回值转成字符串，通过 HTTP 响应发给浏览器
    ↓
你看到 Hello World!
```

不用深究，知道「请求路径 → 对应方法 → 返回结果」这个流程就行。

## 四、@RestController 和 @RequestMapping 详解

### 4.1 @RestController 是什么

**作用**：标记这个类是一个「控制器」，里面的方法返回值会直接作为 HTTP 响应体返回给客户端。

**拆解**：`@RestController` = `@Controller` + `@ResponseBody`
- `@Controller`：标记这是一个控制器（Spring 会扫描它）
- `@ResponseBody`：方法返回值直接写进 HTTP 响应体，而不是跳转到某个页面

**你只需要记住**：写接口的类，上面加 `@RestController` 就对了。

### 4.2 @RequestMapping 是什么

**作用**：定义请求路径和方法的映射关系。就是说「哪个 URL 对应哪个方法」。

**可以用在类上，也可以用在方法上**：
- 用在类上：定义这个类所有接口的**公共前缀**
- 用在方法上：定义这个方法的**具体路径**

**完整路径 = 类上的路径 + 方法上的路径**

### 4.3 指定 HTTP 方法

@RequestMapping 默认接受所有 HTTP 方法（GET、POST、PUT、DELETE 都能访问）。但实际开发中，我们一般会指定方法：

```java
@RestController
@RequestMapping("/user")
public class UserController {

    // 只接受 GET 请求
    @RequestMapping(value = "/info", method = RequestMethod.GET)
    public String getInfo() {
        return "用户信息";
    }

    // 只接受 POST 请求
    @RequestMapping(value = "/add", method = RequestMethod.POST)
    public String addUser() {
        return "添加用户";
    }
}
```

**更简洁的写法（推荐）**：Spring 提供了组合注解，直接用：

| 注解 | 等价于 | 用途 |
|---|---|---|
| `@GetMapping` | `@RequestMapping(method=GET)` | 查询数据 |
| `@PostMapping` | `@RequestMapping(method=POST)` | 新增数据 |
| `@PutMapping` | `@RequestMapping(method=PUT)` | 修改数据 |
| `@DeleteMapping` | `@RequestMapping(method=DELETE)` | 删除数据 |

**实际项目中都用这些组合注解**，上面的代码可以改成：

```java
@RestController
@RequestMapping("/user")
public class UserController {

    @GetMapping("/info")    // GET /user/info
    public String getInfo() {
        return "用户信息";
    }

    @PostMapping("/add")    // POST /user/add
    public String addUser() {
        return "添加用户";
    }
}
```

```java
public class HelloController {
```

## 五、参数绑定（重点）

接口不能只返回固定字符串，还要能**接收客户端传过来的数据**。Spring Boot 提供了多种参数绑定方式。

### 5.1 @RequestParam：接收 URL 后面的参数（Query 参数）

**适用场景**：参数放在 URL 后面，用 `?` 连接，多个参数用 `&` 分隔。
例如：`http://localhost:8080/user/search?name=张三&age=20`

**代码示例**：

```java
@RestController
@RequestMapping("/user")
public class UserController {

    // 访问：GET /user/search?name=张三&age=20
    @GetMapping("/search")
    public String searchUser(
            @RequestParam("name") String name,   // 接收 name 参数
            @RequestParam("age") Integer age      // 接收 age 参数
    ) {
        return "搜索用户：" + name + "，年龄：" + age;
    }
}
```

**Postman 测试**：
- 方法选 GET
- URL 填 `http://localhost:8080/user/search`
- Params 里加两行：key=name value=张三；key=age value=20
- 点 Send

**@RequestParam 的常用属性**：

```java
// required = false：参数可以不传，不传时为 null
@RequestParam(value = "name", required = false) String name

// defaultValue = "未知"：参数不传时，默认值为 "未知"
@RequestParam(value = "name", defaultValue = "未知") String name
```

**什么时候用 @RequestParam**：
- GET 请求的查询参数
- 参数比较少（1-3 个）
- 参数是简单类型（String、Integer 等）

### 5.2 @PathVariable：接收 URL 路径里的参数

**适用场景**：参数是 URL 路径的一部分，用 `{}` 占位。
例如：`http://localhost:8080/user/123`（123 是用户 ID）

**代码示例**：

```java
@RestController
@RequestMapping("/user")
public class UserController {

    // 访问：GET /user/123
    // {id} 是占位符，实际访问时 123 会传给 id 参数
    @GetMapping("/{id}")
    public String getUserById(@PathVariable("id") Long id) {
        return "查询用户 ID：" + id;
    }

    // 可以有多个路径参数
    // 访问：GET /user/123/order/456
    @GetMapping("/{userId}/order/{orderId}")
    public String getUserOrder(
            @PathVariable("userId") Long userId,
            @PathVariable("orderId") Long orderId
    ) {
        return "用户" + userId + "的订单" + orderId;
    }
}
```

**Postman 测试**：
- `GET http://localhost:8080/user/123`
- `GET http://localhost:8080/user/123/order/456`

**什么时候用 @PathVariable**：
- 参数是资源的唯一标识（ID、编号等）
- RESTful 风格的接口

### 5.3 @RequestBody：接收 JSON 请求体（最重要！）

**适用场景**：客户端通过 POST/PUT 请求，在请求体（Body）里传 JSON 数据。
这是**实际开发中最常用的方式**，尤其是提交表单、新增数据时。

**第一步：先建一个实体类（DTO）**

在 `com.example.hellodemo` 下新建包 `dto`，然后建 `UserDTO.java`：

```java
package com.example.hellodemo.dto;

// 这个类用来接收客户端传过来的 JSON 数据
// 字段名要和 JSON 的 key 一致
public class UserDTO {
    private String username;  // 用户名
    private String password;  // 密码
    private String phone;     // 手机号
    private Integer age;      // 年龄

    // getter 和 setter（后面用 Lombok 可以省掉，现在先手写）
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }
    public String getPhone() { return phone; }
    public void setPhone(String phone) { this.phone = phone; }
    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }

    // toString 方便打印看
    @Override
    public String toString() {
        return "UserDTO{username='" + username + "', password='" + password + 
               "', phone='" + phone + "', age=" + age + "}";
    }
}
```

**第二步：写接口接收 JSON**

```java
@RestController
@RequestMapping("/user")
public class UserController {

    // 接收 JSON 请求体
    // @RequestBody 会把请求体里的 JSON 自动转换成 UserDTO 对象
    @PostMapping("/register")
    public String register(@RequestBody UserDTO userDTO) {
        System.out.println("收到注册请求：" + userDTO);
        return "注册成功：" + userDTO.getUsername();
    }
}
```

**Postman 测试**：
1. 方法选 POST
2. URL 填 `http://localhost:8080/user/register`
3. 选 Body → raw → 下拉选 JSON
4. 输入 JSON：
   ```json
   {
       "username": "zhangsan",
       "password": "123456",
       "phone": "13800138000",
       "age": 20
   }
   ```
5. 点 Send

**你会看到**：
- Postman 返回：`注册成功：zhangsan`
- IDEA 控制台打印：`收到注册请求：UserDTO{username='zhangsan', ...}`

**原理（简单理解）**：
```
客户端发 JSON 请求体
    ↓
@RequestBody 注解告诉 Spring：把请求体里的 JSON 拿出来
    ↓
Spring 用 Jackson（内置的 JSON 库）把 JSON 转成 Java 对象
    ↓
字段名一一对应：username → username，password → password
    ↓
你得到一个填充好的 UserDTO 对象，直接用就行
```

**注意事项**：
- JSON 的 key 必须和 Java 类的字段名一致（大小写也要一致）
- 如果字段名不一致，可以用 `@JsonProperty("json里的key")` 注解
- `@RequestBody` 只能用在 POST/PUT 请求上（GET 请求没有请求体）

### 5.4 三种参数绑定方式对比

| 方式 | 位置 | 适用场景 | 示例 URL |
|---|---|---|---|
| `@RequestParam` | URL 后面 `?key=value` | GET 查询、少量参数 | `/user/search?name=张三` |
| `@PathVariable` | URL 路径里 `{id}` | RESTful、资源 ID | `/user/123` |
| `@RequestBody` | 请求体 Body 里的 JSON | POST/PUT 提交复杂数据 | （JSON 在 Body 里） |

### 5.5 动手练习

写一个接口，同时用三种参数绑定方式：

```java
@PostMapping("/test/{type}")
public String testParams(
        @PathVariable("type") String type,           // 路径参数
        @RequestParam(value = "page", defaultValue = "1") Integer page,  // Query参数
        @RequestBody UserDTO userDTO                   // JSON请求体
) {
    return "类型：" + type + "，页码：" + page + "，用户：" + userDTO.getUsername();
}
```

Postman 测试：
- URL：`POST http://localhost:8080/user/test/mobile?page=2`
- Body JSON：`{"username":"lisi","password":"666666"}`

## 六、分层结构（Controller → Service → Mapper）

### 6.1 为什么要分层？

如果所有代码都写在 Controller 里，会怎么样？
- 一个方法几百行，又接收参数、又校验、又操作数据库、又处理异常
- 想改数据库操作，要在一大堆业务代码里找
- 想复用一段逻辑，只能复制粘贴

**分层的目的：各司其职，代码清晰，方便维护和复用。**

### 6.2 三层分别干什么

| 层 | 职责 | 类比 |
|---|---|---|
| **Controller（控制层）** | 接收请求、参数校验、调用 Service、返回结果 | 餐厅服务员：接单、把单子给后厨、把菜端给客人 |
| **Service（业务层）** | 核心业务逻辑、事务控制、调用 Mapper | 后厨厨师：做菜（核心业务）、需要什么食材找仓库要 |
| **Mapper（数据访问层）** | 操作数据库（增删改查） | 仓库管理员：管食材（数据），厨师要什么给什么 |

**调用关系**：
```
客户端 → Controller → Service → Mapper → MySQL
         （接收）    （业务）   （数据库）
```

**返回关系**：
```
MySQL → Mapper → Service → Controller → 客户端
       （数据）  （处理）  （封装）   （响应）
```

### 6.3 项目包结构

在 `com.example.hellodemo` 下建这些包：

```
com.example.hellodemo/
├── HelloDemoApplication.java    启动类
├── controller/                   控制层（接口）
│   └── UserController.java
├── service/                      业务层接口
│   └── UserService.java
├── service/impl/                 业务层实现
│   └── UserServiceImpl.java
├── mapper/                       数据访问层
│   └── UserMapper.java
├── model/                        实体类（对应数据库表）
│   └── User.java
├── dto/                          数据传输对象（接收/返回给前端的对象）
```

### 6.4 各层代码示例

**Model（实体类，对应数据库表）**：

```java
// model/User.java
package com.example.hellodemo.model;

public class User {
    private Long id;          // 用户ID
    private String username;  // 用户名
    private String password;  // 密码
    private String phone;     // 手机号
    private Integer age;      // 年龄

    // getter/setter 省略（后面用 Lombok）
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }
    public String getPhone() { return phone; }
    public void setPhone(String phone) { this.phone = phone; }
    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }
}
```

**Mapper（数据访问层，操作数据库）**：

现在先不用连数据库，用假数据模拟：

```java
// mapper/UserMapper.java
package com.example.hellodemo.mapper;

import com.example.hellodemo.model.User;
import org.springframework.stereotype.Repository;

import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.ConcurrentHashMap;

@Repository  // 标记这是数据访问层，Spring 会管理它
public class UserMapper {

    // 用 Map 模拟数据库，key=id，value=用户
    private final ConcurrentHashMap<Long, User> db = new ConcurrentHashMap<>();
    private long idCounter = 1;

    // 新增用户
    public int insert(User user) {
        user.setId(idCounter++);
        db.put(user.getId(), user);
        return 1; // 影响行数
    }

    // 根据用户名查询
    public User selectByUsername(String username) {
        for (User user : db.values()) {
            if (user.getUsername().equals(username)) {
                return user;
            }
        }
        return null;
    }

    // 根据ID查询
    public User selectById(Long id) {
        return db.get(id);
    }

    // 查询所有
    public List<User> selectAll() {
        return new ArrayList<>(db.values());
    }
}
```

**Service（业务层接口）**：

```java
// service/UserService.java
package com.example.hellodemo.service;

import com.example.hellodemo.model.User;
import java.util.List;

// 业务接口：定义有哪些业务功能
public interface UserService {

    // 注册
    void register(String username, String password, String phone, Integer age);

    // 登录
    User login(String username, String password);

    // 根据ID查询
    User getById(Long id);

    // 查询所有
    List<User> getAll();
}
```

**ServiceImpl（业务层实现）**：

```java
// service/impl/UserServiceImpl.java
package com.example.hellodemo.service.impl;

import com.example.hellodemo.mapper.UserMapper;
import com.example.hellodemo.model.User;
import com.example.hellodemo.service.UserService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.List;

@Service  // 标记这是业务层实现，Spring 会管理它
public class UserServiceImpl implements UserService {

    @Autowired  // 自动注入 Mapper（Spring 帮你把 UserMapper 对象塞进来）
    private UserMapper userMapper;

    @Override
    public void register(String username, String password, String phone, Integer age) {
        // 业务逻辑1：检查用户名是否已存在
        User existUser = userMapper.selectByUsername(username);
        if (existUser != null) {
            throw new RuntimeException("用户名已存在");
        }

        // 业务逻辑2：密码加密（这里先简单处理，后面讲）
        String encryptedPassword = password; // 暂时不加密

        // 业务逻辑3：构建用户对象，存入数据库
        User user = new User();
        user.setUsername(username);
        user.setPassword(encryptedPassword);
        user.setPhone(phone);
        user.setAge(age);

        userMapper.insert(user);
    }

    @Override
    public User login(String username, String password) {
        // 业务逻辑1：根据用户名查询用户
        User user = userMapper.selectByUsername(username);
        if (user == null) {
            throw new RuntimeException("用户不存在");
        }

        // 业务逻辑2：校验密码
        if (!user.getPassword().equals(password)) {
            throw new RuntimeException("密码错误");
        }

        return user;
    }

    @Override
    public User getById(Long id) {
        return userMapper.selectById(id);
    }

    @Override
    public List<User> getAll() {
        return userMapper.selectAll();
    }
}
```

**Controller（控制层）**：

```java
// controller/UserController.java

import com.example.hellodemo.dto.UserDTO;

                userDTO.getUsername(),
                userDTO.getPassword(),
                userDTO.getPhone(),
                userDTO.getAge()
        );
        return "注册成功";
    }

    // 登录
    @PostMapping("/login")

        User user = userService.login(userDTO.getUsername(), userDTO.getPassword());
        return "登录成功，欢迎：" + user.getUsername();
    }

    // 根据ID查询
    @GetMapping("/{id}")

    @GetMapping("/list")

```

### 6.5 @Autowired 是什么？

你在 Service 和 Controller 里都看到了 `@Autowired`，它是干什么的？

**通俗理解**：
- 以前你要用一个对象，得自己 `new`：`UserService userService = new UserServiceImpl();`
- 有了 Spring，你不用自己 new 了，Spring 会帮你创建好对象，你只要说「我需要这个」，它就给你塞进来
- `@Autowired` 就是说「这个对象我需要，Spring 你帮我注入进来」

**你现在只需要记住**：
- Service 里需要 Mapper → 加 `@Autowired private UserMapper userMapper;`
- Controller 里需要 Service → 加 `@Autowired private UserService userService;`
- 不用自己 new，不用管对象什么时候创建的

## 七、application.yml 配置文件

### 7.1 properties 和 yml 选哪个？

Spring Boot 支持两种配置文件格式：
- `application.properties`：键值对格式，层级用 `.` 表示
- `application.yml`：缩进格式，更清晰，**推荐用 yml**

把 `src/main/resources/application.properties` 删掉，新建 `application.yml`。

### 7.2 基本配置

```yaml
# 服务器配置
server:
  port: 8080          # 端口号，默认8080，可以改成别的
  servlet:
    context-path: /   # 项目路径前缀，默认是 /，如果改成 /api，那所有接口都要加 /api

# Spring 配置
spring:
  application:
    name: hello-demo  # 应用名称（后面微服务注册到 Nacos 时用）

  # 数据源配置（连 MySQL 用，现在先注释掉，后面讲）
  # datasource:
  #   driver-class-name: com.mysql.cj.jdbc.Driver
  #   url: jdbc:mysql://localhost:3306/hello_demo?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
  #   username: root
  #   password: 你的密码

# 日志配置
logging:
  level:
    com.example.hellodemo: debug  # 你自己的包日志级别设为 debug，方便看
    org.springframework: info     # Spring 的日志设为 info，太多了刷屏
```

### 7.3 yml 语法要点

1. **缩进表示层级**：用空格缩进（不能用 Tab），同一层级缩进要对齐
2. **键值对用 `:`**：`key: value`（冒号后面必须有空格！）
3. **列表用 `-`**：
   ```yaml
   fruits:
     - apple
     - banana
     - orange
   ```
4. **注释用 `#`**

### 7.4 怎么在代码里读取配置？

有时候你需要在代码里读取配置文件的值，用 `@Value` 注解：

```java
@RestController
@RequestMapping("/test")
public class TestController {

    // 读取配置文件里的 server.port
    @Value("${server.port}")
    private String port;

    // 读取配置，带默认值（如果配置里没有，就用默认值）
    @Value("${spring.application.name:default-app}")
    private String appName;

    @GetMapping("/config")
    public String getConfig() {
        return "端口：" + port + "，应用名：" + appName;
    }
}
```

访问 `GET http://localhost:8080/test/config`，返回：`端口：8080，应用名：hello-demo`

### 7.5 多环境配置（了解）

实际开发中，开发环境和生产环境的配置不一样（数据库地址、端口等），可以用多 profile：

```
application.yml          # 主配置（公共配置）
application-dev.yml      # 开发环境配置
application-prod.yml     # 生产环境配置
```

在 `application.yml` 里指定用哪个：
```yaml
spring:
  profiles:
    active: dev   # 用开发环境配置
```

这个了解就行，现在用不到。

## 八、统一响应体 Result

### 8.1 为什么需要统一响应体？

你现在的接口返回值乱七八糟：
- 注册成功返回 `String "注册成功"`
- 登录成功返回 `String "登录成功，欢迎：zhangsan"`
- 查询用户返回 `User 对象`
- 出错了返回 Spring 默认的 500 错误页

**前端拿到这些返回值，没法统一处理。** 所以我们要规定一个统一的返回格式。

### 8.2 统一响应体格式

一般包含三个字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| code | 状态码，200=成功，其他=失败 | 200 / 500 / 401 |
| message | 提示信息 | "操作成功" / "用户名已存在" |
| data | 返回的数据（可以是任意类型） | 用户对象、列表、null |

### 8.3 代码实现

在 `common` 包下建 `Result.java`：

```java
package com.example.hellodemo.common;

// 统一响应体
public class Result<T> {

    private Integer code;     // 状态码
    private String message;   // 提示信息
    private T data;           // 数据

    // 构造方法私有，不让外面随便 new，用静态方法创建
    private Result(Integer code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
    }

    // 成功，不带数据
    public static <T> Result<T> success() {
        return new Result<>(200, "操作成功", null);
    }

    // 成功，带数据
    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data);
    }

    // 成功，自定义提示信息和数据
    public static <T> Result<T> success(String message, T data) {
        return new Result<>(200, message, data);
    }

    // 失败，默认错误码
    public static <T> Result<T> error(String message) {
        return new Result<>(500, message, null);
    }

    // 失败，自定义错误码
    public static <T> Result<T> error(Integer code, String message) {
        return new Result<>(code, message, null);
    }

    // getter/setter
    public Integer getCode() { return code; }
    public void setCode(Integer code) { this.code = code; }
    public String getMessage() { return message; }
    public void setMessage(String message) { this.message = message; }
    public T getData() { return data; }
    public void setData(T data) { this.data = data; }
}
```

### 8.4 改造 Controller 使用统一响应体

```java
@RestController
@RequestMapping("/user")
public class UserController {

    @Autowired
    private UserService userService;

    // 注册
    @PostMapping("/register")
    public Result<Void> register(@RequestBody UserDTO userDTO) {
        userService.register(
                userDTO.getUsername(),
                userDTO.getPassword(),
                userDTO.getPhone(),
                userDTO.getAge()
        );
        return Result.success("注册成功", null);
    }

    // 登录
    @PostMapping("/login")
    public Result<User> login(@RequestBody UserDTO userDTO) {
        User user = userService.login(userDTO.getUsername(), userDTO.getPassword());
        return Result.success("登录成功", user);
    }

    // 根据ID查询
    @GetMapping("/{id}")
    public Result<User> getById(@PathVariable("id") Long id) {
        User user = userService.getById(id);
        return Result.success(user);
    }

    // 查询所有
    @GetMapping("/list")
    public Result<List<User>> getAll() {
        List<User> users = userService.getAll();
        return Result.success(users);
    }
}
```

### 8.5 测试

注册接口现在返回：
```json

    "code": 200,
    "message": "注册成功",
    "data": null
}
```

查询所有用户返回：
```json

    "message": "操作成功",
    "data": [
        {"id":1,"username":"zhangsan","password":"123456","phone":"13800138000","age":20}
    ]
}
```

**前端只需要判断 code 是否为 200，就能统一处理成功和失败了。**

## 九、全局异常处理

### 9.1 为什么需要全局异常处理？

现在 Service 里抛出异常（比如 `throw new RuntimeException("用户名已存在")`），Spring 默认会返回一个 500 错误页，长得很丑，而且前端拿不到我们定义的错误信息。

我们希望：**不管哪里抛出异常，都能被捕获，然后返回统一的 Result 格式。**

### 9.2 代码实现

在 `common` 包下建 `GlobalExceptionHandler.java`：

```java
package com.example.hellodemo.common;

import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

// @RestControllerAdvice = @ControllerAdvice + @ResponseBody
// 标记这是一个全局异常处理器，所有 Controller 抛出的异常都会被这里捕获
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 捕获所有 RuntimeException（运行时异常）
    @ExceptionHandler(RuntimeException.class)
    public Result<Void> handleRuntimeException(RuntimeException e) {
        // 打印异常堆栈（方便排查问题）
        e.printStackTrace();
        // 返回统一错误响应，message 就是异常里的信息
        return Result.error(e.getMessage());
    }

    // 捕获所有 Exception（兜底，上面没捕获到的都来这）
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        e.printStackTrace();
        return Result.error(500, "系统异常：" + e.getMessage());
    }
}
```

### 9.3 自定义业务异常（进阶，推荐）

实际项目中，我们一般不用 `RuntimeException`，而是自己定义一个业务异常类，方便区分：

在 `common` 包下建 `BusinessException.java`：

```java
package com.example.hellodemo.common;

// 自定义业务异常
public class BusinessException extends RuntimeException {

    private Integer code;  // 错误码

    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }

    public Integer getCode() {
        return code;
    }
}
```

然后在全局异常处理器里加一个专门处理业务异常的方法：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 处理业务异常（我们自己抛的）
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        // 业务异常不用打印堆栈，因为是我们预期的错误
        return Result.error(e.getCode(), e.getMessage());
    }

    // 处理运行时异常
    @ExceptionHandler(RuntimeException.class)
    public Result<Void> handleRuntimeException(RuntimeException e) {
        e.printStackTrace();
        return Result.error(e.getMessage());
    }

    // 兜底
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        e.printStackTrace();
        return Result.error(500, "系统异常");
    }
}
```

把 Service 里的 `throw new RuntimeException(...)` 改成 `throw new BusinessException(...)`：

```java
// UserServiceImpl 里
if (existUser != null) {
    throw new BusinessException("用户名已存在");
}
// ...
if (user == null) {
    throw new BusinessException("用户不存在");
}
if (!user.getPassword().equals(password)) {
    throw new BusinessException("密码错误");
}
```

### 9.4 测试

注册一个已存在的用户名，现在返回：
```json
{
    "code": 500,
    "message": "用户名已存在",
    "data": null
}
```

**完美！** 不管成功还是失败，都是统一的格式，前端可以统一处理了。

## 十、Lombok（简化代码神器）

### 10.1 Lombok 是什么？

你有没有发现，每个实体类都要写一大堆 getter/setter、toString、构造方法？又麻烦又占地方。

**Lombok 就是帮你自动生成这些代码的工具。** 你只要加几个注解，编译时它会自动帮你生成 getter/setter 等方法。

### 10.2 安装 Lombok

1. IDEA 安装 Lombok 插件：
   - File → Settings → Plugins → 搜索「Lombok」→ Install → 重启 IDEA
2. 开启注解处理：
   - File → Settings → Build → Compiler → Annotation Processors → 勾选「Enable annotation processing」
3. 项目里已经加了 Lombok 依赖（创建项目时勾选了），如果没有，在 pom.xml 里加：
   ```xml
   <dependency>
       <groupId>org.projectlombok</groupId>
       <artifactId>lombok</artifactId>
       <optional>true</optional>
   </dependency>
   ```

### 10.3 常用注解

#### @Data：自动生成 getter/setter/toString/equals/hashCode

**用之前**：
```java
public class User {
    private Long id;
    private String username;
    private String password;

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }

    @Override
    public String toString() { return "User{...}"; }
}
```

**用之后**：
```java
import lombok.Data;

@Data
public class User {
    private Long id;
    private String username;
    private String password;
}
```

**就这么简单！** getter/setter/toString 都自动生成了，你照样可以调用 `user.getUsername()`、`user.setPassword(...)`。

#### @Slf4j：自动生成日志对象

**用之前**：
```java
public class UserServiceImpl {
    private static final Logger log = LoggerFactory.getLogger(UserServiceImpl.class);

    public void register(...) {
        log.info("用户注册：{}", username);
    }
}
```

**用之后**：
```java
import lombok.extern.slf4j.Slf4j;

@Slf4j
public class UserServiceImpl {
    public void register(...) {
        log.info("用户注册：{}", username);  // 直接用 log
    }
}
```

#### @Builder：建造者模式，方便构建对象

**用之前**：
```java
User user = new User();
user.setId(1L);
user.setUsername("zhangsan");
user.setPassword("123456");
user.setAge(20);
```

**用之后**：
```java
User user = User.builder()
        .id(1L)
        .username("zhangsan")
        .password("123456")
        .age(20)
        .build();
```

链式调用，写起来很爽。注意：`@Builder` 需要配合 `@Data` 或 `@AllArgsConstructor` 使用。

#### @NoArgsConstructor / @AllArgsConstructor

- `@NoArgsConstructor`：自动生成无参构造方法
- `@AllArgsConstructor`：自动生成全参构造方法（所有字段都作为参数）

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class User {
    private Long id;
    private String username;
    private String password;
}
```

### 10.4 用 Lombok 改造项目

把之前的实体类都加上 Lombok 注解：

**User.java**：
```java
package com.example.hellodemo.model;

import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class User {
    private Long id;
    private String username;
    private String password;
    private String phone;
    private Integer age;
}
```

**UserDTO.java**：
```java
package com.example.hellodemo.dto;

import lombok.Data;

@Data
public class UserDTO {
    private String username;
    private String password;
    private String phone;
    private Integer age;
}
```

**Result.java** 也可以加 `@Data`，省掉 getter/setter：
```java
@Data
public class Result<T> {
    private Integer code;
    private String message;
    private T data;

    private Result(Integer code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
    }
    // ... 静态方法不变
}
```

**UserServiceImpl** 加 `@Slf4j`，用日志代替 System.out：
```java
@Slf4j
@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;

    @Override
    public void register(...) {
        log.info("用户注册：{}", username);
        // ...
    }
}
```

### 10.5 注意事项

1. **必须装插件 + 开启注解处理**，否则 IDEA 会报红（找不到 getter/setter）
2. 团队开发时，所有人都要装 Lombok，否则别人拉你的代码会报错
3. `@Data` 会生成 `equals` 和 `hashCode`，对于有继承关系的类要小心
4. 实体类（model）一般用 `@Data`，DTO 也用 `@Data`，这是最常用的

## 十一、综合实战：用户注册登录（连 MySQL）

前面我们用 Map 模拟了数据库，现在来真的——连 MySQL。

### 11.1 准备数据库

1. 打开 MySQL（命令行或 Navicat）
2. 创建数据库：
   ```sql
   CREATE DATABASE hello_demo DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
3. 使用数据库：
   ```sql
   USE hello_demo;
   ```
4. 创建用户表：
   ```sql
   CREATE TABLE user (
       id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID',
       username VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
       password VARCHAR(100) NOT NULL COMMENT '密码',
       phone VARCHAR(20) COMMENT '手机号',
       age INT COMMENT '年龄',
       created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
       updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
   ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
   ```

### 11.2 添加依赖

在 `pom.xml` 的 `<dependencies>` 里加：

```xml
<!-- MySQL 驱动 -->
```

### 11.3 配置数据源

在 `application.yml` 里加（把之前注释的打开，改成你的数据库信息）：

### 11.4 改造 Mapper（用 MyBatis-Plus）

把之前手写的 `UserMapper` 改成继承 MyBatis-Plus 的 `BaseMapper`：

```java
import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.example.hellodemo.model.User;
import org.apache.ibatis.annotations.Mapper;

@Mapper  // 标记这是 MyBatis 的 Mapper
public interface UserMapper extends BaseMapper<User> {
    // 什么都不用写！BaseMapper 已经提供了常用的增删改查方法：
    // insert(user)、deleteById(id)、updateById(user)、selectById(id)、selectList(null) ...
}
```

**就这么简单！** 继承 `BaseMapper<User>` 就自动获得了 CRUD 能力。

### 11.5 改造 Model（加 MyBatis-Plus 注解）

```java
package com.example.hellodemo.model;

import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableName;
import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.time.LocalDateTime;

@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
@TableName("user")  // 指定对应的数据库表名
public class User {

    @TableId(type = IdType.AUTO)  // 主键，自增
    private Long id;

    private String username;
    private String password;
    private String phone;
    private Integer age;

    private LocalDateTime createdAt;  // 对应数据库 created_at（自动下划线转驼峰）
    private LocalDateTime updatedAt;
}
```

### 11.6 改造 Service（用 MyBatis-Plus 的方法）

```java
package com.example.hellodemo.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.example.hellodemo.common.BusinessException;
import com.example.hellodemo.mapper.UserMapper;
import com.example.hellodemo.model.User;
import com.example.hellodemo.service.UserService;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.List;

@Slf4j
@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;

    @Override
    public void register(String username, String password, String phone, Integer age) {
        // 1. 检查用户名是否已存在
        // LambdaQueryWrapper 是 MyBatis-Plus 的条件构造器
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(User::getUsername, username);  // WHERE username = ?
        User existUser = userMapper.selectOne(wrapper);

        if (existUser != null) {
            throw new BusinessException("用户名已存在");
        }

        // 2. 构建用户对象
        User user = User.builder()
                .username(username)
                .password(password)  // 实际项目要加密，这里先简化
                .phone(phone)
                .age(age)
                .build();

        // 3. 插入数据库
        userMapper.insert(user);
        log.info("用户注册成功：{}", username);
    }

    @Override
    public User login(String username, String password) {
        // 1. 根据用户名查询
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(User::getUsername, username);
        User user = userMapper.selectOne(wrapper);

        if (user == null) {
            throw new BusinessException("用户不存在");
        }

        // 2. 校验密码
        if (!user.getPassword().equals(password)) {
            throw new BusinessException("密码错误");
        }

        log.info("用户登录成功：{}", username);
        return user;
    }

    @Override
    public User getById(Long id) {
        return userMapper.selectById(id);
    }

    @Override
    public List<User> getAll() {
        return userMapper.selectList(null);  // null 表示没有条件，查所有
    }
}
```

## 十三、常见问题 FAQ

### Q1：启动报错「端口 8080 已被占用」怎么办？
A：要么关掉占用 8080 的程序，要么在 `application.yml` 里改端口：`server.port: 8081`

### Q2：Postman 调接口返回 404？
A：检查路径对不对（类上的 @RequestMapping + 方法上的 @PostMapping），检查项目启动成功了没有，检查 HTTP 方法对不对（GET/POST）。

### Q3：@RequestBody 接收不到参数？
A：检查：① 请求方法是不是 POST/PUT；② Content-Type 是不是 application/json；③ JSON 的 key 和 Java 字段名是不是一致；④ 实体类有没有 getter/setter（或 @Data）。

### Q4：Lombok 的 @Data 加了但还是报找不到 getter？
A：检查：① 有没有装 Lombok 插件；② 有没有开启注解处理（Enable annotation processing）；③ 重新编译项目（Build → Rebuild Project）。

### Q5：连 MySQL 报错「Communications link failure」？
A：检查：① MySQL 启动了没有；② URL 里的地址端口对不对；③ 防火墙有没有拦；④ 用户名密码对不对。

### Q6：MyBatis-Plus 打印的 SQL 在哪看？
A：配置了 `log-impl: org.apache.ibatis.logging.stdout.StdOutImpl` 后，SQL 会打印在 IDEA 控制台里，执行查询时就能看到。
