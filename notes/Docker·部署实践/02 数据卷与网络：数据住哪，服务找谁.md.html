别把容器当永久硬盘

课程用Nginx页面演示卷挂载。容器可写层像临时工位，重建工位不该带走重要档案；volume或bind mount把需要保留的数据放到独立位置。挂载覆盖容器路径后看到的是挂载内容，不是自动合并两边文件。

方式 管理者 典型场景
named volume Docker管理存储位置 数据库数据等持久化
bind mount 你指定宿主路径 本地静态页面与配置文件
容器可写层 当前容器 临时文件，不作为唯一重要数据

Windows本地页面实验

先在自己的练习目录建立site/index.html，再在该目录的PowerShell运行：

powershell
$sitePath = (Resolve-Path .\site).Path
docker run --name learn-page -d -p 127.0.0.1:8089:80 --mount "type=bind,source=$sitePath,target=/usr/share/nginx/html,readonly" nginx:stable

浏览器打开8089，修改本地index.html后刷新应能看到变化。这里只读是对容器而言，宿主编辑仍可进行。命令不含删除操作；练习结束自行停止对应容器即可。

localhost到底是谁

应用在容器内访问localhost，指向该容器自己，不是宿主机，也不是隔壁数据库容器。课程Compose用服务名建立连接：同一Compose网络中，应用访问数据库服务名和容器内部端口。

text
宿主浏览器 → localhost:8089 → Nginx容器:80
应用容器 → redis:6379 → 名为redis的服务容器

端口映射主要解决从宿主或外部访问的问题；同网络容器间通常不需要为每个内部组件都开放宿主端口。

自测与答案

题目：数据库容器删了，数据一定还在吗？答案：取决于数据是否写入正确持久卷，以及卷是否也被删除。仅创建一个卷但没挂到真实数据目录，没有保护作用；卷也不是备份。

完成标准：指出项目每类数据实际保存路径，并解释重启与重建的区别。
