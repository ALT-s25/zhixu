03 Dockerfile、Compose与仓库：让别人能重现你的环境

约 3 分钟阅读你的知识，慢慢成林

课程从单容器走向多服务

Dockerfile描述如何构建镜像，Compose描述哪些服务一起运行。像制作说明书与活动排班表，职责不同。构建成功不证明程序运行成功，容器启动也不证明依赖服务已经就绪。

一个Java17镜像骨架

dockerfile
# 示意：先准备已构建好的app.jar，运行时版本应匹配项目
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY app.jar /app/app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app/app.jar"]

EXPOSE只是描述端口，不自动发布宿主端口。不要把本地凭据、数据库备份和整个下载目录COPY到镜像里；用.dockerignore缩小构建上下文。这个骨架用于理解，正式部署还要确定非root用户、资源限制和运行配置。

最小Compose骨架

yaml
services:
  web:
    image: nginx:stable
    ports:
      - "127.0.0.1:8090:80"
  redis:
    image: redis:7
    volumes:
      - learn-redis:/data
    command: ["redis-server", "--appendonly", "yes"]
volumes:
  learn-redis:

两服务只是用于观察网络与卷，没有假装Nginx会自动使用Redis。应用服务加入同网络后才可按redis:6379连接。课程旧式docker-compose与新式docker compose命令应按所装工具确认。

sh
docker compose config
docker compose up -d
docker compose ps
docker compose logs --tail 30

depends_on默认主要控制启动顺序；需配合healthcheck与service_healthy等条件表达健康就绪。应用仍应能处理依赖运行中断连。参见Docker启动顺序说明。

镜像仓库不是代码仓库

课程私有仓库流程是构建→打标签→推送→其他主机拉取。标签如latest或stable是可变名字，不是永远固定的内容；可复现部署应记录实际版本或摘要。推送镜像前检查是否误带凭据。

自测与答案

题目：换一台机器能启动但数据为空，优先怀疑什么？答案：镜像通常不包含原数据卷；要独立迁移或恢复数据，不能把推送镜像等同于迁移数据库。

完成标准：别人仅凭你的构建说明、配置样例和数据初始化步骤，能重建一个练习环境。
