二、进程 vs 线程 ⭐

维度 进程 线程
概念 运行的程序 进程内的执行流
资源 独立内存 共享进程内存
开销 大 小
通信 复杂（IPC） 简单（共享变量）

类比：进程 = 工厂，线程 = 工人。

三、线程创建（3 种方式）⭐⭐

3.1 继承 Thread

java
public class MyThread extends Thread {
    @Override
    public void run() {     // 线程执行的代码
        for (int i = 0; i < 100; i++) {
            System.out.println(getName() + ": " + i);
        }
    }
}

// 启动
MyThread t = new MyThread();
t.start();     // 启动新线程，会自动调 run()
// t.run();     ❌ 这只是普通方法调用，不会启动新线程

3.2 实现 Runnable（更灵活）⭐

java
public class MyRunnable implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 100; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
}

// 启动
Thread t = new Thread(new MyRunnable());
t.start();

// 简化（Lambda）
Thread t2 = new Thread(() -> {
    System.out.println("Hello from " + Thread.currentThread().getName());
});
t2.start();

3.3 实现 Callable（有返回值）⭐

java
public class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        int sum = 0;
        for (int i = 0; i < 100; i++) sum += i;
        return sum;
    }
}

// 启动
ExecutorService es = Executors.newSingleThreadExecutor();
Future<Integer> future = es.submit(new MyCallable());
Integer result = future.get();    // 阻塞获取返回值
System.out.println(result);   // 4950
es.shutdown();

💡 推荐：实现 Runnable + 线程池，而非继承 Thread。

四、线程状态 ⭐⭐⭐

4.1 六种状态

text
   新建
     ↓ start()
   就绪 ────→ 运行 ──→ 阻塞
     ↑          ↓         ↓
     └──────────┴─────────┘
                ↓
              死亡
状态 说明
NEW 新建，未启动
RUNNABLE 就绪 + 运行中（JVM 调度）
BLOCKED 等待获取锁（synchronized）
WAITING 等待（wait/join）
TIMED_WAITING 限时等待（sleep/wait(time)）
TERMINATED 死亡，run() 执行完
java
Thread t = new Thread(() -> {
    System.out.println(t.getState());   // RUNNABLE
});
t.start();

五、线程常用方法 ⭐

5.1 sleep / yield / join

java
// sleep：当前线程休眠指定毫秒（不释放锁）
Thread.sleep(1000);

// yield：让出 CPU，回到就绪状态
Thread.yield();

// join：等待调用 join 的线程执行完，再继续当前线程
Thread t = new Thread(() -> {
    try { Thread.sleep(1000); } catch (InterruptedException e) {}
});
t.start();
t.join();   // 当前线程阻塞，直到 t 执行完

5.2 优先级（1-10）

java
t.setPriority(Thread.MAX_PRIORITY);   // 10
t.setPriority(Thread.MIN_PRIORITY);   // 1

⚠ 优先级只是建议，不保证执行顺序。

5.3 守护线程

java
t.setDaemon(true);   // 设置为守护线程

特点：所有非守护线程结束后，守护线程自动结束（如 GC 线程）。

5.4 中断

java
t.interrupt();    // 中断标记（不强制停止）

// 在 run 中判断
while (!Thread.currentThread().isInterrupted()) {
    // 业务
}

六、线程同步 ⭐⭐⭐

6.1 什么是线程安全

多线程同时操作共享数据时，可能产生数据不一致。

6.2 synchronized ⭐⭐⭐

6.2.1 同步方法

java
public synchronized void increment() {  // 锁 this
    count++;
}

6.2.2 同步代码块

java
public void increment() {
    synchronized (this) {       // 锁 this
        count++;
    }
}

6.2.3 静态同步方法

java
public static synchronized void increment() {  // 锁 类.class
    count++;
}

💡 锁的级别：

  • 实例方法：锁当前对象（this）
  • 静态方法：锁 Class 对象（类.class）

6.2.4 synchronized 特性

  • 互斥性：同一时刻只有一个线程执行
  • 可见性：释放锁时会刷新到主内存
  • 可重入：同一个线程可以多次获取同一把锁
java
public synchronized void method1() {
    method2();   // 可重入，同一线程可继续获取锁
}
public synchronized void method2() { }

6.3 volatile ⭐⭐

作用：保证变量的可见性（一个线程修改，其他线程立即可见）。

java
private volatile boolean flag = false;

public void stop() {
    flag = true;       // 对其他线程立即可见
}

⚠ volatile 不保证原子性。仅适合"一写多读"场景。

6.4 Lock 接口（JDK 5+）⭐⭐

比 synchronized 更灵活：

java
import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.locks.Lock;

Lock lock = new ReentrantLock();

public void increment() {
    lock.lock();
    try {
        count++;
    } finally {
        lock.unlock();   // 必须手动释放！
    }
}

💡 tryLock：尝试获取锁，失败立即返回���

6.5 synchronized vs Lock ⭐⭐

维度 synchronized Lock
释放 自动 手动（finally）
等待 阻塞等待 可 tryLock / 中断
公平 ❌ 非公平 可公平锁
性能 JDK 6+ 优化后差距不大 略好

七、死锁 ⭐

四个必要条件（破坏任一即可避免）：

  1. 互斥
  2. 持有并等待
  3. 不可剥夺
  4. 循环等待
java
// 死锁示例
Object lockA = new Object();
Object lockB = new Object();

new Thread(() -> {
    synchronized (lockA) {
        sleep(100);
        synchronized (lockB) { }   // 等待 lockB
    }
}).start();

new Thread(() -> {
    synchronized (lockB) {
        sleep(100);
        synchronized (lockA) { }   // 等待 lockA
    }
}).start();

避免方法：固定加锁顺序、使用 tryLock、减少嵌套。

八、线程通信 ⭐⭐

8.1 wait / notify / notifyAll

java
// 必须在 synchronized 中调用
synchronized (lock) {
    lock.wait();         // 当前线程等待，释放锁
    lock.notify();        // 唤醒一个等待线程
    lock.notifyAll();     // 唤醒所有等待线程
}

⚠ wait() 释放锁，sleep() 不释放锁。

8.2 生产者-消费者模型 ⭐⭐⭐

java
public class ProducerConsumer {
    private static final int CAPACITY = 10;
    private Queue<Integer> queue = new LinkedList<>();
    private Object lock = new Object();

    public void produce() throws InterruptedException {
        while (true) {
            synchronized (lock) {
                while (queue.size() == CAPACITY) {
                    System.out.println("队列满，等待消费");
                    lock.wait();
                }
                int item = (int) (Math.random() * 100);
                queue.offer(item);
                System.out.println("生产：" + item);
                lock.notify();       // 唤醒消费者
                Thread.sleep(500);
            }
        }
    }

    public void consume() throws InterruptedException {
        while (true) {
            synchronized (lock) {
                while (queue.isEmpty()) {
                    System.out.println("队列空，等待生产");
                    lock.wait();
                }
                int item = queue.poll();
                System.out.println("���费：" + item);
                lock.notify();       // 唤醒生产者
                Thread.sleep(500);
            }
        }
    }
}

⚠ 必须用 while 不是 if！防止虚假唤醒。

8.3 Condition（Lock 的通信）

java
Lock lock = new ReentrantLock();
Condition notFull = lock.newCondition();
Condition notEmpty = lock.newCondition();

// 更灵活：一个锁配多个 Condition
notFull.await();      // 等同于 wait
notEmpty.signal();    // 等同于 notify

九、线程池 ⭐⭐

9.1 为什么用线程池

  • 减少线程创建/销毁的开销
  • 限制线程数，防止资源耗尽

9.2 创建线程池

java
ExecutorService pool = Executors.newFixedThreadPool(5);    // 固定 5 线程
ExecutorService pool2 = Executors.newCachedThreadPool();  // 弹性伸缩
ExecutorService pool3 = Executors.newSingleThreadExecutor(); // 单线程
ExecutorService pool4 = Executors.newScheduledThreadPool(5); // 定时

pool.execute(() -> System.out.println("Task"));
pool.shutdown();   // 不再接受新任务

9.3 自定义线程池（推荐）⭐⭐

java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    5,                      // corePoolSize 核心线程数
    10,                     // maximumPoolSize 最大线程数
    60, TimeUnit.SECONDS,   // keepAliveTime 空闲线程存活时间
    new LinkedBlockingQueue<>(100),  // workQueue 任务队列
    Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.CallerRunsPolicy()   // 拒绝策略
);

💡 拒绝策略：

  • AbortPolicy（默认）：抛异常
  • CallerRunsPolicy：调用者执行
  • DiscardPolicy：丢弃
  • DiscardOldestPolicy：丢弃最老任务

十、面试常问 ⭐⭐⭐

💡 进程和线程的区别？ 进程是资源分配的基本单位，线程是 CPU 调度的基本单位。同一进程的线程共享内存。

💡 创建线程的 3 种方式？

  1. 继承 Thread
  2. 实现 Runnable
  3. 实现 Callable（有返回值）

💡 run() 和 start() 的区别？

  • run()：普通方法调用
  • start()：启动新线程，由 JVM 调用 run()

💡 synchronized 和 volatile 的区别？ | 维度 | synchronized | volatile | |------|-------------|----------| | 原子性 | ✅ | ❌ | | 可见性 | ✅ | ✅ | | 阻塞 | 会 | 不 | | 修饰 | 方法/代码块 | 变量 |

💡 sleep() 和 wait() 的区别？ | 维度 | sleep | wait | |------|-------|------| | 释放锁 | ❌ | ✅ | | 调用 | Thread | Object | | 用途 | 暂停 | 线程通信 |

💡 线程池参数？ corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler

💡 Java 内存模型 JMM？

  • 主内存（共享）
  • 工作内存（线程私有）
  • 8 个原子操作（read、load、use、assign、store、write、lock、unlock）
