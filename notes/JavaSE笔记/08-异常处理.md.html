二、异常体系 ⭐⭐⭐

2.1 顶级父类

text
Throwable (可抛出的)
├── Error (错误)               —— 严重，无法处理
│   ├── OutOfMemoryError
│   └── StackOverflowError
└── Exception (异常)          —— 可处理
    ├── IOException (受检异常)
    ├── SQLException (受检异常)
    └── RuntimeException (运行时异常)
        ├── NullPointerException
        ├── ArrayIndexOutOfBoundsException
        ├── ArithmeticException
        ├── NumberFormatException
        └── ClassCastException

2.2 受检异常 vs 非受检异常

维度 受检异常 (Checked) 非受检异常 (Unchecked)
继承 Exception 及其子类（除 RuntimeException） RuntimeException 及其子类
编译 必须处理（try-catch 或 throws） 不强制处理
原因 外部因素（IO、数据库） 程序员逻辑错误
例子 IOException、SQLException 空指针、数组越界
java
// 受检异常示例
public void readFile() throws IOException {     // 必须声明 throws
    FileReader fr = new FileReader("a.txt");
}

// 非受检异常示例
public int divide(int a, int b) {
    return a / b;     // b=0 会抛 ArithmeticException，无需声明
}

三、异常处理机制 ⭐⭐⭐

3.1 try-catch-finally

java
try {
    // 可能出现异常的代码
    int result = 10 / 0;
} catch (ArithmeticException e) {     // 捕获特定异常
    System.out.println("除数不能为零");
    e.printStackTrace();              // 打印栈轨迹
} catch (Exception e) {                // 兜底异常
    System.out.println("其他异常");
} finally {
    // 无论是否异常都执行（通常用于��放资源）
    System.out.println("执行 finally");
}

3.2 多个 catch 规则

  1. 子类异常必须放在父类之前
  2. 多个 catch 只匹配第一个满足的类型
  3. Java 7+ 可用 | 多异常捕获
java
try {
    // ...
} catch (NullPointerException | ArrayIndexOutOfBoundsException e) {
    System.out.println("空指针或数组越界");
}

3.3 try-with-resources（Java 7+）⭐

自动关闭实现了 AutoCloseable 接口的资源：

java
// 传统写法
BufferedReader br = null;
try {
    br = new BufferedReader(new FileReader("a.txt"));
    return br.readLine();
} finally {
    if (br != null) br.close();
}

// try-with-resources（推荐）
try (BufferedReader br = new BufferedReader(new FileReader("a.txt"))) {
    return br.readLine();
}    // 自动调用 br.close()

3.4 throws（声明抛出）⭐⭐

将异常抛给调用者处理：

java
public void readFile() throws IOException {     // 声明可能抛出
    FileReader fr = new FileReader("a.txt");    // 受检异常必须 throws
}

// 调用方必须处理
public void caller() {
    try {
        readFile();
    } catch (IOException e) {
        e.printStackTrace();
    }
}

// 也可以继续向上 throws
public void caller() throws IOException {
    readFile();
}

3.5 throw（手动抛出）⭐

java
public void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负：" + age);
    }
    this.age = age;
}

3.6 throws vs throw

维度 throws throw
位置 方法声明 方法体内
后面 异常类名（可多个） 异常对象（只能一个）
作用 声明可能抛出 主动抛出
个数 可声明多个异常 每次抛一个

四、异常常用方法

java
catch (Exception e) {
    e.printStackTrace();          // 打印栈轨迹（开发时最常用）
    e.getMessage();                // 返回异常信息
    e.toString();                  // 返回异常的字符串表示
    System.out.println(e.fillInStackTrace());
}

五、自定义异常 ⭐

5.1 为什么需要自定义异常

  • Java 内置异常不够用
  • 业务相关的异常描述

5.2 自定义步骤

java
// 1. 继承 Exception（受检）或 RuntimeException（非受检）
public class LoginException extends RuntimeException {
    public LoginException() {
        super();
    }

    public LoginException(String message) {
        super(message);     // 传给父类
    }
}

// 2. 使用
public void login(String username, String password) {
    if (!"admin".equals(username) || !"123".equals(password)) {
        throw new LoginException("用户名或密码错误！");
    }
}

六、异常实践建议 ⭐⭐

6.1 应该捕获异常的场景

✅ 网络请求失败 ✅ 文件读写 ✅ 数据库操作 ✅ 用户输入校验

6.2 不应该捕获异常的场景

❌ 捕获但不处理（catch 块为空）—— 隐藏了问题 ❌ 捕获 Exception 兜底 —— 应该捕获具体异常 ❌ 异常用于控制流程 —— 性能差，应使用 if-else

6.3 良好的实践

java
// ✅ 好的写法
try {
    // 业务代码
} catch (FileNotFoundException e) {
    logger.error("文件未找到：{}", filePath, e);
    throw new BusinessException("文件不存在");
}

// ❌ 不好的写法
try {
    // 业务代码
} catch (Exception e) {
    // 什么都不做
}

七、面试常问 ⭐⭐

💡 Error 和 Exception 的区别？

  • Error：严重错误（JVM 内部），程序无法处理
  • Exception：程序可以处理的异常

💡 受��异常和运行时异常的区别？

  • 受检异常：编译时必须处理（throws 或 try-catch）
  • 运行时异常：编译时不强制，一般是程序 bug

💡 final、finally、finalize 的区别？

  • final：修饰类（不可继承）、方法（不可重写）、变量（常量）
  • finally：try-catch 始终执行的代码块（除非 JVM 退出）
  • finalize：Object 的方法，GC 前调用，已废弃

💡 try-catch-finally 中哪个部分可以省略？ catch 和 finally 不能同时省略。但 try-finally 可以（无 catch 不处理）。

💡 try 中 return 后 finally 还执行吗？ 执行。finally 在 return 前执行（修改返回值不影响原 return）。 但 System.exit() 会阻止 finally。

八、本章小结

✅ 已掌握：

  • 异常体系：Throwable → Error / Exception → RuntimeException
  • 受检异常 vs 运行时异常
  • try-catch-finally 用法
  • throws 声明异常
  • throw 手动抛出
  • 自定义异常
  • try-with-resources 自动关闭资源

✅ 易错点：

  • catch 必须从小到大（子类 → 父类）
  • 受检异常必须处理
  • finally 在 return 前执行
  • finally 不执行的特殊情况：System.exit()、JVM 崩溃
