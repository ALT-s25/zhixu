学习笔记/Elasticsearch·搜索实践

01 倒排索引、Mapping与文档：从找一本书开始

约 3 分钟阅读你的知识，慢慢成林

先建立正确直觉

逐本翻书找“上海酒店”很慢，倒排索引像书后索引：词条→出现该词的文档列表。边界：匹配结果取决于分词器、字段映射和查询类型，不是任意中文字符串都能自动按你的理解搜索。

课程hotel数据从MySQL转为HotelDoc，包含名称、品牌、城市、价格、位置等。ES适合搜索展示，原业务数据仍由明确的权威库维护。

字段 映射思路 为什么
name text 需要分词检索
city、brand keyword 精确筛选与聚合
price 数值 范围与排序
location geo_point 距离查询
suggestion completion 自动补全

创建独立练习索引

在Kibana Dev Tools中分两次执行，索引名专用于练习。此例使用内置分词行为，中文效果与课程安装IK后的结果可能不同。

http
PUT learn_hotels
{
  "mappings": {
    "properties": {
      "name": {"type": "text"},
      "city": {"type": "keyword"},
      "brand": {"type": "keyword"},
      "price": {"type": "integer"},
      "location": {"type": "geo_point"},
      "suggestion": {"type": "completion"}
    }
  }
}
http
PUT learn_hotels/_doc/1
{
  "name": "小芽酒店", "city": "上海", "brand": "小芽",
  "price": 300, "location": {"lat": 31.23, "lon": 121.47},
  "suggestion": ["小芽酒店", "xiaoya"]
}

GET learn_hotels/_doc/1能取回文档；搜索可能需要等待refresh后可见。文档存在与立刻能被_search搜到，不是同一时刻保证。

修改不是任意改结构

新增字段与改变已有字段类型是不同操作。已有字段类型通常不能直接改成另一种；需要新索引、数据重建和切换方案，而不是直接删除有业务数据的索引。

自测与答案

题目：city为什么不用text再做精确筛选？答案：城市作为整体值更符合keyword语义，避免分词结果影响精确匹配和聚合。

完成标准：为自己的三条酒店数据设计字段，逐项说明类型选择。
