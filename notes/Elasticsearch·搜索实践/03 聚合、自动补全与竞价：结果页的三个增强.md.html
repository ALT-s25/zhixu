03 聚合、自动补全与竞价：结果页的三个增强

约 2 分钟阅读你的知识，慢慢成林

聚合像现场分组统计

课程不把城市、品牌选项写死，而是从符合查询条件的酒店数据中聚合。桶聚合负责分组，指标聚合负责每组的平均价等统计。

http
GET learn_hotels/_search
{
  "size": 0,
  "query": {"term": {"city": "上海"}},
  "aggs": {
    "brands": {
      "terms": {"field": "brand", "size": 20},
      "aggs": {"avg_price": {"avg": {"field": "price"}}}
    }
  }
}

size=0表示不需要普通搜索文档，不是没有聚合结果。外层query限制聚合范围；结果应从aggregations读取。terms默认是取部分桶，不保证任意数量品牌都完整列出，需按需求设计分页聚合等方案。

自动补全不是全文搜索

课程添加completion字段，并引入拼音分词器，使用户输入前缀获得建议。类比是输入时给出候选菜单，不是提交关键词后的完整搜索排名。

http
GET learn_hotels/_search
{
  "suggest": {
    "hotel_suggest": {
      "prefix": "xiao",
      "completion": {"field": "suggestion", "size": 5, "skip_duplicates": true}
    }
  }
}

本例在前章手动写入xiaoya，所以不依赖拼音插件也能理解前缀匹配；要按课程让中文自动生成拼音，需安装匹配ES版本的插件，配置analyzer并重建相应数据。不要把手工测试成功描述成拼音功能已自动实现。

竞价排名与用户理解

课程用function_score影响部分酒店得分，同时界面显示广告标记。加分不等于在所有排序条件下一定第一：若用户明确按价格升序，就要决定是否尊重价格排序。技术规则应与页面承诺一致。

自测与答案

题目：筛选上海之后，品牌聚合仍包含其他城市品牌一定是ES错了吗？答案：先看query是否应用到聚合范围，或你是否故意采用全局聚合。结果取决于DSL层级。

完成标准：讲清普通hits、聚合桶、suggest候选是三套不同的响应结构。
