02 搜索、过滤、排序与高亮：把一句需求拆成DSL

约 3 分钟阅读你的知识，慢慢成林

课程需求拆解

用户想找“上海、价格不超过500、与酒店关键词相关”的结果。关键词影响相关性得分，城市与价格通常只是资格条件。像先按要求筛出候选，再按贴合程度排序，两个步骤不要混在一起。

http
GET learn_hotels/_search
{
  "query": {
    "bool": {
      "must": [{"match": {"name": "酒店"}}],
      "filter": [
        {"term": {"city": "上海"}},
        {"range": {"price": {"lte": 500}}}
      ]
    }
  },
  "from": 0, "size": 5,
  "sort": [{"price": "asc"}],
  "highlight": {"fields": {"name": {}}}
}

这例明确按价格排序，所以不要再期待一定按相关性得分排列。name的中文匹配效果依赖分词；先用_analyze理解分词结果，再判断查询是否写错。

课程Java实现的固定骨架

RequestParams接收key/page/size/city/brand/minPrice/maxPrice等→组装query→添加分页排序→发请求→解析hits与total→解析高亮和距离→组装返回值。先在DSL验证，再翻译成客户端API，能少掉一半排错变量。

空关键词应使用match_all或等价无关键词查询；价格下界高于上界、page小于1、size过大应在接口层验证。高亮缺失时使用原name，不要让显示名称变null。

分页与附近酒店

from/size适合浅分页，页数很深会增加处理成本。需要稳定连续遍历时学习search_after配合一致的排序与PIT等机制，不能无限加大窗口。

课程附近酒店按geo距离排序，坐标必须分清经度与纬度；显示的距离来自排序/计算结果，而不是名称里含“附近”。相同距离时还需稳定的辅助排序字段。

高亮的显示边界

高亮返回片段含标记标签，不要把不可信完整字符串直接作为任意HTML执行。显示层仅允许预期高亮标签或用安全的文本分段渲染。

自测与答案

题目：term查询“酒店”为什么可能搜不到text字段中你以为应存在的结果？答案：term按词条精确匹配，不先像match那样分析查询文本；应核对实际分词词条与字段类型。

完成标准：把一句搜索需求标成关键词、过滤、排序、分页四类，并写出对应DSL位置。
