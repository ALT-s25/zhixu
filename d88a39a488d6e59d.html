一、视图（View）

1.1 什么是视图

视图是基于 SQL 查询定义的虚拟表，不存储数据，每次查询视图时动态执行底层 SQL。

text
类比：视图就像报表模板，每次打开都是实时数据

1.2 创建视图

sql
-- 创建视图：查询员工和部门的联合信息
CREATE VIEW v_emp_dept AS
SELECT
    e.id,
    e.name AS emp_name,
    e.salary,
    d.name AS dept_name
FROM employee e
LEFT JOIN department d ON e.dept_id = d.id;

-- 查询视图（和查表一样）
SELECT * FROM v_emp_dept WHERE dept_name = '技术部';

1.3 更新和删除视图

sql
-- 修改视图
CREATE OR REPLACE VIEW v_emp_dept AS
SELECT e.id, e.name, d.name AS dept_name
FROM employee e LEFT JOIN department d ON e.dept_id = d.id;

-- 删除视图
DROP VIEW IF EXISTS v_emp_dept;

1.4 视图的优缺点

优点 缺点
简化复杂查询 更新受限
隐藏表结构 性能不佳（每次重新执行）
权限控制（只给视图权限） 调试困难

二、存储过程（Stored Procedure）

2.1 什么是存储过程

预先编译好的 SQL 语句集合，存在数据库中，可以反复调用。

sql
-- 创建存储过程
DELIMITER //
CREATE PROCEDURE p_add_user(
    IN  p_name    VARCHAR(50),     -- 输入参数
    IN  p_phone   CHAR(11),
    OUT p_id      BIGINT            -- 输出参数
)
BEGIN
    INSERT INTO user(username, phone) VALUES(p_name, p_phone);
    SET p_id = LAST_INSERT_ID();   -- 获取自增 id
END //
DELIMITER ;

-- 调用存储过程
CALL p_add_user('张三', '13800138000', @new_id);
SELECT @new_id;   -- 查看输出参数

2.2 流程控制

sql
DELIMITER //
CREATE PROCEDURE p_grade(IN score INT, OUT grade CHAR(1))
BEGIN
    IF score >= 90 THEN
        SET grade = 'A';
    ELSEIF score >= 80 THEN
        SET grade = 'B';
    ELSEIF score >= 70 THEN
        SET grade = 'C';
    ELSE
        SET grade = 'D';
    END IF;
END //
DELIMITER ;

2.3 循环

sql
DELIMITER //
CREATE PROCEDURE p_sum(IN n INT, OUT result INT)
BEGIN
    DECLARE i INT DEFAULT 1;
    SET result = 0;
    WHILE i <= n DO
        SET result = result + i;
        SET i = i + 1;
    END WHILE;
END //
DELIMITER ;

CALL p_sum(100, @s);
SELECT @s;    -- 5050

三、函数（Function）

3.1 创建函数

sql
-- 函数有且只有一个返回值（区别于存储过程）
DELIMITER //
CREATE FUNCTION f_full_name(first_name VARCHAR(50), last_name VARCHAR(50))
RETURNS VARCHAR(100) DETERMINISTIC
BEGIN
    RETURN CONCAT(last_name, first_name);
END //
DELIMITER ;

-- 使用函数
SELECT f_full_name('三', '张');   -- 张三

四、触发器（Trigger）

4.1 什么是触发器

在数据变更时自动执行的 SQL，可在 INSERT/UPDATE/DELETE 前后触发。

sql
-- 场景：订单删除后，自动记录到历史表
DELIMITER //
CREATE TRIGGER trg_order_delete
AFTER DELETE ON `order`           -- 在 order 表删除后触发
FOR EACH ROW                       -- 每行触发一次
BEGIN
    INSERT INTO order_history(id, user_id, amount, delete_time)
    VALUES(OLD.id, OLD.user_id, OLD.amount, NOW());
    -- OLD 表示被删除的那行数据
END //
DELIMITER ;
时机 操作 NEW / OLD
BEFORE INSERT INSERT 前 NEW（新数据）
AFTER INSERT INSERT 后 NEW（新数据）
BEFORE UPDATE UPDATE 前 OLD/NEW
AFTER UPDATE UPDATE 后 OLD/NEW
BEFORE DELETE DELETE 前 OLD（旧数据）
AFTER DELETE DELETE 后 OLD（旧数据）

五、锁机制 ⭐⭐⭐

5.1 锁的分类

text
MySQL 锁
├── 全局锁：锁整个数据库（备份用）
├── 表锁
│   ├── 表共享读锁（S Lock）：多个事务可同时读
│   └── 表独占写锁（X Lock）：只能一个事务写
└── 行锁（InnoDB）⭐
    ├── 行共享锁（S Lock）
    ├── 行排他锁（X Lock）
    ├── 意向锁
    ├── 间隙锁（Gap Lock）
    └── 临键锁（Next-Key Lock）

5.2 行锁 ⭐⭐

InnoDB 支持行级锁（性能好，并发高）。

sql
-- 加共享锁（允许其他事务读，不允许写）
SELECT * FROM user WHERE id = 1 LOCK IN SHARE MODE;

-- 加排他锁（不允许其他事务读写）
SELECT * FROM user WHERE id = 1 FOR UPDATE;

5.3 死锁

sql
-- 事务 A
BEGIN;
UPDATE user SET balance = balance - 100 WHERE id = 1;  -- 锁住 id=1
UPDATE user SET balance = balance + 100 WHERE id = 2;  -- 等 id=2

-- 事务 B（同时执行）
BEGIN;
UPDATE user SET balance = balance - 100 WHERE id = 2;  -- 锁住 id=2
UPDATE user SET balance = balance + 100 WHERE id = 1;  -- 等 id=1

-- 结果：A 等 B，B 等 A，死锁！
-- MySQL 会自动检测死锁，回滚代价小的那个事务

避免死锁：

  • 多表操作保持固定顺序（先操作 id 小的）
  • 控制事务范围，不要太长
  • 超时自动回滚：innodb_lock_wait_timeout

6.2 EXPLAIN 分析执行计划

sql
EXPLAIN SELECT * FROM user WHERE username = 'Jack';

关键字段：

字段 说明 好/坏
type 访问类型 const/ref 好，ALL 坏（全表扫描）
key 实际使用的索引 有 key 表示用了索引
rows 预估扫描行数 越小越好
Extra 额外信息 Using filesort / Using temporary 坏

七、常见面试题 ⭐⭐⭐

💡 MyISAM 和 InnoDB 的区别？ | 维度 | MyISAM | InnoDB | |------|--------|--------| | 事务 | 不支持 | ✅ 支持 | | 外键 | 不支持 | ✅ 支持 | | 行锁 | ❌ 表锁 | ✅ 行锁 | | 崩溃恢复 | 较差 | ✅ 好 | | 推荐 | 只读 | 生产必用 |

💡 MySQL 的存储引擎有哪些？ InnoDB（默认，支持事务行锁）、MyISAM（不支持事务）、Memory（内存引擎）。

💡 MySQL 有哪些日志？

  • redo log（重做日志）：crash recovery，保证持久化
  • undo log（回滚日志）：事务回滚，MVCC
  • binlog（二进制日志）：主从复制，数据归档

💡 MVCC 是什么？ Multi-Version Concurrency Control（多版本并发控制）。在 READ COMMITTED 和 REPEATABLE READ 隔离级别下，通过 undo log 实现读不加锁，提高并发。
