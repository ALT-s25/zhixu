06 Redis与接口文档：会整合，也要会检查结果

约 2 分钟阅读你的知识，慢慢成林

原文：第114—129页；Redis从120页、接口文档从124页开始。优先级：CRUD完成后学习。

Redis可以类比速度快的临时查询柜，MySQL仍承担需要长期可靠保存的业务记录。边界：Redis并不只有缓存用途，也不能因为快就把所有正确性问题交给它。

课程展示依赖、连接配置和StringRedisTemplate读写。先用一个独立测试键验证连接，再研究自动配置与连接工厂，最后放进业务缓存。

java
// 整合片段，redis为注入的StringRedisTemplate
redis.opsForValue().set("learn:hello", "Java", Duration.ofMinutes(5));
String value = redis.opsForValue().get("learn:hello");
// value可能为null：键不存在、过期或被删除

接口文档像窗口办事说明：参数、类型、响应和错误应与实际接口一致。OpenAPI是规范，Swagger相关UI用于展示与调试；文档能打开不意味着权限已正确控制。版本应与课程工程匹配，不能任意组合starter。

练习：删除测试键后再次读取并处理null；为一个分页接口补充参数和失败响应说明，再对照真实请求验证。边界：本章不是黑马Redis完整课程总结，不能替代其缓存、秒杀和分布式锁专项资料。
