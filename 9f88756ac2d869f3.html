二、数据库操作

sql
-- 查询所有数据库
SHOW DATABASES;

-- 查询当前数据库
SELECT DATABASE();

-- 创建数据库
CREATE DATABASE mydb;
-- 指定字符集
CREATE DATABASE mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
-- 如果不存在才创建（推荐，不会报错）
CREATE DATABASE IF NOT EXISTS mydb;

-- 删除数据库（慎用！数据全没）
DROP DATABASE mydb;
DROP DATABASE IF EXISTS mydb;   -- 存在才删

-- 切换/使用数据库
USE mydb;

⚠ 生产环境一定要有备份才能执行 DROP！

三、数据类型 ⭐

3.1 数值类型

类型 大小 范围 用途
TINYINT 1 byte -128~127 状态（0/1）
SMALLINT 2 bytes -32768~32767 小整数
INT 4 bytes -2³¹~2³¹-1 常用整数
BIGINT 8 bytes -2⁶³~2⁶³-1 大整数（订单ID）
FLOAT 4 bytes 单精度 浮点（少用）
DOUBLE 8 bytes 双精度 浮点（少用）
DECIMAL(p,s) 变长 精确小数 金额必用

⚠ 金额类型必须用 DECIMAL，不能用 float/double（精度丢失！） 例：price DECIMAL(10, 2) 表示最多 10 位，小数 2 位，如 99999999.99

3.2 字符串类型

类型 大小 特点 用途
CHAR(n) 0~255 字符 定长，不足补空格 手机号、身份证
VARCHAR(n) 0~65535 字符 变长，按实际存储 最常用：姓名、地址
TEXT 0~65535 字符 长文本 文章内容
LONGTEXT 0~4G 字符 超长文本 超长内容
BLOB 二进制 二进制大对象 图片（不推荐存图片）

💡 CHAR vs VARCHAR：

  • CHAR(10) 存 "hi"，实际占 10 个字符空间（补空格），查询快
  • VARCHAR(10) 存 "hi"，实际占 2 个字符空间，节省空间

3.3 日期时间类型

类型 格式 范围 用途
DATE YYYY-MM-DD 1000~9999年 生日
TIME HH:MM:SS - 时间
DATETIME YYYY-MM-DD HH:MM:SS 1000~9999年 创建时间、更新时间
TIMESTAMP YYYY-MM-DD HH:MM:SS 1970~2038年 时间戳（会自动更新）
YEAR YYYY 1901~2155 年份

💡 推荐用 DATETIME 存时间，TIMESTAMP 有 2038 年问题。

四、表操作 ⭐⭐

4.1 查询表

sql
-- 查看当前数据库所有表
SHOW TABLES;

-- 查看表结构（字段定义）
DESC 表名;
-- 或
DESCRIBE 表名;
-- 完整定义（含建表语句）
SHOW CREATE TABLE 表名;

4.2 创建表 ⭐⭐

sql
CREATE TABLE 表名 (
    字段名 数据类型 [约束],
    字段名 数据类型 [约束],
    ...
) COMMENT '表注释';

示例：创建用户表：

sql
CREATE TABLE user (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    username    VARCHAR(50) NOT NULL UNIQUE COMMENT '用户名',
    password    VARCHAR(200) NOT NULL COMMENT '密码',
    nickname    VARCHAR(100) COMMENT '昵称',
    phone       CHAR(11) COMMENT '手机号',
    email       VARCHAR(100) COMMENT '邮箱',
    gender      TINYINT DEFAULT 1 COMMENT '性别：1男2女',
    avatar      VARCHAR(500) COMMENT '头像URL',
    balance     DECIMAL(10, 2) DEFAULT 0 COMMENT '余额',
    status      TINYINT DEFAULT 1 COMMENT '状态：1正常0禁用',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) COMMENT '用户表';

各约束说明：

约束 说明
PRIMARY KEY 主键，唯一且非空
AUTO_INCREMENT 自动递增（配合整数主键）
NOT NULL 非空约束
UNIQUE 唯一约束
DEFAULT 值 默认值
COMMENT '注释' 字段注释

⚠ 生产规范：

  • 主键必须命名为 id，类型 BIGINT AUTO_INCREMENT
  • 必须有 create_time 和 update_time 字段
  • 每个字段必须有 COMMENT 注释
  • 表名、字段名用小写 + 下划线（snake_case）

4.3 修改表

sql
-- 添加字段
ALTER TABLE user ADD COLUMN age INT COMMENT '年龄';

-- 修改字段类型
ALTER TABLE user MODIFY COLUMN nickname VARCHAR(200);

-- 修改字段名和类型
ALTER TABLE user CHANGE COLUMN nickname nick_name VARCHAR(200) COMMENT '昵称';

-- 删除字段（慎用！数据会丢失）
ALTER TABLE user DROP COLUMN age;

-- 修改表名
ALTER TABLE user RENAME TO sys_user;
-- 或
RENAME TABLE user TO sys_user;

4.4 删除表

sql
-- 删除表（慎用！）
DROP TABLE user;
DROP TABLE IF EXISTS user;   -- 推荐，存在才删

-- 清空表数据（保留结构）
TRUNCATE TABLE user;         -- 清空，自增 ID 重置
DELETE FROM user;            -- 清空，自增 ID 不重置（见 DML 章节）

五、实战：设计订单系统表结构

sql
-- 商品表
CREATE TABLE product (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    name        VARCHAR(200) NOT NULL COMMENT '商品名',
    price       DECIMAL(10,2) NOT NULL COMMENT '价格',
    stock       INT DEFAULT 0 COMMENT '库存',
    status      TINYINT DEFAULT 1 COMMENT '状态',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP
) COMMENT '商品表';

-- 订单表
CREATE TABLE `order` (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT NOT NULL COMMENT '用户ID',
    total       DECIMAL(10,2) NOT NULL COMMENT '订单总额',
    status      TINYINT DEFAULT 0 COMMENT '0待支付1已支付2已取消',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP
) COMMENT '订单表';

-- 订单详情表
CREATE TABLE order_item (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    order_id    BIGINT NOT NULL COMMENT '订单ID',
    product_id  BIGINT NOT NULL COMMENT '商品ID',
    num         INT NOT NULL COMMENT '数量',
    price       DECIMAL(10,2) NOT NULL COMMENT '单价'
) COMMENT '订单详情表';

六、常见报错

报错 1：Table already exists

text
原因：表已存在
解决：DROP TABLE IF EXISTS 再 CREATE，或用 CREATE TABLE IF NOT EXISTS

报错 2：Data too long for column

text
原因：插入的数据超过字段长度限制
解决：ALTER TABLE 修改字段长度

报错 3：Incorrect datetime value

text
原因：日期格式不对
解决：统一用 'YYYY-MM-DD HH:MM:SS' 格式

七、面试常问

💡 CHAR 和 VARCHAR 的区别？

  • CHAR 定长，不足补空格，查询快，适合固定长度（手机号）
  • VARCHAR 变长，按实际长度存储，节省空间，适合可变长度（姓名）

💡 为什么不能用 FLOAT/DOUBLE 存金额？ 浮点数有精度问题，0.1 + 0.2 ≠ 0.3。金额必须用 DECIMAL(p,s) 精确存储。

💡 DATETIME 和 TIMESTAMP 的区别？

  • DATETIME：1000-9999年，不受时区影响，推荐
  • TIMESTAMP：1970-2038年，自动换算时区，有 2038 问题
