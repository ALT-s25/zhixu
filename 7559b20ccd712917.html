第一部分：网络编程

1. 概述与软件结构

网络编程：在网络通信协议下，不同计算机上运行的程序之间进行数据传输。
应用场景：通信、视频通话、网游、邮件……只要涉及计算机之间通过网络传数据，就有网络编程。

1.1 软件结构

C/S 结构（Client/Server，客户端/服务器）

[图示：C/S 架构示意图——客户端与服务器直接通信，常见如 QQ、飞秋等桌面应用]

  • 特点：需要安装专属客户端软件，功能强大，可直接使用本地资源。
  • 代表：QQ、红蜘蛛、飞秋。

B/S 结构（Browser/Server，浏览器/服务器）

[图示：B/S 架构示意图——用浏览器作为客户端访问服务器，常见如网页应用]

  • 特点：用浏览器访问，无需安装额外软件，更新维护方便。
  • 代表：各类网站、Web 应用。

两种架构各有优劣，但无论哪种架构，都离不开网络的支持。

2. 服务器概念

text
服务器：安装了服务器软件的计算机。
后面会学到的服务器软件：Tomcat（Web 服务器）

生活类比： 服务器就像一家 24 小时营业的便利店，它随时等待顾客（客户端）上门，然后提供服务（返回数据）。

网络通信协议： 两台计算机在做数据交互时要遵守的规则，对数据的格式、速率等做出规定。就像两个人打电话要用同一种语言一样，只有都遵守协议，才能完成数据交互。

[图示：网络通信协议层级示意图——展示协议如何约束数据交互的格式和流程]

3. 通信三要素

网络通信需要三个基本要素：IP 地址、协议、端口号。

[图示：通信三要素关系图——IP 定位机器，端口定位程序，协议规定通信方式]

3.1 IP 地址

text
概述：互联网协议地址（Internet Protocol Address），俗称 IP，是计算机的唯一标识。
作用：用于两台计算机之间建立连接。

IPV4：
  32 位二进制数，通常分成 4 组，每组 0~255 的十进制整数，格式如 192.168.65.100
  最多表示约 42 亿个地址（已经不够用了）

IPV6：
  128 位地址，每 16 个字节一组，共 8 组十六进制数
  格式：ABCD:EF01:2345:6789:ABCD:EF01:2345:6789
  号称能给地球上每一粒沙子分配一个 IP 地址

常用命令：
  ipconfig          → 查看本机 IP
  ping IP地址       → 测试能否连接某台计算机

特殊地址（代表本机，到哪里都不变）：
  127.0.0.1
  localhost
  
访问本机服务格式：localhost:端口号/应用名称/资源路径
  例如：localhost:8080/应用名称/index.html

3.2 协议

text
TCP：面向连接协议
  需要先确认连接，才能进行数据交互（三次握手）
  好处：数据安全，提供可靠的传输环境
  坏处：效率相对低一些

UDP：面向无连接协议
  不需要建立连接，直接发送
  好处：效率高，速度快
  坏处：传输的数据不安全，容易丢失数据包

生活类比：

  • TCP 就像打电话：先拨号等接通（三次握手），通话中途不会丢字，挂断时礼貌道别（四次挥手）。
  • UDP 就像发短信：发出去就不管了，对方收没收到不知道，但速度快。

TCP 三次握手（建立连接）

[图示：TCP 三次握手流程图——客户端和服务器各自的状态变化]

text
第一次握手：客户端向服务器发出连接请求，等待服务器确认。
            （客户端：我想连接你，你在吗？）

第二次握手：服务器向客户端回送响应，通知客户端收到了连接请求。
            （服务器：我在，我听到了，你能听到我吗？）

第三次握手：客户端再次向服务器发送确认信息，确认连接建立。
            （客户端：好的，我也听到你了，我们开始通信吧！）

为什么需要三次？ 两次握手无法确保双方都具备收发能力，三次才能确认双向通道都正常。

TCP 四次挥手（断开连接）

[图示：TCP 四次挥手流程图——连接断开的四个步骤]

text
第一次挥手：客户端向服务器提出结束连接，不再发数据（但还能接收）。
            （客户端：我说完了，准备挂电话吧）

第二次挥手：服务器接收到后，把最后的数据发给客户端，并告知上层不再接收数据。
            （服务器：好的，我还有几句话，你先听着）

第三次挥手：服务器发完最后的数据，给客户端发送释放连接的报文。
            （服务器：我也说完了，可以挂了）

第四次挥手：客户端回复彻底断开的报文，然后等待 2MSL 时间再彻底关闭。
            （客户端：收到，我们就此再见）
            
注：客户端等待 2MSL 是为了防止服务器没收到最后的报文，
    如果服务器重发了释放请求，客户端在等待时间内能重新确认。

为什么是四次而不是三次？ 因为 TCP 是全双工的，双方各自有发送和接收，关闭时需要各自确认关闭，所以比握手多一次。

3.3 端口号

text
作用：每一个应用程序的唯一标识（在同一台机器上）

范围：用两个字节表示的整数，0~65535
  0~1023：知名端口，用于知名的网络服务（如 HTTP:80, HTTPS:443, FTP:21）
  1024 以上：普通应用程序使用

注意：如果端口号被其他程序占用，当前程序启动会失败！

生活类比： IP 地址就像大楼地址，端口号就像大楼里的具体房间号。快递员（数据）找到大楼（IP）后，还需要知道送到哪个房间（端口）。

4. UDP 协议编程

text
DatagramSocket  → 好比寄快递找的快递公司
DatagramPacket  → 好比快递公司的打包装箱

4.1 客户端（发送端）

步骤：

  1. 创建 DatagramSocket 对象（快递公司）
  2. 创建 DatagramPacket 对象，将数据进行打包（指定接收端IP和端口）
  3. 发送数据
  4. 释放资源
java
import java.net.DatagramSocket;
import java.net.DatagramPacket;
import java.net.InetAddress;

public class UDPSend {
    public static void main(String[] args) throws Exception {

        // 1. 创建 DatagramSocket 对象（代表快递公司）
        //    空参：系统随机分配一个可用端口号
        //    有参：自己指定端口号，如 new DatagramSocket(8888)
        DatagramSocket socket = new DatagramSocket();

        // 2. 准备要发送的数据，转换为字节数组
        byte[] bytes = "你好呀".getBytes();

        // 3. 指定接收端的 IP 地址（127.0.0.1 表示本机）
        InetAddress ip = InetAddress.getByName("127.0.0.1");

        // 4. 指定接收端的端口号
        int port = 6666;

        // 5. 创建 DatagramPacket 对象，将数据打包
        //    参数：数据字节数组、数据长度、目标IP、目标端口
        DatagramPacket dp = new DatagramPacket(bytes, bytes.length, ip, port);

        // 6. 通过 socket 发送数据包
        socket.send(dp);

        // 7. 释放资源（关闭 socket）
        socket.close();
    }
}

重要：在没有接收端的情况下，发送端执行不会报错！因为 UDP 是面向无连接协议，不管有没有接收端，照发不误。

4.2 服务端（接收端）

步骤：

  1. 创建 DatagramSocket 对象，指定服务端端口号
  2. 准备数组，创建 DatagramPacket 接收数据包
  3. 接收数据包
  4. 解析数据包
  5. 释放资源
java
import java.net.DatagramSocket;
import java.net.DatagramPacket;
import java.net.InetAddress;

public class UDPReceive {
    public static void main(String[] args) throws Exception {

        // 1. 创建 DatagramSocket 对象，指定服务端监听的端口号（要与发送端一致）
        DatagramSocket socket = new DatagramSocket(6666);

        // 2. 创建字节数组，用于保存接收到的数据
        byte[] bytes = new byte[1024];

        // 3. 创建 DatagramPacket 对象，用于接收数据包（只需传入字节数组和长度）
        DatagramPacket dp = new DatagramPacket(bytes, bytes.length);

        // 4. 调用 receive 方法接收数据包（此方法会阻塞，直到收到数据）
        socket.receive(dp);

        // 5. 解析数据包
        byte[] data = dp.getData();         // 获取接收到的字节数据
        int len = dp.getLength();           // 获取实际接收的数据长度
        InetAddress address = dp.getAddress(); // 获取发送端的 IP 地址
        int port = dp.getPort();            // 获取发送端的端口号

        // 6. 将字节数组转换为字符串并打印（从0开始，读 len 个字节）
        System.out.println(new String(data, 0, len));
        System.out.println(address + "..." + port);

        // 7. 释放资源
        socket.close();
    }
}

5. TCP 协议编程

[图示：TCP 客户端与服务器通信流程图——服务器先 accept 等待，客户端发起连接，双方通过 Socket 流通信]

[图示：TCP 数据传输过程——客户端写出数据到服务器，服务器读入数据后写出响应，客户端读入响应]

5.1 编写客户端

步骤：

  1. 创建 Socket 对象，指定服务端的 IP 和端口号（建立连接）
  2. 通过 getOutputStream() 向服务端发送数据
  3. 通过 getInputStream() 读取服务端响应的数据
  4. 关流
java
import java.net.Socket;
import java.io.OutputStream;
import java.io.InputStream;

public class TCPClient {
    public static void main(String[] args) throws Exception {

        // 1. 创建 Socket 对象，指定服务端的 IP 和端口号
        //    执行此行代码时，就会与服务器发起三次握手建立连接
        Socket socket = new Socket("127.0.0.1", 6666);

        // 2. 通过 socket 获取输出流，用于向服务端发送数据
        OutputStream os = socket.getOutputStream();

        // 3. 将字符串转为字节数组，写出给服务端
        os.write("我想下载一个小电影".getBytes());

        // 4. 通过 socket 获取输入流，用于读取服务端响应的数据
        InputStream is = socket.getInputStream();

        // 5. 创建字节数组准备接收数据
        byte[] bytes = new byte[1024];

        // 6. 读取服务端响应，返回实际读到的字节数
        int len = is.read(bytes);

        // 7. 将字节数组转为字符串并打印
        System.out.println(new String(bytes, 0, len));

        // 8. 关流（先关 is 和 os，最后关 socket）
        is.close();
        os.close();
        socket.close();
    }
}

5.2 编写服务端

步骤：

  1. 创建 ServerSocket 对象，设置端口号
  2. 调用 accept() 方法等待客户端连接（阻塞），返回 Socket 对象
  3. 通过 getInputStream() 读取客户端发来的数据
  4. 通过 getOutputStream() 向客户端响应数据
  5. 关闭资源
java
import java.net.ServerSocket;
import java.net.Socket;
import java.io.InputStream;
import java.io.OutputStream;

public class TCPServer {
    public static void main(String[] args) throws Exception {

        // 1. 创建 ServerSocket 对象，绑定端口号 6666（服务端监听此端口）
        ServerSocket ss = new ServerSocket(6666);

        // 2. 调用 accept() 方法，等待客户端连接
        //    此方法会阻塞（程序暂停在这里），直到有客户端连接进来
        //    连接成功后返回一个 Socket 对象，代表与该客户端的连接
        Socket socket = ss.accept();

        // 3. 通过 socket 获取输入流，读取客户端发来的数据
        InputStream is = socket.getInputStream();
        byte[] bytes = new byte[1024];

        // 4. 读取数据，返回实际读到的字节数
        int len = is.read(bytes);

        // 5. 打印客户端发来的内容
        System.out.println(new String(bytes, 0, len));

        // 6. 通过 socket 获取输出流，给客户端发送响应
        OutputStream os = socket.getOutputStream();

        // 7. 向客户端写出响应内容
        os.write("给你一个小电影".getBytes());

        // 8. 关闭资源（注意顺序，先关子流，再关 socket，最后关 ServerSocket）
        os.close();
        is.close();
        socket.close();
        ss.close();
    }
}

6. 文件上传

[图示：文件上传流程图——客户端读本地文件，通过 Socket 流传给服务器，服务器写到硬盘，再响应"上传成功"]

[图示：服务端接收文件的详细步骤——获取流、边读边写、响应客户端]

6.1 文件上传——单线程版本

客户端代码：

java
import java.net.Socket;
import java.io.*;

public class UploadClient {
    public static void main(String[] args) throws Exception {

        // 1. 创建 Socket 对象，连接服务端
        Socket socket = new Socket("127.0.0.1", 6666);

        // 2. 创建 FileInputStream，读取本地要上传的图片
        FileInputStream fis = new FileInputStream("E:\\Idea\\io\\24.jpg");

        // 3. 获取 socket 的输出流，用于将图片数据传给服务端
        OutputStream os = socket.getOutputStream();

        // 4. 边读本地文件，边写给服务端（循环传输，直到文件读完）
        byte[] bytes = new byte[1024];
        int len;
        while ((len = fis.read(bytes)) != -1) {
            os.write(bytes, 0, len);  // 每次只写实际读到的字节数，避免多余数据
        }

        // 5. 给服务端写一个结束标记（告诉服务端文件已经传完了）
        //    不加这个，服务端的 while 循环会永远等待，不知道文件传完没有
        socket.shutdownOutput();

        System.out.println("======以下代码是读取响应的结果======");

        // 6. 获取 socket 的输入流，读取服务端的响应结果
        InputStream is = socket.getInputStream();
        byte[] bytes1 = new byte[1024];
        int len1 = is.read(bytes1);

        // 7. 打印服务端响应内容（比如"上传成功"）
        System.out.println(new String(bytes1, 0, len1));

        // 8. 关流（顺序：先关读写流，再关 socket）
        is.close();
        os.close();
        fis.close();
        socket.close();
    }
}

服务端代码：

java
import java.net.ServerSocket;
import java.net.Socket;
import java.io.*;
import java.util.UUID;

public class UploadServer {
    public static void main(String[] args) throws Exception {

        // 1. 创建 ServerSocket 对象，监听端口 6666
        ServerSocket ss = new ServerSocket(6666);

        // 2. 等待客户端连接
        Socket socket = ss.accept();

        // 3. 获取 socket 的输入流，读取客户端传来的图片数据
        InputStream is = socket.getInputStream();

        // 4. 生成唯一文件名，避免多个客户端上传时文件名冲突
        //    UUID.randomUUID() 生成一个随机的十六进制唯一字符串
        //    再拼上系统时间戳，双重保险确保唯一
        String s = UUID.randomUUID().toString();
        String name = s + System.currentTimeMillis();

        // 5. 创建 FileOutputStream，将接收到的图片写到硬盘上
        FileOutputStream fos = new FileOutputStream("E:\\Idea\\io\\upload\\" + name + ".jpg");

        // 6. 边读客户端数据，边写到本地文件（循环直到 read 返回 -1，即收到结束标记）
        byte[] bytes = new byte[1024];
        int len;
        while ((len = is.read(bytes)) != -1) {
            fos.write(bytes, 0, len);
        }

        System.out.println("======以下代码是给客户端的响应结果======");

        // 7. 获取 socket 的输出流，给客户端发送"上传成功"的响应
        OutputStream os = socket.getOutputStream();
        os.write("上传成功".getBytes());

        // 8. 关流
        os.close();
        fos.close();
        is.close();
        socket.close();
        ss.close();
    }
}

6.2 文件上传服务端——多线程版本

问题： 上面的单线程服务端只能同时处理一个客户端。第二个客户端连接时，必须等第一个处理完。

解决方案： 每来一个客户端，就开一个新线程去处理它，主线程继续等待下一个连接。

java
import java.net.ServerSocket;
import java.net.Socket;
import java.io.*;
import java.util.UUID;

public class UploadServerThread {
    public static void main(String[] args) throws Exception {

        // 1. 创建 ServerSocket 对象，监听端口 6666
        ServerSocket ss = new ServerSocket(6666);

        // 2. 用 while(true) 让服务器持续运行，不断接受新客户端
        while (true) {
            // 3. 等待客户端连接（阻塞），每来一个客户端就会返回一个新 Socket
            Socket socket = ss.accept();

            // 4. 每来一个客户端，开启一个新线程处理它
            //    这样主线程可以立即回去 accept() 等待下一个客户端
            new Thread(new Runnable() {
                @Override
                public void run() {
                    InputStream is = null;
                    FileOutputStream fos = null;
                    OutputStream os = null;
                    try {
                        // 5. 获取输入流，读取客户端传来的图片
                        is = socket.getInputStream();

                        // 6. 生成唯一文件名（UUID + 时间戳）
                        String s = UUID.randomUUID().toString();
                        String name = s + System.currentTimeMillis();

                        // 7. 创建文件输出流，准备写到本地磁盘
                        fos = new FileOutputStream("E:\\Idea\\io\\upload\\" + name + ".jpg");

                        // 8. 边读边写，循环直到客户端发送结束标记
                        byte[] bytes = new byte[1024];
                        int len;
                        while ((len = is.read(bytes)) != -1) {
                            fos.write(bytes, 0, len);
                        }

                        System.out.println("======以下代码是给客户端的响应结果======");

                        // 9. 给客户端发送响应
                        os = socket.getOutputStream();
                        os.write("上传成功".getBytes());

                    } catch (Exception e) {
                        e.printStackTrace(); // 打印异常信息，方便排查问题
                    } finally {
                        // 10. 无论成功还是失败，都要关流（放在 finally 确保一定执行）
                        CloseUtils.closeQ(socket, fos, is, os);
                    }
                }
            }).start(); // 启动线程
        }
    }
}

import java.io.*;
import java.net.Socket;

// 工具类，统一处理关流操作，避免主业务代码中出现大量 try-catch
public class CloseUtils {

    // 私有构造，防止外界 new 这个工具类（工具类不需要实例化）
    private CloseUtils() {}

    // 关闭所有流资源的静态方法（每个都单独 try-catch，一个出错不影响其他）
    public static void closeQ(Socket socket, FileOutputStream fos, InputStream is, OutputStream os) {

        // 关闭输出流
        if (os != null) {
            try {
                os.close();
            } catch (IOException e) {
                throw new RuntimeException(e);
            }
        }

        // 关闭文件输出流
        if (fos != null) {
            try {
                fos.close();
            } catch (IOException e) {
                throw new RuntimeException(e);
            }
        }

        // 关闭输入流
        if (is != null) {
            try {
                is.close();
            } catch (IOException e) {
                throw new RuntimeException(e);
            }
        }

        // 关闭 Socket
        if (socket != null) {
            try {
                socket.close();
            } catch (IOException e) {
                throw new RuntimeException(e);
            }
        }
    }
}

8. 网络编程面试常问

Q：TCP 和 UDP 的区别？

TCP 面向连接，可靠，有三次握手/四次挥手，速度慢；适合文件传输、HTTP、邮件等场景。
UDP 面向无连接，不可靠，速度快；适合视频直播、DNS 查询、游戏实时数据等对速度要求高、允许少量丢包的场景。

Q：为什么 TCP 建立连接需要三次握手，而不是两次？

两次握手只能确保客户端发的能到服务器，但无法确认服务器发的能到客户端。三次握手才能保证双方都具备正常收发数据的能力。

Q：TCP 四次挥手中，为什么客户端最后要等待 2MSL 再关闭？

防止最后一个 ACK 包丢失导致服务器重发 FIN 包，客户端需要在等待时间内能够重新发送确认。

Q：socket.shutdownOutput() 和 socket.close() 的区别？

shutdownOutput() 只关闭输出流，发送一个 FIN 包告诉对方"我发完了"，但连接还在，输入流还能继续读；close() 是完全关闭连接。文件传输完后先调用 shutdownOutput()，等读完响应再调 close()。

1. 概述

text
1. 概述：正则表达式是一个具有特殊规则的字符串
2. 作用：校验（验证手机号、身份证号、密码、用户名、邮箱等）
3. String 中的校验方法：

生活类比： 正则表达式就像一个"模板"，输入的字符串要与这个模板匹配。就像身份证号必须符合特定格式一样（18位，前17位数字，最后一位是数字或X）。

对比演示：不用正则 vs 用正则校验 QQ 号：

java
import java.util.Scanner;

public class RegexDemo {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        String data = scanner.next(); // 读取用户输入

        // 方式一：传统方式（代码冗长）
        // boolean result01 = method01(data);
        // System.out.println("result01 = " + result01);

        // 方式二：使用正则表达式（简洁）
        boolean result02 = method02(data);
        System.out.println("result02 = " + result02);
    }

    // 使用正则表达式校验 QQ 号：不能以0开头，5-15位纯数字
    // [1-9] 表示第一位是1~9中的一个
    // [0-9]{4,14} 表示后面4到14位都是0~9的数字，合计5~15位
    private static boolean method02(String data) {
        boolean result = data.matches("[1-9][0-9]{4,14}");
        return result;
    }

    // 传统方式校验 QQ 号（对比用）
    private static boolean method01(String data) {
        // 检查是否以 0 开头
        if (data.startsWith("0")) {
            return false;
        }
        // 检查是否全是数字
        char[] chars = data.toCharArray();
        for (char aChar : chars) {
            if (aChar < '0' || aChar > '9') {
                return false;
            }
        }
        // 检查长度是否在 5-15 位
        if (data.length() < 5 || data.length() > 15) {
            return false;
        }
        return true;
    }
}

2. 字符类 []

text
java.util.regex.Pattern：正则表达式的编译表示形式
[] 表示一个区间，范围可以自己定义，代表其中的某一个字符

语法示例：
1. [abc]       → 代表 a 或者 b 或者 c 中的一个
2. [^abc]      → 代表除 a、b、c 以外的任何字符（^ 在 [] 内表示非/取反）
3. [a-z]       → 代表 a-z 的所有小写字母中的一个
4. [A-Z]       → 代表 A-Z 的所有大写字母中的一个
5. [0-9]       → 代表 0-9 之间的某一个数字字符
6. [a-zA-Z0-9] → 代表 a-z 或 A-Z 或 0-9 中的任意一个
7. [a-dm-p]    → a 到 d 或 m 到 p 中的任意一个
java
// 字符类示例
private static void method01() {

    // 1. 验证字符串是否以 h 开头，d 结尾，中间是 aeiou 的某一个字符
    //    [h] 匹配 'h'，[aeiou] 匹配元音字母，[d] 匹配 'd'
    boolean result01 = "had".matches("[h][aeiou][d]");
    System.out.println("result01 = " + result01);  // true

    // 2. 验证字符串是否以 h 开头，d 结尾，中间不是 aeiou 的某个字符
    //    [^aeiou] 匹配非元音字母
    boolean result02 = "hyd".matches("[h][^aeiou][d]");
    System.out.println("result02 = " + result02);  // true

    // 3. 验证字符串是否是以 a-z 任意小写字母开头，后面跟 ad
    //    [a-z] 匹配任意小写字母
    boolean result03 = "had".matches("[a-z][a][d]");
    System.out.println("result03 = " + result03);  // true
}

// 逻辑运算符示例
private static void method02() {

    // 1. 要求字符串是小写字母，且不以 [aeiou] 开头，后面跟 ad

4. 预定义字符

text
预定义字符是常用字符类的简写（注意：在 Java 字符串中，\ 需要写成 \\）：

1. "."   → 匹配任何字符（注意不能加 []，不能写成 [.]）
2. "\\d" → 任何数字 [0-9] 的简写（digit，重点）
3. "\\D" → 任何非数字 [^0-9] 的简写
4. "\\s" → 空白字符（空格、制表符等）的简写
5. "\\S" → 非空白字符的简写
6. "\\w" → 单词字符 [a-zA-Z_0-9] 的简写（word，重点）
7. "\\W" → 非单词字符 [^\w] 的简写
java
// 预定义字符示例
private static void method03() {

    // 1. 验证字符串是否是三位数字
    //    写法一：[0-9][0-9][0-9]（详细写法）
    //    写法二：\\d\\d\\d（简写，推荐）
    boolean result01 = "111".matches("\\d\\d\\d");
    System.out.println("result01 = " + result01);  // true

    // 2. 验证手机号：1 开头，第二位是 3、5 或 8，后面 9 位都是 0-9 的数字
    //    [1] 匹配 1，[358] 匹配 3/5/8，\\d 匹配一个数字，共 9 个 \\d
    boolean result02 = "13838381438".matches("[1][358]\\d\\d\\d\\d\\d\\d\\d\\d\\d");
    System.out.println("result02 = " + result02);  // true

    // 3. 验证字符串以 h 开头，d 结尾，中间是任意一个字符
    //    . 匹配任意单个字符
    boolean result03 = "had".matches("[h].[d]");
    System.out.println("result03 = " + result03);  // true
}

5. 数量词

text
数量词用来指定某个字符/模式出现的次数，x 代表前面的字符或表达式：

1. X?     → x 出现 0 次或 1 次（可有可无）
2. X*     → x 出现 0 次到多次（任意次）
3. X+     → x 出现 1 次或多次（至少1次）
4. X{n}   → x 恰好出现 n 次
5. X{n,}  → x 至少出现 n 次（n 及 n 以上）
6. X{n,m} → x 出现 n 到 m 次（包含两端：n <= 次数 <= m）
java
// 数量词示例
private static void method04() {

    // 1. 验证字符串是否是三位数字
    //    \\d{3} 表示数字恰好出现 3 次，等价于 \\d\\d\\d
    boolean result01 = "111".matches("\\d{3}");
    System.out.println("result01 = " + result01);  // true

    // 2. 验证手机号（用数量词简化）
    //    [1] 第一位是1，[358] 第二位是3/5/8，\\d{9} 后面9位数字
    boolean result02 = "13838381438".matches("[1][358]\\d{9}");
    System.out.println("result02 = " + result02);  // true

    // 3. 验证 QQ 号：不能以0开头，都是数字，长度 5-15
    //    [1-9] 第一位是1~9，[0-9]{4,14} 后面4到14位数字，合计5~15位
    boolean result03 = "111111".matches("[1-9][0-9]{4,14}");
    System.out.println("result03 = " + result03);  // true
}

10. 正则表达式面试常问

Q：Java 中 \\d 和 \d 的区别？

Java 字符串中 \\ 才代表一个反斜杠 \，所以 \\d 才是正则中的 \d（匹配数字）。如果写 \d，编译时会报非法转义序列的错误。

Q：matches 和在字符串中搜索有什么区别？

matches 要求整个字符串从头到尾完整匹配正则，相当于自动加了 ^ 和 $。如果只想找子串，需要用 Pattern.matcher() 配合 find() 方法。

Q：常见的手机号正则是什么？

简单版：[1][3-9]\\d{9}（1开头，第二位3~9，后面9位数字） 完整版：1[3-9]\\d{9} 或更复杂的精确到运营商的规则。

1. 模板方法设计模式（Template Method Pattern）

text
核心思想：定义一个操作中的算法骨架，把某些步骤的具体实现延迟到子类中。
         父类明确了固定不变的部分，子类实现变化的部分。

生活类比：饭店吃饭有三步：点菜 → 吃菜 → 买单
  "点菜"和"买单"是固定的（父类实现）
  "吃菜"是每家餐厅不同的（子类各自实现）

抽象父类（骨架）：

java
// 抽象类：定义算法骨架（饭店的通用流程）
public abstract class Hotel {

    // 模板方法：定义了整体流程（固定不变）
    // final 修饰可以防止子类重写整体流程（可选）
    public void eat() {
        System.out.println("点菜");   // 固定步骤1：每家餐厅都要点菜
        eatCai();                      // 变化步骤：吃什么、怎么吃由子类决定
        System.out.println("买单");   // 固定步骤2：每家餐厅都要买单
    }

    // 抽象方法：具体的"吃菜"方式由子类实现
    public abstract void eatCai();
}

子类（具体实现）：

java

        System.out.println("薄饼");
        System.out.println("放鸭肉");
        System.out.println("酱");
        System.out.println("葱丝");

        System.out.println("放辣椒油");
        System.out.println("倒到大碗中吃");
    }
}

2. 单例模式（Singleton Pattern）

text
目的：
  单（一个）例（实例/对象）
  让一个类只产生一个对象，供整个程序（全局）使用

分类：
  a. 饿汉式：迫不及待，类加载时就创建好对象
  b. 懒汉式：懒得创建，第一次用到时才创建

生活类比： 单例就像一个公司只有一个 CEO，不管谁来问"你们 CEO 是谁"，都是同一个人。

2.1 饿汉式

text
特点：类加载时就创建对象，不管用不用得到
优点：线程安全（天然安全，JVM 保证类只加载一次）
缺点：如果对象一直不用，会浪费内存（饿汉式说：管它，先创建了再说！）
java
public class Singleton {

    // 1. 私有化构造方法，防止外部随意 new 对象
    //    这是单例模式的第一步，让外界无法自己创建实例
    private Singleton() {}

    // 2. 在类的内部创建一个唯一的实例（静态的，随着类的加载而创建）
    //    private：不让外界直接访问这个对象（必须通过 get 方法拿）
    //    static：属于类本身，不属于某个对象，保证只有一份
    private static Singleton singleton = new Singleton();

    // 3. 提供一个公共的静态方法，让外界通过此方法获取唯一实例
    //    static：让外界可以不创建对象就调用这个方法
    public static Singleton getSingleton() {
        return singleton;  // 返回类内部唯一的那个实例
    }
}

测试（无论调用多少次，都是同一个对象）：

java
public class SingletonTest {
    public static void main(String[] args) {
        // 多次调用 getSingleton()，每次返回的都是同一个对象
        // 打印地址都相同
        for (int i = 0; i < 10; i++) {
            Singleton singleton = Singleton.getSingleton();
            System.out.println(singleton);  // 10 次打印同一个地址
        }
    }
}

2.2 懒汉式（双重检查锁）

text
特点：第一次用到时才创建对象
优点：节省内存（不用的话不创建）
缺点：多线程环境下需要加锁处理（否则可能创建出多个对象）
     懒汉式说：我太懒了，等你真正用到我再说！
     
双重检查锁（DCL，Double-Checked Locking）：
  为了兼顾线程安全和性能，先判断再加锁，加锁后再判断一次
java
public class Singleton1 {

    // 1. 私有化构造方法
    private Singleton1() {}

    // 2. 声明实例变量，初始值为 null（懒加载，暂不创建）
    //    volatile 关键字：防止指令重排序（保证多线程下的可见性和有序性）
    private static volatile Singleton1 singleton1 = null;

    // 3. 提供获取实例的公共静态方法（双重检查锁）
    public static Singleton1 getSingleton1() {

        // 第一次检查：如果已经创建了，直接返回（避免每次都抢锁，提升性能）
        if (singleton1 == null) {

            // 加锁：同一时刻只允许一个线程进入
            synchronized (Singleton1.class) {

                // 第二次检查：防止多个线程同时通过第一次检查后，重复创建对象
                if (singleton1 == null) {
                    singleton1 = new Singleton1();  // 只创建一次
                }
            }
        }
        return singleton1;  // 返回唯一实例
    }
}

2.3 单例模式小结

text
无论饿汉式还是懒汉式，核心都是两步：
  1. 构造私有（private 构造方法）→ 外界无法随意 new 对象
  2. 对象私有且静态（private static 成员变量）→ 类内部持有唯一实例，且不直接暴露

区别对比：
  饿汉式：static 变量直接初始化 → 类加载时创建 → 线程安全但可能浪费内存
  懒汉式：static 变量初始为 null → 第一次使用时创建 → 节省内存但多线程需加锁

3. 设计模式常见报错

情况 说明 解决方法
多线程下懒汉式创建了多个实例 没有同步处理，多个线程同时通过了 null 检查 使用双重检查锁，同时给变量加 volatile
单例被反射破坏 通过反射可以访问私有构造方法 在构造方法中加判断，如果已存在实例则抛出异常
单例被反序列化破坏 反序列化会创建新对象 添加 readResolve() 方法返回已有实例

4. 设计模式面试常问

Q：单例模式饿汉式和懒汉式的区别？

饿汉式在类加载时就创建对象，线程安全但可能浪费内存；懒汉式在第一次使用时创建对象，节省内存但多线程环境下需要加双重检查锁 + volatile。

Q：双重检查锁中为什么需要 volatile？

new Singleton1() 在 JVM 底层分为三步：分配内存 → 初始化对象 → 将引用指向内存地址。JVM 可能对这三步进行指令重排序，导致另一个线程拿到的是未初始化完成的对象。volatile 禁止指令重排序，确保对象完全初始化后才对外可见。

Q：怎么防止单例被反射破坏？

在私有构造方法中加判断：如果实例已经存在，就抛出异常，拒绝通过反射创建新实例。

Q：模板方法模式的应用场景？

多个类有相同的流程骨架，只有某些步骤的实现不同时使用。常见于 JDK 中的 AbstractList（提供了通用骨架，具体 get 方法由子类实现）。

第四部分：Lombok

1. Lombok 介绍

text
1. 作用：简化 JavaBean 开发，自动生成样板代码
2. 使用步骤：
   a. 安装 Lombok 插件（IDEA 2022+ 自带，无需手动安装）
   b. 在项目中导入 Lombok 的 jar 包（Maven 项目在 pom.xml 中添加依赖）
   c. 修改 IDEA 设置：开启"注解处理器"（Annotation Processing）

[图示：Lombok 工作原理示意图——源码中只有注解，编译生成的字节码文件中自动包含 getter/setter/构造方法等]

原理： Lombok 在编译阶段通过注解处理器（APT）自动生成代码，注入到字节码文件中。
源码（.java 文件）中看不到 getter/setter，但编译后的字节码（.class 文件）中有。

生活类比： Lombok 就像一个"代码速记员"，你只需要在黑板上写一个简单符号（注解），它就帮你自动扩写出完整的代码。

2. Lombok 常用注解

@Getter 和 @Setter

  • 作用：自动生成成员变量的 get 和 set 方法
  • 写在成员变量上：只对当前变量有效
  • 写在类上：对类中所有成员变量有效
  • 注意：静态成员变量无效（静态变量不走 getter/setter 的逻辑）

@ToString

  • 作用：自动生成 toString() 方法
  • 只能写在类上
  • 生成的 toString() 会包含类名和所有字段的值

@NoArgsConstructor 和 @AllArgsConstructor

  • @NoArgsConstructor：生成无参数构造方法
  • @AllArgsConstructor：生成全参数构造方法（所有字段都作为参数）
  • 只能写在类上

@EqualsAndHashCode

  • 作用：自动生成 hashCode() 和 equals() 方法
  • 只能写在类上
  • 两个对象字段值相同时，equals 返回 true

@Data

  • 作用：一站式注解，相当于同时加了：
    • @Getter + @Setter（所有字段）
    • @ToString
    • @EqualsAndHashCode
    • @NoArgsConstructor（无参构造）
  • 只能写在类上
  • 注意：@Data 只生成无参构造，如果需要全参构造要额外加 @AllArgsConstructor

3. Lombok 代码示例

JavaBean 实体类（使用 Lombok）：

java
import lombok.Data;
import lombok.AllArgsConstructor;
import lombok.NoArgsConstructor;

// @Data：自动生成 getter/setter/toString/hashCode/equals/无参构造
@Data
// @AllArgsConstructor：自动生成全参构造（有几个字段就有几个参数）
@AllArgsConstructor
// @NoArgsConstructor：显式生成无参构造
// （加了 @AllArgsConstructor 后如果还需要无参构造，需要加这个）
@NoArgsConstructor
public class Person {
    private String name;   // 姓名字段
    private Integer age;   // 年龄字段
    // 不需要写 getter/setter/构造/toString，Lombok 自动生成
}

使用 Lombok 生成的 Person 类：

java
public class LombokTest {
    public static void main(String[] args) {

        // 使用无参构造 + setter（@NoArgsConstructor + @Setter 生成）
        Person person = new Person();
        person.setName("涛哥");   // Lombok 自动生成的 setter
        person.setAge(10);        // Lombok 自动生成的 setter

        // 使用 Lombok 自动生成的 getter 获取属性值
        System.out.println(person.getName() + "..." + person.getAge());

        System.out.println("================");

        // 使用全参构造（@AllArgsConstructor 生成）
        Person p1 = new Person("三上", 28);
        System.out.println(p1.getName() + "..." + p1.getAge());
        // toString() 也是 Lombok 自动生成的：
        System.out.println(p1);  // 输出：Person(name=三上, age=28)
    }
}

4. Lombok 常见报错

报错信息 原因 解决方法
cannot find symbol: method getName() Lombok 插件未安装，编译时找不到 getter 安装 Lombok 插件，或重新启用注解处理器
加了 @Data 还是没有 setter 字段是 final 修饰的（final 字段只有 getter，没有 setter） 去掉 final，或不要对该字段生成 setter
加了 @AllArgsConstructor 后无参构造消失了 Java 默认只有在没有任何构造方法时才自动生成无参构造 同时加 @NoArgsConstructor
@Data 生成的 equals 比较结果不对 @Data 默认用所有字段比较，如果有字段不想参与比较需要排除 使用 @EqualsAndHashCode(exclude = "字段名")

5. Lombok 面试常问

Q：Lombok 的原理是什么？

Lombok 利用 Java 的注解处理器（APT，Annotation Processing Tool）在编译期介入，分析注解并修改 AST（抽象语法树），从而在编译后的字节码中注入生成的代码。源码里没有这些方法，但字节码里有。

Q：生产环境推荐用 Lombok 吗？

有争议。优点是减少样板代码，提高开发效率；缺点是增加了对 Lombok 的依赖，调试时 IDE 需要插件支持，某些场景下（如继承）行为不直观。目前业界主流项目大量使用 Lombok，推荐使用。

Q：@Data 包含哪些注解的功能？

等价于 @Getter + @Setter + @ToString + @EqualsAndHashCode + @RequiredArgsConstructor（生成 final 字段的构造，如果没有 final 字段则是无参构造）。
