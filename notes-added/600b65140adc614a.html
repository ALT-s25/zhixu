二、什么是 Docker ⭐

2.1 解决了什么问题

问题：本地能跑，服务器跑不起来（依赖版本不一致）。

text
开发机：jdk8 + mysql5.7 + redis3.0
服务器：jdk11 + mysql8.0 + redis6.0
结果：运行失败！

Docker 的解法：把应用和所有依赖打包成镜像，到哪里都是同样的环境。

2.2 Docker vs 虚拟机

虚拟机 Docker
技术 硬件虚拟化（Hypervisor） 进程隔离（namespace/cgroup）
启动时间 分钟级 秒级
体积 GB MB
性能 较差（隔离完整） 接近原生
隔离性 强 较强

三、核心概念 ⭐

text
Docker 架构
                     ┌───────────────────┐
                     │  Docker Hub（仓库）│
                     └────────┬──────────┘
                        pull/push
                              ↓
  ┌────────────────────────────────────────────┐
  │            Docker Host（服务器）            │
  │                                            │
  │  Images（镜像）                             │
  │   mysql:5.7  nginx:latest  redis:6.0        │
  │       ↓ run                                │
  │  Containers（容器）                         │
  │   [mysql-c1]  [nginx-c1]  [redis-c1]       │
  └────────────────────────────────────────────┘
  ↑ Docker CLI 操作
概念 说明
镜像（Image） 只读模板，包含应用和依赖
容器（Container） 镜像的运行实例，可以启停删
仓库（Registry） 存储镜像（DockerHub / 私有仓库）

四、镜像操作 ⭐⭐

bash
# 拉取镜像
docker pull nginx              # 最新版
docker pull nginx:1.23         # 指定版本

# 查看镜像
docker images

# 删除镜像
docker rmi nginx:latest

# 保存镜像到本地
docker save -o nginx.tar nginx:latest

# 从本地加载镜像
docker load -i nginx.tar

# 查找镜像（DockerHub）
docker search redis

五、容器操作 ⭐⭐

5.1 基本命令

bash
# 创建并运行容器
docker run -d \             # -d 后台运行
  --name nginx \            # 容器名称
  -p 80:80 \                # 端口映射（宿主:容器）
  nginx

# 查看运行中容器
docker ps

# 查看所有容器（含停止的）
docker ps -a

# 停止/启动/重启
docker stop nginx
docker start nginx
docker restart nginx

# 删除容器（先停止）
docker rm nginx
docker rm -f nginx          # 强制删除（无需先停止）

# 查看容器日志
docker logs nginx
docker logs -f nginx        # 持续输出

# 进入容器
docker exec -it nginx bash  # 进入（exit 退出不停止容器）

5.2 运行 MySQL 容器示例

bash
docker run -d \
  --name mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \     # 环境变量
  -v /data/mysql/data:/var/lib/mysql \ # 数据卷（持久化）
  -v /data/mysql/conf:/etc/mysql/conf.d \
  mysql:5.7

六、数据卷 ⭐⭐

6.1 为什么需要数据卷

容器删除 → 容器内数据也丢失！数据卷解决容器数据持久化和宿主机共享问题。

6.2 数据卷操作

bash
# 创建数据卷
docker volume create html

# 查看数据卷列表
docker volume ls

# 查看数据卷详情（挂载路径）
docker volume inspect html

# 删除数据卷
docker volume rm html
docker volume prune    # 删除未使用的数据卷

6.3 挂载方式

方式一：具名挂载（volume）

bash
docker run -d \
  --name nginx \
  -p 80:80 \
  -v html:/usr/share/nginx/html \   # html 是 volume 名
  nginx

方式二：绑定挂载（bind mount，更常用）

bash
docker run -d \
  --name nginx \
  -p 80:80 \
  -v /home/nginx/html:/usr/share/nginx/html \  # 宿主机路径:容器路径
  nginx

💡 区别：

  • Volume 由 Docker 管理（路径在 /var/lib/docker/volumes/）
  • Bind Mount 指定宿主机路径，更直观，推荐开发使用

七、Dockerfile 自定义镜像 ⭐⭐

7.1 镜像层结构

text
Ubuntu 基础层
    ↓
安装 JRE 层
    ↓
拷贝 jar 包层
    ↓
设置启动命令层

相同层复用，节省空间。

7.2 Dockerfile 语法

dockerfile
# 基础镜像
FROM ubuntu:20.04

# 执行命令（构建时）
RUN apt-get install -y java-8-jdk

# 设置工作目录
WORKDIR /app

# 拷贝文件（宿主机 → 镜像）
COPY app.jar /app/app.jar
# ADD 会自动解压 tar.gz

# 暴露端口（声明，不实际映射）
EXPOSE 8080

# 环境变量
ENV TZ=Asia/Shanghai

# 容器启动时执行的命令
ENTRYPOINT ["java", "-jar", "app.jar"]
# CMD ["java", "-jar", "app.jar"]  # 可被 docker run 覆盖

7.3 实际项目：构建 Java 镜像

dockerfile
# 推荐：基于 java8 基础镜像（更简洁）
FROM java:8-alpine

COPY ./app.jar /tmp/app.jar

EXPOSE 8080

ENTRYPOINT java -jar /tmp/app.jar
bash
# 构建镜像
docker build -t myapp:1.0 .    # -t 名称:标签，. 是 Dockerfile 所在路径

# 推送到仓库
docker push myapp:1.0

八、Docker Compose ⭐⭐⭐

8.1 什么是 Docker Compose

批量管理多个容器，用一个 docker-compose.yml 文件定义所有服务，一条命令启动整个应用。

8.2 docker-compose.yml 语法

yaml
version: "3.8"

services:
  mysql:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: "123456"
    volumes:
      - /tmp/mysql/data:/var/lib/mysql
      - /tmp/mysql/conf:/etc/mysql/conf.d
    ports:
      - "3306:3306"
    networks:
      - hm-net

  redis:
    image: redis:latest
    ports:
      - "6379:6379"
    networks:
      - hm-net

  userservice:
    build: ./user-service    # 基于 Dockerfile 构建
    ports:
      - "8081:8081"
    networks:
      - hm-net
    depends_on:
      - mysql                # 依赖 mysql 先启动
      - redis

networks:
  hm-net:
    driver: bridge

8.3 常用命令

bash
# 启动所有服务（-d 后台）
docker-compose up -d

# 停止并删除容器
docker-compose down

# 查看日志
docker-compose logs -f userservice

# 重新构建
docker-compose build

# 重启某个服务
docker-compose restart userservice

# 查看运行状态
docker-compose ps

九、私有镜像仓库（Docker Registry）

bash
# 启动本地仓库
docker run -d \
  --name registry \
  -p 5000:5000 \
  -v /data/registry:/var/lib/registry \
  registry

# 推送镜像到私有仓库
docker tag myapp:1.0 192.168.150.101:5000/myapp:1.0
docker push 192.168.150.101:5000/myapp:1.0

# 拉取
docker pull 192.168.150.101:5000/myapp:1.0

十一、面试常问 ⭐⭐

💡 Docker 和虚拟机有什么区别？

  • Docker 进程级隔离，共享 OS 内核，轻量快
  • 虚拟机硬件虚拟化，含完整 OS，重但隔离更强

💡 数据卷是什么？ 将宿主机目录挂载到容器，实现数据持久化和容器间共享。

💡 Dockerfile 中 COPY 和 ADD 的区别？ ADD 会自动解压 tar 包，其他与 COPY 相同。推荐用 COPY（更清晰）。

💡 ENTRYPOINT 和 CMD 的区别？

  • CMD：可被 docker run 后的命令覆盖
  • ENTRYPOINT：不会被覆盖，docker run 后的命令作为参数传入

💡 Docker Compose 的作用？ 用 YAML 文件定义多容器应用，一条命令批量启停。

  • Docker Compose 编排多容器

✅ 易错点：

  • 端口映射格式：宿主机端口:容器端口

  • 删除容器前需先 stop，或 rm -f
  • 数据卷删容器不会删，volume prune 才删
