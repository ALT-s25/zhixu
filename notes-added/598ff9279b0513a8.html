1. 多表关系概述

1.1 为什么要多张表？

反例（全放一张表）：

order_id customer_name customer_phone product_name product_price
1 张三 138xxx 苹果手机 8999
2 张三 138xxx 耳机 299
3 李四 139xxx 苹果手机 8999

问题：

  • 数据冗余：张三的手机号存了两遍，苹果手机的价格存了两遍
  • 更新异常：张三换号码，要改所有行
  • 删除异常：删掉订单1，苹果手机信息也没了

正例（拆成多张表）：

text
customers 表：customer_id, name, phone
products 表：product_id, name, price
orders 表：order_id, customer_id, product_id（通过 ID 引用其他表）

1.2 三种多表关系

一对多（最常见）

一个部门有多个员工，一个员工只属于一个部门。

text
dept 表：dept_id, dept_name
emp 表：emp_id, emp_name, dept_id（外键指向 dept.dept_id）

多对多

一个学生选多门课，一门课被多个学生选。

text
student 表：student_id, name
course 表：course_id, name
student_course 表（中间表）：student_id, course_id（联合主键）

中间表是多对多关系的标准解法。

一对一

一个人只有一个身份证，一个身份证只属于一个人（相对少见）。

text
person 表：person_id, name
id_card 表：id_card_id, card_no, person_id UNIQUE（外键+唯一约束）

2. 笛卡尔积问题

2.1 什么是笛卡尔积

两张表直接查询，不加连接条件，会返回 M×N 行（所有组合），这就是笛卡尔积，也叫"交叉连接"。

sql
-- 建立测试数据（下面所有例子都用这组数据）
CREATE DATABASE multi_query_demo;
USE multi_query_demo;

-- 部门表
CREATE TABLE dept (
    dept_id   INT         PRIMARY KEY AUTO_INCREMENT,
    dept_name VARCHAR(50) NOT NULL,
    location  VARCHAR(100)
);

-- 员工表
CREATE TABLE emp (
    emp_id    INT          PRIMARY KEY AUTO_INCREMENT,
    emp_name  VARCHAR(50)  NOT NULL,
    dept_id   INT,                        -- 注意：不加外键，方便演示
    salary    DECIMAL(10,2) DEFAULT 0,
    manager_id INT                        -- 上级的 emp_id（自连接用）
);

-- 薪资等级表
CREATE TABLE sal_grade (
    grade      INT,
    low_sal    DECIMAL(10,2),
    high_sal   DECIMAL(10,2)
);

-- 插入部门数据
INSERT INTO dept VALUES
(1, '技术部', '北京'),
(2, '市场部', '上海'),
(3, '财务部', '广州'),
(4, '人事部', '深圳');   -- 故意插一个没有员工的部门

-- 插入员工数据
INSERT INTO emp VALUES
(1,  '刘备',  1, 20000, NULL),   -- 技术部，无上级
(2,  '关羽',  1, 15000, 1),      -- 技术部，上级是刘备
(3,  '张飞',  1, 12000, 1),      -- 技术部，上级是刘备
(4,  '诸葛亮', 2, 18000, 1),     -- 市场部，上级是刘备
(5,  '赵云',  2, 14000, 4),      -- 市场部，上级是诸葛亮
(6,  '马超',  3, 11000, 1),      -- 财务部，上级是刘备
(7,  '黄忠',  NULL, 9000, 1);    -- 部门为 NULL（无部门员工）

-- 插入薪资等级
INSERT INTO sal_grade VALUES
(1,  0,      5000),
(2,  5001,   10000),
(3,  10001,  15000),
(4,  15001,  20000),
(5,  20001,  99999);

2.2 笛卡尔积示例

sql
-- 错误示范：没有连接条件，产生笛卡尔积
SELECT emp.emp_name, dept.dept_name
FROM emp, dept;
-- 结果：7(员工) × 4(部门) = 28 行，大量无意义数据！

-- 正确做法：加连接条件
SELECT emp.emp_name, dept.dept_name
FROM emp, dept
WHERE emp.dept_id = dept.dept_id;  -- 隐式内连接

3. 内连接 INNER JOIN

3.1 核心概念

内连接只返回两张表都能匹配上的行。 类比：两个班的花名册取交集，两边都有的人才算。

text
emp 表：有 7 名员工
dept 表：有 4 个部门

内连接结果：只有 dept_id 在两表都存在的行
- 黄忠（dept_id=NULL）→ 不出现
- 人事部（没有员工）→ 不出现

3.2 语法

sql
-- 显式内连接（推荐）
SELECT 列名
FROM 表1
INNER JOIN 表2 ON 连接条件;   -- INNER 可以省略，直接 JOIN

-- 隐式内连接（老写法）
SELECT 列名
FROM 表1, 表2
WHERE 连接条件;

3.3 完整示例

sql
-- 示例1：查询员工姓名和所在部门
SELECT
    e.emp_name  AS '员工姓名',
    d.dept_name AS '部门名称',
    d.location  AS '地点'
FROM emp e
INNER JOIN dept d ON e.dept_id = d.dept_id;
-- 结果：6行（黄忠因 dept_id=NULL 被排除）

-- 示例2：查询员工姓名、部门、薪资等级
SELECT
    e.emp_name  AS '员工',
    d.dept_name AS '部门',
    e.salary    AS '薪资',
    sg.grade    AS '薪资等级'
FROM emp e
INNER JOIN dept d       ON e.dept_id = d.dept_id                 -- 连接部门
INNER JOIN sal_grade sg ON e.salary BETWEEN sg.low_sal AND sg.high_sal;  -- 连接薪资等级
-- 多表连接：依次 JOIN 即可

-- 示例3：带条件过滤的内连接
SELECT
    e.emp_name,
    d.dept_name,
    e.salary
FROM emp e
INNER JOIN dept d ON e.dept_id = d.dept_id
WHERE d.dept_name = '技术部'    -- 过滤：只看技术部
  AND e.salary > 10000;         -- 过滤：薪资大于 10000

4. 外连接 LEFT/RIGHT JOIN

4.1 核心概念

外连接在内连接基础上，额外保留某一侧的所有记录，即使对面没有匹配。

类型 保留哪边 说明
LEFT JOIN 左表全部保留 右表无匹配的行，右表列显示 NULL
RIGHT JOIN 右表全部保留 左表无匹配的行，左表列显示 NULL

类比：

  • LEFT JOIN：以左表为基础，能拼上的拼，拼不上的右边填 NULL
  • RIGHT JOIN：以右表为基础，能拼上的拼，拼不上的左边填 NULL

4.2 LEFT JOIN 示例

sql
-- 查询所有员工（包括没有部门的员工）
SELECT
    e.emp_name  AS '员工姓名',
    d.dept_name AS '部门名称'
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.dept_id;
-- 结果：7行（黄忠也出现，dept_name 显示 NULL）

-- 查找没有部门的员工
SELECT
    e.emp_name  AS '无部门员工'
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.dept_id
WHERE d.dept_id IS NULL;   -- 右表为 NULL，说明左表没有匹配
-- 结果：黄忠

-- 查询所有部门及其员工数（包括空部门）
SELECT
    d.dept_name     AS '部门',
    COUNT(e.emp_id) AS '员工数'   -- COUNT 对 NULL 不计数
FROM dept d
LEFT JOIN emp e ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name;
-- 结果：4行（人事部员工数为 0）

4.3 RIGHT JOIN 示例

sql
-- 查询所有部门（包括没有员工的部门）
-- 以 dept 为右表，所有部门都保留
SELECT
    e.emp_name  AS '员工姓名',
    d.dept_name AS '部门名称'
FROM emp e
RIGHT JOIN dept d ON e.dept_id = d.dept_id;
-- 结果：7行（人事部出现，emp_name 显示 NULL）

-- 等价的 LEFT JOIN 写法（推荐统一用 LEFT JOIN，更直观）
SELECT
    e.emp_name  AS '员工姓名',
    d.dept_name AS '部门名称'
FROM dept d
LEFT JOIN emp e ON d.dept_id = e.dept_id;
-- 和上面 RIGHT JOIN 结果相同

建议：统一使用 LEFT JOIN，把"主表"放在左边，可读性更好。

5. 全连接 FULL JOIN

5.1 核心概念

全连接 = LEFT JOIN ∪ RIGHT JOIN，保留两张表所有记录，能匹配上的合并，匹配不上的填 NULL。

text
LEFT JOIN 结果 + RIGHT JOIN 结果（去掉重复行）

MySQL 不支持 FULL OUTER JOIN 语法，需要用 UNION 模拟。

5.2 用 UNION 模拟全连接

sql
-- 全连接：所有员工 + 所有部门（包括无部门员工和无员工部门）
SELECT
    e.emp_name  AS '员工',
    d.dept_name AS '部门'
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.dept_id   -- 左连接：所有员工

UNION                                        -- 合并去重

SELECT
    e.emp_name  AS '员工',
    d.dept_name AS '部门'
FROM emp e
RIGHT JOIN dept d ON e.dept_id = d.dept_id; -- 右连接：所有部门
-- 结果：8行（7名员工 + 1个空部门"人事部"）

6. 自连接

6.1 核心概念

自连接：一张表和自己连接，通常用于处理层级关系（如组织架构、分类树）。

类比：员工表里有"上级 ID"，查"员工和他上级的名字"，就需要把员工表和自己 JOIN。

技巧：给同一张表起两个别名，把它当成两张表来看。

6.2 完整示例

sql
-- 查询每个员工和他的直接上级
SELECT
    e.emp_name  AS '员工',
    m.emp_name  AS '上级'
FROM emp e                              -- e：员工
LEFT JOIN emp m ON e.manager_id = m.emp_id;  -- m：上级（同一张表，别名不同）
-- LEFT JOIN 保证刘备（无上级）也出现，上级显示 NULL

-- 结果：
-- 刘备   NULL（没有上级）
-- 关羽   刘备
-- 张飞   刘备
-- 诸葛亮 刘备
-- 赵云   诸葛亮
-- 马超   刘备
-- 黄忠   刘备

-- 查询下级比上级薪资还高的员工
SELECT
    e.emp_name  AS '员工',
    e.salary    AS '员工薪资',
    m.emp_name  AS '上级',
    m.salary    AS '上级薪资'
FROM emp e
INNER JOIN emp m ON e.manager_id = m.emp_id  -- 内连接，只看有上级的
WHERE e.salary > m.salary;                   -- 下级薪资 > 上级薪资

7. 联合查询 UNION / UNION ALL

7.1 核心概念

UNION 把多条 SELECT 的结果纵向合并（上下拼接），每条 SELECT 的列数和类型必须一致。

关键字 是否去重 性能
UNION 去重（相同行只保留一行） 较慢（需要排序去重）
UNION ALL 不去重，全部保留 快

类比：

  • UNION：合并两个班花名册，同名同姓的合并成一个
  • UNION ALL：直接把两个花名册叠放，不管重复

7.2 完整示例

sql
-- 示例1：查询薪资 < 10000 或薪资 > 18000 的员工
-- 方式一：OR 条件
SELECT emp_name, salary FROM emp
WHERE salary < 10000 OR salary > 18000;

-- 方式二：UNION（对于复杂条件可读性更好）
SELECT emp_name, salary FROM emp WHERE salary < 10000
UNION
SELECT emp_name, salary FROM emp WHERE salary > 18000;

-- 示例2：合并员工和部门名称列表（列名取第一条 SELECT 的列名）
SELECT emp_name AS '名称', '员工' AS '类型' FROM emp
UNION ALL
SELECT dept_name AS '名称', '部门' AS '类型' FROM dept;

-- 示例3：UNION 去重效果
SELECT emp_name FROM emp WHERE dept_id = 1
UNION
SELECT emp_name FROM emp WHERE salary > 12000;
-- 刘备、关羽同时满足两个条件，UNION 只出现一次

SELECT emp_name FROM emp WHERE dept_id = 1
UNION ALL
SELECT emp_name FROM emp WHERE salary > 12000;
-- UNION ALL：刘备、关羽会出现两次

8. 子查询

8.1 核心概念

子查询：一条 SQL 语句嵌套在另一条 SQL 里作为数据来源或条件。 外层 SQL 叫"主查询"，括号里的叫"子查询"。

类比：你先查出"技术部的 dept_id"，再用这个 ID 查员工。 子查询就是把这两步合成一步，括号里先算。

8.2 按结果分类

类型 返回结果 配合使用
标量子查询 一行一列（单个值） =、>、< 等比较运算符
行子查询 一行多列 =、!=、IN 配合 ()
列子查询 多行一列（一组值） IN、NOT IN、ANY、ALL
表子查询 多行多列 当作临时表放在 FROM 子句

8.3 标量子查询（最常见）

子查询返回单一值，用于比较条件。

sql
-- 查询薪资高于平均薪资的员工
SELECT emp_name, salary
FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);  -- 子查询先算平均薪资
-- 子查询结果：约 14143（单一值）
-- 主查询：salary > 14143

-- 查询和"诸葛亮"同一部门的员工
SELECT emp_name, dept_id
FROM emp
WHERE dept_id = (SELECT dept_id FROM emp WHERE emp_name = '诸葛亮')
  AND emp_name != '诸葛亮';   -- 排除诸葛亮自己

-- 查询最高薪资的员工
SELECT emp_name, salary
FROM emp
WHERE salary = (SELECT MAX(salary) FROM emp);

8.4 列子查询（多行单列）

子查询返回一列多行，配合 IN、NOT IN、ANY、ALL 使用。

sql
-- 查询在"技术部"或"市场部"工作的员工
SELECT emp_name, dept_id
FROM emp
WHERE dept_id IN (
    SELECT dept_id FROM dept
    WHERE dept_name IN ('技术部', '市场部')
);
-- 子查询返回：(1, 2)
-- 主查询：dept_id IN (1, 2)

-- 查询不在任何有员工的部门工作的员工（dept 表中没有该部门）
SELECT emp_name
FROM emp
WHERE dept_id NOT IN (
    SELECT dept_id FROM dept WHERE dept_id IS NOT NULL
);

-- ANY：薪资高于技术部任意一名员工（即高于技术部最低薪资）
SELECT emp_name, salary
FROM emp
WHERE salary > ANY (
    SELECT salary FROM emp WHERE dept_id = 1
);

-- ALL：薪资高于技术部所有员工（即高于技术部最高薪资）
SELECT emp_name, salary
FROM emp
WHERE salary > ALL (
    SELECT salary FROM emp WHERE dept_id = 1
);

8.5 行子查询（单行多列）

子查询返回一行多列，用于多列同时匹配。

sql
-- 查询和"关羽"薪资相同、上级也相同的员工
SELECT emp_name, salary, manager_id
FROM emp
WHERE (salary, manager_id) = (
    SELECT salary, manager_id FROM emp WHERE emp_name = '关羽'
)
AND emp_name != '关羽';

8.6 表子查询（多行多列）

子查询返回多行多列，当作临时表使用（必须给别名）。

sql
-- 把高薪员工子查询当作临时表，再连接部门
SELECT t.emp_name, t.salary, d.dept_name
FROM (
    SELECT emp_id, emp_name, dept_id, salary
    FROM emp
    WHERE salary > 12000               -- 子查询：先过滤高薪员工
) t                                    -- 必须给子查询一个别名
INNER JOIN dept d ON t.dept_id = d.dept_id;

-- 表子查询作为 FROM（派生表）
SELECT dept_id, AVG(salary) AS avg_sal
FROM (
    SELECT dept_id, salary FROM emp WHERE dept_id IS NOT NULL
) t
GROUP BY dept_id;

8.7 WHERE vs HAVING 中的子查询

sql
-- WHERE 中的子查询（过滤行）
SELECT emp_name, salary
FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);

-- HAVING 中的子查询（过滤分组后的结果）
SELECT dept_id, AVG(salary) AS avg_sal
FROM emp
GROUP BY dept_id
HAVING AVG(salary) > (SELECT AVG(salary) FROM emp);  -- 高于全公司平均薪资的部门

9. IN / EXISTS / ANY / ALL

9.1 IN vs EXISTS

IN：先执行子查询，把结果集拿出来，再逐行比较。 适合：子查询结果集小的情况。

EXISTS：对主查询每一行，执行一次子查询，看是否有结果（有→保留，无→丢弃）。 适合：主查询结果集小、子查询结果集大的情况。

sql
-- IN 写法：查询有员工的部门
SELECT dept_name
FROM dept
WHERE dept_id IN (
    SELECT DISTINCT dept_id FROM emp WHERE dept_id IS NOT NULL
);

-- EXISTS 写法：等价查询
SELECT dept_name
FROM dept d
WHERE EXISTS (
    SELECT 1 FROM emp e WHERE e.dept_id = d.dept_id  -- 能找到匹配行就返回 TRUE
);
-- EXISTS 里写什么无所谓，只看是否有结果，通常写 SELECT 1 表示"只要存在"

-- NOT IN vs NOT EXISTS
-- 注意：NOT IN 遇到 NULL 值会有坑！
-- 如果子查询结果含 NULL，NOT IN 结果为空集
SELECT dept_name FROM dept
WHERE dept_id NOT IN (SELECT dept_id FROM emp);  -- 坑！emp.dept_id 有 NULL，结果为空

-- NOT EXISTS 更安全
SELECT dept_name FROM dept d
WHERE NOT EXISTS (
    SELECT 1 FROM emp e WHERE e.dept_id = d.dept_id
);

9.2 NOT IN 的 NULL 坑

sql
-- 演示 NOT IN 的 NULL 陷阱
-- emp 表中有一行 dept_id = NULL

-- 预期：找出没有员工的部门（dept_id=4 的人事部）
SELECT dept_name FROM dept
WHERE dept_id NOT IN (SELECT dept_id FROM emp);
-- 实际结果：空！因为 NOT IN (1, 2, 3, NULL) 中含 NULL，整个条件为 UNKNOWN

-- 修复方案1：过滤掉子查询中的 NULL
SELECT dept_name FROM dept
WHERE dept_id NOT IN (
    SELECT dept_id FROM emp WHERE dept_id IS NOT NULL
);

-- 修复方案2：改用 NOT EXISTS（推荐）
SELECT dept_name FROM dept d
WHERE NOT EXISTS (
    SELECT 1 FROM emp e WHERE e.dept_id = d.dept_id
);

9.3 ANY 和 ALL

sql
-- ANY（SOME）：满足子查询中任意一个值即可
-- salary > ANY(...) 等价于 salary > MIN(子查询结果)
SELECT emp_name, salary FROM emp
WHERE salary > ANY (SELECT salary FROM emp WHERE dept_id = 1);
-- 只要比技术部某人薪资高就行

-- ALL：必须满足子查询中所有值
-- salary > ALL(...) 等价于 salary > MAX(子查询结果)
SELECT emp_name, salary FROM emp
WHERE salary > ALL (SELECT salary FROM emp WHERE dept_id = 1);
-- 必须比技术部所有人薪资都高

10. 综合案例

10.1 准备完整数据

sql
-- 以上面建好的 dept、emp、sal_grade 表为基础

-- 查询每个员工的：姓名、部门、薪资、薪资等级、上级姓名
SELECT
    e.emp_name           AS '员工',
    d.dept_name          AS '部门',
    e.salary             AS '薪资',
    sg.grade             AS '薪资等级',
    m.emp_name           AS '直属上级'
FROM emp e
LEFT JOIN dept d
    ON e.dept_id = d.dept_id                           -- 连接部门
LEFT JOIN sal_grade sg
    ON e.salary BETWEEN sg.low_sal AND sg.high_sal     -- 连接薪资等级
LEFT JOIN emp m
    ON e.manager_id = m.emp_id;                        -- 自连接查上级

10.2 统计分析查询

sql
-- 各部门的员工数、平均薪资、最高薪资
SELECT
    d.dept_name            AS '部门',
    COUNT(e.emp_id)        AS '员工数',
    ROUND(AVG(e.salary),2) AS '平均薪资',
    MAX(e.salary)          AS '最高薪资'
FROM dept d
LEFT JOIN emp e ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name
ORDER BY AVG(e.salary) DESC;

-- 查询平均薪资高于全公司平均薪资的部门
SELECT
    d.dept_name,
    ROUND(AVG(e.salary), 2) AS avg_sal
FROM dept d
INNER JOIN emp e ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name
HAVING avg_sal > (SELECT AVG(salary) FROM emp);

-- 查询每个部门薪资最高的员工（相关子查询）
SELECT
    e.emp_name,
    e.dept_id,
    e.salary
FROM emp e
WHERE e.salary = (
    SELECT MAX(salary) FROM emp
    WHERE dept_id = e.dept_id  -- 相关子查询：引用了外层的 e.dept_id
);

10.3 多对多查询（使用中间表）

sql
-- 创建学生、课程、选课表
CREATE TABLE student (
    stu_id   INT PRIMARY KEY AUTO_INCREMENT,
    stu_name VARCHAR(50) NOT NULL
);

CREATE TABLE course (
    course_id   INT PRIMARY KEY AUTO_INCREMENT,
    course_name VARCHAR(50) NOT NULL
);

CREATE TABLE stu_course (
    stu_id    INT,
    course_id INT,
    score     DECIMAL(5,2),
    PRIMARY KEY (stu_id, course_id)
);

-- 插入数据
INSERT INTO student VALUES (1,'小明'), (2,'小红'), (3,'小张');
INSERT INTO course  VALUES (1,'MySQL'), (2,'Java'), (3,'Python');
INSERT INTO stu_course VALUES
(1, 1, 90), (1, 2, 85),    -- 小明选了 MySQL、Java
(2, 1, 78), (2, 3, 92),    -- 小红选了 MySQL、Python
(3, 2, 88), (3, 3, 76);    -- 小张选了 Java、Python

-- 查询每个学生的选课情况
SELECT
    s.stu_name   AS '学生',
    c.course_name AS '课程',
    sc.score      AS '成绩'
FROM student s
INNER JOIN stu_course sc ON s.stu_id = sc.stu_id
INNER JOIN course c     ON sc.course_id = c.course_id
ORDER BY s.stu_id, sc.score DESC;

-- 查询选了 MySQL 课程的学生
SELECT s.stu_name
FROM student s
WHERE s.stu_id IN (
    SELECT sc.stu_id FROM stu_course sc
    INNER JOIN course c ON sc.course_id = c.course_id
    WHERE c.course_name = 'MySQL'
);

-- 查询同时选了 MySQL 和 Java 的学生
SELECT s.stu_name
FROM student s
WHERE s.stu_id IN (SELECT stu_id FROM stu_course sc JOIN course c ON sc.course_id=c.course_id WHERE c.course_name='MySQL')
  AND s.stu_id IN (SELECT stu_id FROM stu_course sc JOIN course c ON sc.course_id=c.course_id WHERE c.course_name='Java');

11. 常见报错汇总

11.1 Column 'xx' in field list is ambiguous

text
ERROR 1052 (23000): Column 'dept_id' in field list is ambiguous
原因：两张表都有 dept_id 列，不知道用哪个
解决：加表名/别名前缀
sql
-- 错误
SELECT dept_id FROM emp INNER JOIN dept ON emp.dept_id = dept.dept_id;
-- 正确
SELECT emp.dept_id FROM emp INNER JOIN dept ON emp.dept_id = dept.dept_id;
-- 或用别名
SELECT e.dept_id FROM emp e INNER JOIN dept d ON e.dept_id = d.dept_id;

11.2 子查询返回多行（标量子查询）

text
ERROR 1242 (21000): Subquery returns more than 1 row
原因：在需要单值的地方，子查询返回了多行
sql
-- 错误：dept_name='技术部'只有一个，但如果有多个就会报错
SELECT * FROM emp
WHERE dept_id = (SELECT dept_id FROM dept WHERE dept_name LIKE '%部');  -- 多个部门名含'部'
-- 修复：用 IN 代替 =
SELECT * FROM emp
WHERE dept_id IN (SELECT dept_id FROM dept WHERE dept_name LIKE '%部');

11.3 NOT IN 返回空结果

text
现象：NOT IN 子查询没有报错，但结果为空
原因：子查询结果集含 NULL，NOT IN (..., NULL) 恒为 UNKNOWN
解决：在子查询加 WHERE column IS NOT NULL，或改用 NOT EXISTS

11.4 UNION 列数不匹配

text
ERROR 1222 (21000): The used SELECT statements have a different number of columns
原因：UNION 两侧 SELECT 的列数不同
解决：确保列数相同，用 NULL 或常量补齐
sql
-- 错误
SELECT emp_name FROM emp
UNION
SELECT dept_name, location FROM dept;  -- 列数不同

-- 修复
SELECT emp_name, NULL AS location FROM emp
UNION
SELECT dept_name, location FROM dept;

11.5 子查询别名缺失

text
ERROR 1248 (42000): Every derived table must have its own alias
原因：FROM 子句中的子查询没有别名
解决：给子查询加 AS 别名
sql
-- 错误
SELECT * FROM (SELECT emp_name FROM emp WHERE salary > 10000);

-- 修复
SELECT * FROM (SELECT emp_name FROM emp WHERE salary > 10000) AS high_sal_emp;

12. 面试常问

Q1：INNER JOIN 和 LEFT JOIN 的区别？

对比 INNER JOIN LEFT JOIN
返回行数 只返回两表都匹配的行 左表全部保留，右表无匹配填 NULL
适用场景 只关心有关联的数据 需要保留主表所有数据
NULL 处理 自动过滤左表/右表 NULL 保留左表，右表可能为 NULL

Q2：子查询什么时候比 JOIN 慢？

子查询可能较慢的场景：

  1. 相关子查询（Correlated Subquery）：子查询引用了外层的列，外层每一行都要重新执行一次子查询。

    • 例：WHERE salary = (SELECT MAX(salary) FROM emp WHERE dept_id = e.dept_id)
    • 外层有 N 行，子查询执行 N 次，复杂度 O(N²)

  2. 子查询结果无法被索引利用时

改进方法：用 JOIN 或窗口函数替代相关子查询：

sql
-- 相关子查询（慢）
SELECT * FROM emp e
WHERE salary = (SELECT MAX(salary) FROM emp WHERE dept_id = e.dept_id);

-- 改用 JOIN（通常更快）
SELECT e.*
FROM emp e
INNER JOIN (
    SELECT dept_id, MAX(salary) AS max_sal
    FROM emp GROUP BY dept_id
) m ON e.dept_id = m.dept_id AND e.salary = m.max_sal;

Q3：IN 和 EXISTS 如何选择？

  • 子查询结果集小（如几百行）→ 用 IN，简单直观
  • 子查询结果集大（如几万行）→ 用 EXISTS，只判断是否存在，不用加载全部数据
  • 有 NULL 参与时 → 优先用 EXISTS，避免 NOT IN 的 NULL 陷阱

Q4：UNION 和 UNION ALL 的区别及使用建议？

对比 UNION UNION ALL
去重 是（排序后去重） 否
性能 较慢 快
使用建议 确实需要去重时用 明确知道无重复或不关心重复时用

建议优先用 UNION ALL，显式去重可以用 DISTINCT。

Q5：什么是笛卡尔积，如何避免？

笛卡尔积 = 多表查询不加连接条件，结果为 M×N 行。 避免方法：始终在 ON 或 WHERE 子句加连接条件。

Q6：自连接的典型应用场景？

  • 员工表查上级/下属
  • 分类表查父分类（菜单树、商品分类树）
  • 朋友关系表查共同好友

Q7：LEFT JOIN 后 WHERE 条件和 ON 条件的区别？

sql
-- ON 条件：连接时就过滤（影响连接结果）
SELECT e.emp_name, d.dept_name
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.dept_id AND d.location = '北京';
-- 结果：所有员工都出现，但只有北京部门的员工才能显示 dept_name

-- WHERE 条件：连接后再过滤（影响最终行数）
SELECT e.emp_name, d.dept_name
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.dept_id
WHERE d.location = '北京';
-- 结果：只有北京员工，非北京员工被过滤掉了

规律：LEFT JOIN 时，过滤条件放 ON 和 WHERE 结果不同，ON 保留左表所有行，WHERE 对结果再过滤。

13. 本章小结

连接类型速查表

连接类型 语法 结果 类比
内连接 INNER JOIN 交集 两张名单都有的人
左外连接 LEFT JOIN 左表全部 + 匹配 以左表为准
右外连接 RIGHT JOIN 右表全部 + 匹配 以右表为准
全连接 UNION 模拟 并集 两张名单合并
自连接 表别名自连接 层级关系 员工找上级
交叉连接 CROSS JOIN 笛卡尔积 通常是 BUG

子查询使用场景

子查询类型 返回 常见用法
标量子查询 单个值 WHERE col = (...)
列子查询 多行单列 WHERE col IN (...)
行子查询 一行多列 WHERE (a,b) = (...)
表子查询 多行多列 FROM (...) AS t

学习建议

  1. 先把 INNER JOIN、LEFT JOIN 练熟，这是最常用的 80%
  2. UNION ALL 在报表统计里很有用
  3. 子查询从标量子查询开始，逐步理解 IN/EXISTS
  4. 自连接是处理层级数据的利器，理解后非常有用
  5. 多表查询一定要养成加表别名的习惯，提高可读性
