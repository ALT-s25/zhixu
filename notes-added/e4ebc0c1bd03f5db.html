按章节学习你的知识，慢慢成林

难度：中高 | 学习建议：2 天 对应黑马 SpringCloud 资料：day05-服务保护和分布式事务 项目导向：微服务生产环境必备，防止服务雪崩

一、为什么需要服务保护

1.1 服务雪崩

场景：微服务 A 调用 B，B 调用 C，C 因为某原因响应慢。

text
用户 → A → B → C（慢！）
              ↓
     B 的线程全在等 C
     B 的线程池耗尽
     A 的请求也开始积压
     A 的线程池耗尽
              ↓
       整个系统崩溃！

这就是服务雪崩：一个服务故障，导致整个调用链都崩了。

1.2 Sentinel 的三大保护措施

保护措施 场景 说明
流量控制（限流） 高并发 超出阈值的请求直接拒绝
熔断降级 下游故障 下游不可用时快速失败，不等待
系统自适应保护 整体负载 根据 CPU/内存动态调整

二、Sentinel 快速入门

2.1 引入依赖

xml
<!-- 服务调用方（order-service 等）引入 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>

2.2 配置连接 Sentinel 控制台

yaml
spring:
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8080   # Sentinel 控制台地址
        port: 8719                   # 本服务的 Sentinel 通信端口

2.3 启动 Sentinel 控制台

bash
# 下载 sentinel-dashboard.jar
java -jar sentinel-dashboard-1.8.1.jar --server.port=8080
# 访问：http://localhost:8080，用 sentinel/sentinel 登录

三、流量控制（限流）⭐⭐⭐

3.1 资源定义

Sentinel 保护的对象叫"资源"，默认把每个 Controller 接口作为资源。

java
// 方式一：注解（推荐）
@SentinelResource(value = "queryUser",  // 资源名
    blockHandler = "blockQueryUser")     // 被限流时调用的方法
public User queryUser(Long id) {
    return userService.getById(id);
}

// 被限流时的降级方法（参数要和原方法一致，最后多 BlockException）
public User blockQueryUser(Long id, BlockException e) {
    return new User(-1L, "服务繁忙，请稍后重试", null);
}

// 方式二：API
try (Entry entry = SphU.entry("queryUser")) {
    return userService.getById(id);
} catch (BlockException e) {
    return new User(-1L, "限流了", null);
}

3.2 控制台配置流控规则

在 Sentinel 控制台 → 簇点链路 → 选择资源 → 点击"流控"：

参数 说明
资源名 要保护的接口/方法
阈值类型 QPS（每秒请求数）/ 并发线程数
单机阈值 超过这个数量触发限流
流控模式 直接/关联/链路
流控效果 快速失败/Warm Up/排队等待

三种流控效果：

  • 快速失败：超过阈值立即返回 FlowException
  • Warm Up（预热）：初始只允许阈值/3，经过预热时间后达到阈值（防冷启动）
  • 排队等待：超过阈值的请求排队等，适合削峰填谷

四、熔断降级 ⭐⭐⭐

4.1 熔断原理（断路器模式）

text
正常状态（Closed）
    ↓ 失败率过高
熔断状态（Open）：直接返回降级，不请求下游
    ↓ 经过熔断时长
半开状态（Half-Open）：放行一个请求试探
    ↓ 试探成功
正常状态（Closed）
    ↓ 试探失败
熔断状态（Open）（重新计时）

4.2 控制台配置熔断规则

参数 说明
熔断策略 慢调用比例 / 异常比例 / 异常数
最小请求数 统计窗口内的最小请求数
统计时长 时间窗口（单位毫秒）
比例阈值 超过这个比例触发熔断
熔断时长 熔断多久后进入半开状态

三种熔断策略：

策略 触发条件
慢调用比例 慢响应（超过 RT）请求比例超过阈值
异常比例 异常请求比例超过阈值
异常数 异常请求数超过阈值

4.3 Feign 整合 Sentinel（熔断降级）⭐⭐

yaml
feign:
  sentinel:
    enabled: true   # 开启 Feign 对 Sentinel 的支持
java
// 1. 定义降级处理类
@Component
public class UserClientFallback implements UserClient {
    @Override
    public User getUserById(Long id) {
        // 下游不可用时的降级返回
        return new User(-1L, "服务暂时不可用", null);
    }
}

// 2. 在 FeignClient 注解上指定降级类
@FeignClient(value = "user-service",
             fallback = UserClientFallback.class)  // 指定降级类
public interface UserClient {
    @GetMapping("/user/{id}")
    User getUserById(@PathVariable("id") Long id);
}

五、@SentinelResource 注解详解

java
@SentinelResource(
    value = "queryHot",                   // 资源名
    blockHandler = "blockHandler",         // 限流/熔断处理方法
    blockHandlerClass = MyHandler.class,   // 处理方法所在类（不在同一类时）
    fallback = "fallbackMethod",           // 业务异常时的降级方法
    exceptionsToIgnore = {NullPointerException.class}  // 忽略某些异常，不降级
)
public HotItem queryHot(String itemId) {
    return hotService.getById(itemId);
}

// blockHandler：只处理 BlockException（限流/熔断）
public HotItem blockHandler(String itemId, BlockException e) {
    return HotItem.defaultItem();
}

// fallback：处理所有业务异常
public HotItem fallbackMethod(String itemId, Throwable e) {
    return HotItem.defaultItem();
}

六、热点规则 ⭐

场景：某个参数值特别热（如商品 id=1 是爆款），限制这个参数值的访问频率。

java
@SentinelResource("queryItem")
public Item queryItem(@RequestParam("itemId") String itemId) {
    return itemService.getById(itemId);
}

在控制台：热点规则 → 资源名 queryItem → 参数索引 0（第一个参数）→ 阈值 100 QPS

可以针对某个参数值设置例外： 如 itemId=1 是 VIP 商品，允许 1000 QPS，其他参数值只允许 100 QPS。

七、规则持久化 ⭐⭐

问题：Sentinel 控制台配置的规则，服务重启后会丢失！

解决：把规则持久化到 Nacos 配置中心。

xml
<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-datasource-nacos</artifactId>
</dependency>
yaml
spring:
  cloud:
    sentinel:
      datasource:
        flow:
          nacos:
            server-addr: localhost:8848
            dataId: ${spring.application.name}-flow-rules
            groupId: SENTINEL_GROUP
            rule-type: flow    # 流控规则

八、常见报错

报错 1：BlockException 未捕获，直接返回 500

text
原因：没有配置 blockHandler
解决：加 @SentinelResource(blockHandler="xxx") 或 全局异常处理

报错 2：Sentinel 控制台看不到服务

text
原因：服务没有发起过请求（懒加载）
解决：先访问一次接口，或配置 eager: true

九、面试常问 ⭐⭐

💡 服务雪崩是什么？怎么解决？ 一个服务故障，导致调用链上所有服务都崩。用 Sentinel 限流+熔断解决。

💡 限流和熔断的区别？

  • 限流：控制进来的流量（如每秒最多 100 个请求）
  • 熔断：检测下游是否正常，不正常就断开（不再调用下游）

💡 熔断的三种状态？ Closed（正常）→ Open（熔断）→ Half-Open（半开）

💡 Sentinel 和 Hystrix 的区别？ | 维度 | Sentinel | Hystrix | |------|---------|---------| | 控制台 | ✅ 有 | ❌ 无 | | 规则配置 | 动态（控制台/Nacos）| 静态代码 | | 熔断策略 | 慢调用/异常比例/数 | 仅异常比例 | | 维护状态 | ✅ 活跃 | ❌ 停止维护 |
