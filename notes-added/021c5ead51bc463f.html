1. 什么是约束

1.1 类比理解

把数据库的表想象成一张 登记表：

  • 姓名栏不能空着 → NOT NULL
  • 身份证号不能重复 → UNIQUE
  • 每人有唯一编号 → PRIMARY KEY
  • 性别默认"未知" → DEFAULT
  • 年龄必须 > 0 → CHECK
  • 部门编号必须在部门表里存在 → FOREIGN KEY

约束就是数据库帮你把守的数据质量门卫，在数据写入时自动检查，不合格直接拒绝。

1.2 约束分类

约束类型 关键字 作用
非空约束 NOT NULL 该列不能存 NULL
唯一约束 UNIQUE 该列值在表内不重复
主键约束 PRIMARY KEY 唯一 + 非空，行的唯一标识
默认约束 DEFAULT 插入时未指定该列则用默认值
检查约束 CHECK 自定义校验规则（8.0+生效）
外键约束 FOREIGN KEY 引用另一张表的主键，保证引用完整性

2. 非空约束 NOT NULL

2.1 核心概念

NOT NULL 表示该列必须有值，不允许为 NULL。 NULL 和空字符串 '' 是两回事：

  • NULL：表示"不知道"或"不存在"
  • ''：表示"知道，但是空的"

2.2 建表语法

sql
-- 方式一：列级约束（定义列时直接加）
CREATE TABLE student (
    id      INT         NOT NULL,       -- id 不能为 NULL
    name    VARCHAR(50) NOT NULL,       -- 姓名不能为 NULL
    email   VARCHAR(100)                -- email 可以为 NULL（不加约束）
);

-- 方式二：修改已有表，添加 NOT NULL
ALTER TABLE student
    MODIFY email VARCHAR(100) NOT NULL; -- 把 email 也改为非空

2.3 完整测试代码

sql
-- 1. 建表
CREATE TABLE t_notnull (
    id    INT         NOT NULL,
    name  VARCHAR(50) NOT NULL,
    remark VARCHAR(200)           -- 备注允许为空
);

-- 2. 正常插入
INSERT INTO t_notnull(id, name, remark) VALUES (1, '张三', '备注');  -- OK
INSERT INTO t_notnull(id, name)         VALUES (2, '李四');          -- OK，remark 默认 NULL

-- 3. 违反约束（会报错）
INSERT INTO t_notnull(id, name) VALUES (3, NULL);    -- ERROR: name 不能为 NULL
INSERT INTO t_notnull(id)       VALUES (4);          -- ERROR: name 不能为 NULL

-- 4. 查看表结构
DESC t_notnull;

-- 5. 删除 NOT NULL（允许为空）
ALTER TABLE t_notnull MODIFY name VARCHAR(50) NULL;

-- 6. 重新添加 NOT NULL
ALTER TABLE t_notnull MODIFY name VARCHAR(50) NOT NULL;

3. 唯一约束 UNIQUE

3.1 核心概念

UNIQUE 保证该列（或列组合）的值在整个表中不重复。 与主键的区别：

  • UNIQUE 允许有 NULL（且多个 NULL 不算重复，MySQL 8.0.13+）
  • 一张表可以有多个 UNIQUE 约束
  • 主键只能有一个

3.2 建表语法

sql
-- 方式一：列级定义
CREATE TABLE t_unique1 (
    id    INT,
    email VARCHAR(100) UNIQUE,       -- email 唯一
    phone VARCHAR(20)  UNIQUE        -- phone 也唯一
);

-- 方式二：表级定义（可以给约束起名）
CREATE TABLE t_unique2 (
    id    INT,
    email VARCHAR(100),
    phone VARCHAR(20),
    UNIQUE KEY uk_email (email),     -- 给约束命名 uk_email
    UNIQUE KEY uk_phone (phone)
);

-- 方式三：联合唯一（多列组合唯一）
CREATE TABLE t_unique3 (
    id         INT,
    first_name VARCHAR(50),
    last_name  VARCHAR(50),
    -- 姓名组合唯一，单独重复没关系
    UNIQUE KEY uk_name (first_name, last_name)
);

3.3 完整测试代码

sql
CREATE TABLE t_unique_test (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(100) UNIQUE,
    phone VARCHAR(20)
);

-- 正常插入
INSERT INTO t_unique_test(email, phone) VALUES ('a@test.com', '13800000001'); -- OK
INSERT INTO t_unique_test(email, phone) VALUES ('b@test.com', '13800000002'); -- OK

-- 违反唯一约束（报错）
INSERT INTO t_unique_test(email, phone) VALUES ('a@test.com', '13800000003'); -- ERROR: Duplicate entry

-- NULL 可以重复插入
INSERT INTO t_unique_test(email, phone) VALUES (NULL, '13800000004'); -- OK
INSERT INTO t_unique_test(email, phone) VALUES (NULL, '13800000005'); -- OK（NULL 不算重复）

-- 查看唯一索引
SHOW INDEX FROM t_unique_test;

-- 删除唯一约束（本质是删索引）
ALTER TABLE t_unique_test DROP INDEX email;

-- 添加唯一约束
ALTER TABLE t_unique_test ADD UNIQUE KEY uk_email (email);

4. 主键约束 PRIMARY KEY

4.1 核心概念

主键 = 唯一 + 非空，是行的唯一标识符。 类比：每个人的身份证号，全国唯一，且必须有。

规则：

  • 每张表最多只有一个主键
  • 主键列的值不能为 NULL
  • 主键列的值不能重复
  • 主键会自动创建索引（提升查询速度）

4.2 单列主键

sql
-- 方式一：列级定义
CREATE TABLE t_pk1 (
    id   INT         PRIMARY KEY,    -- 直接在列后加 PRIMARY KEY
    name VARCHAR(50) NOT NULL
);

-- 方式二：表级定义（推荐，更灵活）
CREATE TABLE t_pk2 (
    id   INT,
    name VARCHAR(50) NOT NULL,
    PRIMARY KEY (id)                 -- 在最后单独定义
);

4.3 联合主键（复合主键）

sql
-- 多列共同构成主键（两列组合不重复即可）
CREATE TABLE t_pk_composite (
    student_id INT,
    course_id  INT,
    score      DECIMAL(5,2),
    PRIMARY KEY (student_id, course_id)  -- student_id 和 course_id 的组合唯一
);

-- 测试
INSERT INTO t_pk_composite VALUES (1, 101, 90.5);  -- OK
INSERT INTO t_pk_composite VALUES (1, 102, 85.0);  -- OK（student_id 相同但 course_id 不同）
INSERT INTO t_pk_composite VALUES (2, 101, 92.0);  -- OK（course_id 相同但 student_id 不同）
INSERT INTO t_pk_composite VALUES (1, 101, 88.0);  -- ERROR：组合重复

4.4 自增主键 AUTO_INCREMENT

sql
-- AUTO_INCREMENT：插入时自动+1，不需要手动指定
CREATE TABLE t_pk_auto (
    id   INT          AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50)  NOT NULL
);

-- 测试
INSERT INTO t_pk_auto(name) VALUES ('张三');   -- id = 1（自动）
INSERT INTO t_pk_auto(name) VALUES ('李四');   -- id = 2（自动）
INSERT INTO t_pk_auto(name) VALUES ('王五');   -- id = 3（自动）

-- 查看最后插入的自增值
SELECT LAST_INSERT_ID();

-- 修改自增起始值（从 1000 开始）
ALTER TABLE t_pk_auto AUTO_INCREMENT = 1000;
INSERT INTO t_pk_auto(name) VALUES ('赵六');   -- id = 1000

-- 注意：删除数据不会重置自增值
DELETE FROM t_pk_auto WHERE id = 1000;
INSERT INTO t_pk_auto(name) VALUES ('孙七');   -- id = 1001（不是 1000）

4.5 修改主键

sql
-- 添加主键（表建好后）
ALTER TABLE t_pk1 ADD PRIMARY KEY (id);

-- 删除主键
ALTER TABLE t_pk1 DROP PRIMARY KEY;

-- 注意：如果有 AUTO_INCREMENT，删主键前先去掉 AUTO_INCREMENT
ALTER TABLE t_pk_auto MODIFY id INT;         -- 先去掉 AUTO_INCREMENT
ALTER TABLE t_pk_auto DROP PRIMARY KEY;       -- 再删主键

5. 默认约束 DEFAULT

5.1 核心概念

DEFAULT 指定列的默认值：插入数据时如果没有给这列赋值，就用默认值填充。

类比：网站注册时，"是否订阅邮件"默认勾选。

5.2 建表语法

sql
CREATE TABLE t_default (
    id         INT         PRIMARY KEY AUTO_INCREMENT,
    name       VARCHAR(50) NOT NULL,
    gender     TINYINT     DEFAULT 0,          -- 0=未知, 1=男, 2=女
    status     VARCHAR(10) DEFAULT 'active',   -- 字符串默认值
    created_at DATETIME    DEFAULT CURRENT_TIMESTAMP,  -- 默认当前时间
    score      DECIMAL(5,2) DEFAULT 0.00
);

5.3 完整测试代码

sql
-- 插入时不指定有默认值的列
INSERT INTO t_default(name) VALUES ('张三');
-- 结果：gender=0, status='active', created_at=当前时间, score=0.00

-- 明确插入 NULL（会覆盖默认值）
INSERT INTO t_default(name, gender) VALUES ('李四', NULL);
-- 结果：gender=NULL（不用默认值，明确写了 NULL）

-- 用 DEFAULT 关键字显式使用默认值
INSERT INTO t_default(name, gender, status) VALUES ('王五', 1, DEFAULT);
-- 结果：status='active'（使用默认值）

SELECT * FROM t_default;

-- 修改默认值
ALTER TABLE t_default ALTER COLUMN gender SET DEFAULT 1;

-- 删除默认值
ALTER TABLE t_default ALTER COLUMN gender DROP DEFAULT;

6. 检查约束 CHECK（MySQL 8.0+）

6.1 核心概念

CHECK 约束允许你自定义校验条件，插入或更新数据时必须满足该条件。

⚠️ 注意：MySQL 5.x 版本虽然语法不报错，但 CHECK 约束不生效！ 只有 MySQL 8.0.16+ 才真正强制执行 CHECK 约束。

6.2 建表语法

sql
CREATE TABLE t_check (
    id     INT          PRIMARY KEY AUTO_INCREMENT,
    name   VARCHAR(50)  NOT NULL,
    age    INT          CHECK (age > 0 AND age <= 150),  -- 年龄 1~150
    gender CHAR(1)      CHECK (gender IN ('M', 'F', 'U')),  -- 性别只能是这三个
    score  DECIMAL(5,2) CHECK (score >= 0 AND score <= 100) -- 分数 0~100
);

6.3 完整测试代码

sql
-- 正常插入
INSERT INTO t_check(name, age, gender, score) VALUES ('张三', 25, 'M', 90.5);  -- OK

-- 违反 CHECK 约束
INSERT INTO t_check(name, age, gender, score) VALUES ('李四', -1, 'M', 90.5);   -- ERROR: age
INSERT INTO t_check(name, age, gender, score) VALUES ('王五', 25, 'X', 90.5);   -- ERROR: gender
INSERT INTO t_check(name, age, gender, score) VALUES ('赵六', 25, 'M', 150);    -- ERROR: score

-- 表级 CHECK（多列联合校验）
CREATE TABLE t_check2 (
    id         INT PRIMARY KEY AUTO_INCREMENT,
    start_date DATE,
    end_date   DATE,
    -- 结束日期必须晚于开始日期
    CHECK (end_date > start_date)
);

-- 查看 CHECK 约束
SELECT * FROM information_schema.TABLE_CONSTRAINTS
WHERE TABLE_NAME = 't_check' AND CONSTRAINT_TYPE = 'CHECK';

-- 删除 CHECK 约束（需要知道约束名）
ALTER TABLE t_check DROP CHECK t_check_chk_1;

-- 添加 CHECK 约束
ALTER TABLE t_check ADD CONSTRAINT chk_age CHECK (age > 0 AND age <= 150);

7. 外键约束 FOREIGN KEY

7.1 核心概念

外键约束保证引用完整性：子表中的外键列的值，必须在父表的主键/唯一键中存在（或为 NULL）。

类比：公司员工表里有"部门编号"列，这个编号必须在部门表里真实存在，不能随便填一个不存在的部门编号。

术语：

  • 父表（主表）：被引用的表（如部门表）
  • 子表（从表）：持有外键的表（如员工表）

7.2 建表示例

sql
-- 先建父表（部门表）
CREATE TABLE dept (
    dept_id   INT         PRIMARY KEY AUTO_INCREMENT,
    dept_name VARCHAR(50) NOT NULL UNIQUE
);

-- 再建子表（员工表），引用 dept 的主键
CREATE TABLE emp (
    emp_id    INT         PRIMARY KEY AUTO_INCREMENT,
    emp_name  VARCHAR(50) NOT NULL,
    dept_id   INT,                                -- 外键列
    salary    DECIMAL(10,2) DEFAULT 0,
    -- 定义外键约束
    CONSTRAINT fk_emp_dept                        -- 给外键起名
        FOREIGN KEY (dept_id)                     -- 子表的外键列
        REFERENCES dept(dept_id)                  -- 引用父表的哪一列
);

7.3 添加和删除外键

sql
-- 建表后添加外键
ALTER TABLE emp
    ADD CONSTRAINT fk_emp_dept
    FOREIGN KEY (dept_id) REFERENCES dept(dept_id);

-- 查看外键
SELECT * FROM information_schema.KEY_COLUMN_USAGE
WHERE TABLE_NAME = 'emp' AND REFERENCED_TABLE_NAME IS NOT NULL;

-- 删除外键
ALTER TABLE emp DROP FOREIGN KEY fk_emp_dept;

7.4 完整测试代码

sql
-- 准备数据
INSERT INTO dept(dept_name) VALUES ('技术部'), ('市场部'), ('财务部');
-- dept_id 分别是 1, 2, 3

-- 正常插入员工（dept_id 在 dept 表存在）
INSERT INTO emp(emp_name, dept_id, salary) VALUES ('张三', 1, 10000);  -- OK
INSERT INTO emp(emp_name, dept_id, salary) VALUES ('李四', 2, 8000);   -- OK
INSERT INTO emp(emp_name, dept_id)         VALUES ('王五', NULL);       -- OK（外键允许 NULL）

-- 违反外键约束（dept_id=99 不存在）
INSERT INTO emp(emp_name, dept_id) VALUES ('赵六', 99);  -- ERROR: a foreign key constraint fails

-- 违反外键：删除被引用的父记录
DELETE FROM dept WHERE dept_id = 1;  -- ERROR: Cannot delete or update a parent row

-- 违反外键：修改被引用的父记录主键
UPDATE dept SET dept_id = 100 WHERE dept_id = 1;  -- ERROR

7.5 级联操作

级联操作决定：当父表记录被删除或更新时，子表的相关记录怎么处理。

级联选项 含义
RESTRICT 默认值，拒绝删除/更新父记录（如果有子记录）
NO ACTION 和 RESTRICT 相同（MySQL 中等同）
CASCADE 父记录删除/更新时，子记录同步删除/更新
SET NULL 父记录删除/更新时，子表外键列设为 NULL
SET DEFAULT 子表外键设为默认值（MySQL InnoDB 不支持）
sql
-- 示例1：CASCADE（级联删除和更新）
CREATE TABLE dept2 (
    dept_id   INT PRIMARY KEY AUTO_INCREMENT,
    dept_name VARCHAR(50) NOT NULL
);

CREATE TABLE emp2 (
    emp_id   INT PRIMARY KEY AUTO_INCREMENT,
    emp_name VARCHAR(50),
    dept_id  INT,
    CONSTRAINT fk_emp2_dept2
        FOREIGN KEY (dept_id) REFERENCES dept2(dept_id)
        ON DELETE CASCADE   -- 父删除 → 子自动删除
        ON UPDATE CASCADE   -- 父更新 → 子自动更新
);
sql
-- 测试 CASCADE
INSERT INTO dept2(dept_name) VALUES ('技术部');       -- dept_id = 1
INSERT INTO emp2(emp_name, dept_id) VALUES ('张三', 1);
INSERT INTO emp2(emp_name, dept_id) VALUES ('李四', 1);

DELETE FROM dept2 WHERE dept_id = 1;
-- 结果：dept2 中 dept_id=1 被删，emp2 中两条记录也自动删除

-- 示例2：SET NULL（级联置空）
CREATE TABLE dept3 (
    dept_id   INT PRIMARY KEY AUTO_INCREMENT,
    dept_name VARCHAR(50) NOT NULL
);

CREATE TABLE emp3 (
    emp_id   INT PRIMARY KEY AUTO_INCREMENT,
    emp_name VARCHAR(50),
    dept_id  INT,       -- 注意：SET NULL 要求此列允许 NULL
    CONSTRAINT fk_emp3_dept3
        FOREIGN KEY (dept_id) REFERENCES dept3(dept_id)
        ON DELETE SET NULL  -- 父删除 → 子外键设为 NULL
        ON UPDATE SET NULL  -- 父更新 → 子外键设为 NULL
);

INSERT INTO dept3(dept_name) VALUES ('市场部');       -- dept_id = 1
INSERT INTO emp3(emp_name, dept_id) VALUES ('王五', 1);

DELETE FROM dept3 WHERE dept_id = 1;
-- 结果：emp3 中 dept_id 变为 NULL（员工还在，只是没有部门了）
SELECT * FROM emp3;

8. 外键的作用与弊端

8.1 外键的好处

  1. 数据完整性：数据库层面保证不会出现"孤儿数据"（引用了不存在的记录）
  2. 自动级联：删除/更新父记录时，子记录自动处理
  3. 文档化关系：从表结构就能看出表间关系

8.2 外键的弊端（互联网公司不推荐用的原因）

8.2.1 性能问题

text
每次 INSERT/UPDATE/DELETE 子表，都要去父表查一遍 → 额外的 IO
每次删改父表，都要检查子表是否有引用 → 额外的锁竞争

大型系统中，这些额外开销会显著影响吞吐量。

8.2.2 扩展性差

text
分库分表时，父表和子表可能在不同数据库/服务器上
→ 外键跨库不支持，必须去掉外键

8.2.3 运维困难

text
数据迁移、批量导入时，经常因为外键约束顺序问题报错
→ 需要先禁用外键检查: SET FOREIGN_KEY_CHECKS = 0;
→ 导入完再启用: SET FOREIGN_KEY_CHECKS = 1;

8.2.4 开发灵活性差

text
无法先插子表再插父表（即使在同一个事务里）
无法做某些"暂时不满足约束"的中间状态操作

8.3 互联网公司的通常做法

不使用数据库外键，改为应用层（代码层）维护引用完整性：

text
1. 插入员工前，代码里先查部门是否存在
2. 删除部门前，代码里先查是否有员工在此部门
3. 通过业务逻辑 + 代码注释 + API 契约来保证数据一致性

优点：

  • 灵活，可以分库分表
  • 性能好，减少数据库压力
  • 迁移、导入方便

缺点：

  • 需要开发者自律，可能因代码 bug 导致脏数据
  • 需要额外写校验代码

阿里巴巴 Java 开发手册 明确规定：【强制】不得使用外键与级联，一切外键概念必须在应用层解决。

9. 常见报错汇总

9.1 违反 NOT NULL

text
ERROR 1048 (23000): Column 'name' cannot be null
原因：往 NOT NULL 列插入 NULL
解决：给该列提供非 NULL 值

9.2 违反 UNIQUE

text
ERROR 1062 (23000): Duplicate entry 'a@test.com' for key 'uk_email'
原因：插入了已存在的唯一值
解决：换一个不重复的值，或用 INSERT IGNORE / ON DUPLICATE KEY UPDATE
sql
-- 忽略重复（不报错，不插入）
INSERT IGNORE INTO t_unique_test(email) VALUES ('a@test.com');

-- 重复时更新
INSERT INTO t_unique_test(email, phone)
VALUES ('a@test.com', '13900000001')
ON DUPLICATE KEY UPDATE phone = '13900000001';

9.3 违反主键约束

text
ERROR 1062 (23000): Duplicate entry '1' for key 'PRIMARY'
原因：插入了已存在的主键值
解决：使用 AUTO_INCREMENT 或换一个不重复的值

9.4 违反外键约束（插入子表）

text
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails
(`mydb`.`emp`, CONSTRAINT `fk_emp_dept` FOREIGN KEY (`dept_id`) REFERENCES `dept` (`dept_id`))
原因：子表插入了父表不存在的值
解决：先往父表插入对应记录，再插子表

9.5 违反外键约束（删除父表）

text
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails
原因：删除父表记录时，子表还有引用
解决：先删子表相关记录，再删父表；或改用 CASCADE

9.6 CHECK 约束不生效（MySQL 5.x）

text
现象：在 MySQL 5.x 中 CHECK 约束写了但不报错，也不阻止非法数据
原因：MySQL 5.x 解析 CHECK 语法但不执行
解决：升级到 MySQL 8.0.16+，或用触发器模拟 CHECK

10. 面试常问

Q1：主键和唯一约束的区别？

对比项 PRIMARY KEY UNIQUE
NULL 不允许 允许（MySQL 中多个 NULL 不算重复）
数量 一张表只能有1个 可以有多个
索引 聚簇索引（InnoDB） 普通唯一索引
用途 行的唯一标识 保证某列不重复

Q2：为什么 InnoDB 建议用自增整数作主键？

  1. 顺序插入：自增 ID 总是插在 B+ 树最右边，不会引起页分裂，性能好
  2. 空间小：整数占 4~8 字节，比 UUID 的 36 字节小得多
  3. 关联查询快：外键关联用整数比字符串快

如果用 UUID 或随机主键，每次插入都可能随机插在 B+ 树中间，导致频繁页分裂，性能差。

Q3：外键约束的三种级联操作？

  • CASCADE：父删/改 → 子跟着删/改
  • SET NULL：父删/改 → 子外键置 NULL
  • RESTRICT：父有子引用时，拒绝删/改父

Q4：互联网公司为什么不建议用外键？

性能（每次写操作要检查引用）、扩展性（分库分表时外键跨库不支持）、运维复杂度（批量导入需要临时禁用）这三方面原因，改在应用层维护数据一致性。

Q5：CHECK 约束在 MySQL 哪个版本才生效？

MySQL 8.0.16+。之前的版本语法不报错但不执行，可用触发器代替。

Q6：如何临时禁用外键检查（批量导入数据时）？

sql
SET FOREIGN_KEY_CHECKS = 0;  -- 禁用
-- ... 执行批量导入 ...
SET FOREIGN_KEY_CHECKS = 1;  -- 恢复

11. 本章小结

约束 核心作用 允许 NULL 每表数量 版本要求
NOT NULL 必须有值 否 多个 全版本
UNIQUE 值不重复 是（多NULL不算重复） 多个 全版本
PRIMARY KEY 唯一+非空，行标识 否 仅1个 全版本
DEFAULT 未赋值时填默认 - 多个 全版本
CHECK 自定义校验 - 多个 8.0.16+
FOREIGN KEY 引用完整性 是 多个 全版本（InnoDB）

学习路径建议：

  1. 先掌握 NOT NULL、UNIQUE、PRIMARY KEY、DEFAULT，这四个最常用
  2. CHECK 在 MySQL 8.0+ 项目中可以用
  3. FOREIGN KEY 了解原理，实际生产中按公司规范决定是否使用
