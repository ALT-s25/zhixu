二、基础概念 ⭐

2.1 倒排索引

正向索引：从文档找关键词（MySQL B+ 树）

倒排索引：从关键词找文档

text
文档 1: "Hello World"
文档 2: "Hello Java"

词条 → 文档列表
"hello" → [1, 2]
"world" → [1]
"java"  → [2]

搜索 "hello" → 直接查词条，返回 [1, 2]，O(1)。

2.2 ES vs MySQL

MySQL Elasticsearch
Table（表） Index（索引库）
Row（行） Document（文档）
Column（列） Field（字段）
Schema Mapping（映射）
SQL DSL（JSON）

💡 ES 适合搜索 + 统计分析；MySQL 适合事务、复杂关联。两者互补。

三、索引库操作（mapping）⭐⭐

3.1 mapping 映射属性

字段类型 说明
text 可分词的文本（参与全文检索）
keyword 不可分词（精确匹配，如品牌、ID）
long/integer/short/byte 整数
float/double 浮点
boolean 布尔
date 日期
geo_point 地理坐标
object / nested 嵌套对象

3.2 创建索引库

json
PUT /hotel
{
  "mappings": {
    "properties": {
      "name": {
        "type": "text",
        "analyzer": "ik_max_word",        // 分词器
        "copy_to": "all"                  // 拷贝到 all 字段
      },
      "price": { "type": "integer" },
      "city": { "type": "keyword" },
      "starName": { "type": "keyword" },
      "location": { "type": "geo_point" },
      "all": {
        "type": "text",
        "analyzer": "ik_max_word"
      }
    }
  }
}

3.3 索引库 CRUD

json
// 查看
GET /hotel

// 修改（只能追加字段，不能修改已有字段）
PUT /hotel/_mapping
{
  "properties": {
    "newField": { "type": "keyword" }
  }
}

// 删除
DELETE /hotel

⚠ mapping 字段一旦定义不能修改，只能追加新字段。要修改必须重建索引。

五、DSL 查询 ⭐⭐⭐

5.1 查询语法结构

json
GET /hotel/_search
{
  "query": { /* 查询条件 */ },
  "from": 0, "size": 20,              // 分页
  "sort": [ /* 排序 */ ],
  "highlight": { /* 高亮 */ }
}

5.2 全文检索（match）⭐

json
// 单字段查询
{ "query": { "match": { "all": "外滩如家" } } }

// 多字段查询（multi_match）
{
  "query": {
    "multi_match": {
      "query": "如家",
      "fields": ["name", "business"]
    }
  }
}

💡 match 会分词后查询；multi_match 参与字段越多得分越低，性能越差，建议用 copy_to 合并到单字段。

5.3 精准查询

json
// term：精确匹配（不分词）
{ "query": { "term": { "city": "上海" } } }

// range：范围查询
{ "query": { "range": { "price": { "gte": 100, "lte": 500 } } } }

⚠ text 类型字段不能用 term 精确匹配（已被分词）。精确匹配用 keyword。

5.4 地理查询

json
// 矩形范围
{
  "query": {
    "geo_bounding_box": {
      "location": {
        "top_left": { "lat": 31.1, "lon": 121.5 },
        "bottom_right": { "lat": 31.0, "lon": 121.4 }
      }
    }
  }
}

// 附近（按距离排序）
{
  "query": {
    "geo_distance": {
      "distance": "5km",
      "location": "31.21,121.5"
    }
  },
  "sort": [
    {
      "_geo_distance": {
        "location": "31.21,121.5",
        "order": "asc",
        "unit": "km"
      }
    }
  ]
}

5.5 复合查询（bool）⭐⭐

json
{
  "query": {
    "bool": {
      "must":     [ { "match": { "all": "如家" } } ],     // 必须匹配（参与算分）
      "should":   [ { "term": { "starName": "五" } } ],    // 可选匹配（加分）
      "must_not": [ { "range": { "price": { "gt": 500 } } } ], // 必须不匹配（过滤，不算分）
      "filter":   [ { "range": { "score": { "gte": 45 } } } ] // 过滤（不算分，性能好）
    }
  }
}
子句 是否算分 含义
must ✅ 必须匹配
should ✅ 满足即加分（无 must 时至少满足一个）
must_not ❌ 必须不匹配（过滤）
filter ❌ 必须匹配（过滤，性能好）

💡 相关性算分：must 和 should 参与打分；filter 和 must_not 仅过滤，性能更好。

5.6 算分函数（function_score）

json
{
  "query": {
    "function_score": {
      "query": { "match": { "all": "外滩" } },
      "functions": [
        {
          "filter": { "term": { "isAD": true } },  // 广告位
          "weight": 10                              // 加权 10 倍
        }
      ],
      "boost_mode": "multiply"   // 原始分 × 权重
    }
  }
}

六、搜索结果处理 ⭐⭐

6.1 排序

json
// 普通字段排序
{ "sort": [ { "price": "asc" } ] }

// 地理坐标排序
{ "sort": [ { "_geo_distance": { "location": "31.2,121.5", "order": "asc", "unit": "km" } } ] }

6.2 分页

json
{
  "query": { "match_all": {} },
  "from": 0,    // 起始位置
  "size": 20    // 每页大小
}

⚠ 深度分页问题：from + size 超过 10000 时性能急剧下降。大数据量用 search_after 或 scroll。

6.3 高亮 ⭐

json
{
  "query": { "match": { "all": "如家" } },
  "highlight": {
    "fields": {
      "name": {
        "pre_tags": "<em style='color:red'>",
        "post_tags": "</em>",
        "require_field_match": false   // 不要求字段匹配
      }
    }
  }
}

七、数据聚合 ⭐⭐

7.1 三种聚合类型

类型 说明 DSL 关键字
Bucket 桶聚合（分组） terms
Metric 指标聚合（求 max/avg） avg/max/stats
Pipeline 管道聚合（基于其他聚合结果） -

7.2 DSL 示例

json
GET /hotel/_search
{
  "size": 0,    // 不返回文档，只要聚合结果
  "query": { "range": { "price": { "lte": 500 } } },  // 限定聚合范围
  "aggs": {
    "brandAgg": {
      "terms": {
        "field": "brand",
        "size": 20                // 返回前 20 个桶
      },
      "aggs": {
        "scoreAvg": { "avg": { "field": "score" } },
        "scoreMax": { "max": { "field": "score" } }
      }
    }
  }
}

八、自动补全 ⭐

8.1 拼音分词器

json
// 自定义分词器（拼音 + 中文）
PUT /hotel
{
  "settings": {
    "analysis": {
      "analyzer": {
        "pinyin_analyzer": {
          "tokenizer": "ik_max_word",
          "filter": "pinyin_filter"
        }
      },
      "filter": {
        "pinyin_filter": {
          "type": "pinyin",
          "keep_full_pinyin": false,
          "keep_joined_full_pinyin": true
        }
      }
    }
  }
}

8.2 自动补全查询（completion suggester）

json
{
  "suggest": {
    "titleSuggest": {
      "text": "sh",                  // 用户输入
      "completion": {
        "field": "title.suggest",    // 必须是 completion 类型
        "skip_duplicates": true,
        "size": 10
      }
    }
  }
}

⚠ 自动补全字段必须是 completion 类型，数据按特定格式写入。

9.5 搜索文档 ⭐⭐⭐

java
// 构建 DSL 查询
SearchRequest request = new SearchRequest("hotel");

// 1. match 查询
request.source()
    .query(QueryBuilders.matchQuery("all", "如家"))
    .from(0).size(20);

// 2. bool 查询
BoolQueryBuilder boolQuery = QueryBuilders.boolQuery();
boolQuery.must(QueryBuilders.matchQuery("all", "如家"));
boolQuery.filter(QueryBuilders.rangeQuery("price").lte(500));
request.source().query(boolQuery);

// 3. 高亮
request.source()
    .highlighter(new HighlightBuilder()
        .field("name")
        .requireFieldMatch(false));

// 4. 排序 + 分页
request.source()
    .sort(SortBuilders.fieldSort("price").order(SortOrder.ASC))
    .from(0).size(20);

// 执行查询
SearchResponse response = client.search(request, RequestOptions.DEFAULT);

// 解析结果
SearchHits hits = response.getHits();
long total = hits.getTotalHits().value;
for (SearchHit hit : hits) {
    String json = hit.getSourceAsString();
    HotelDoc doc = JSON.parseObject(json, HotelDoc.class);

    // 高亮结果处理
    Map<String, HighlightField> hlf = hit.getHighlightFields();
    if (hlf.containsKey("name")) {
        String highlightName = hlf.get("name").getFragments()[0].string();
        doc.setName(highlightName);  // 替换为高亮后的名称
    }
}

9.6 聚合查询

java
request.source()
    .size(0)   // 不返回文档
    .aggregation(AggregationBuilders.terms("brandAgg")
        .field("brand").size(20));

SearchResponse response = client.search(request, RequestOptions.DEFAULT);
Aggregations aggregations = response.getAggregations();
List<String> brandList = aggregations.get("brandAgg")
    .getBuckets().stream()
    .map(bucket -> bucket.getKeyAsString())
    .collect(Collectors.toList());

十、数据同步（MySQL ↔ ES）⭐⭐

10.1 三种方案

方案 说明 优缺点
同步调用 微服务修改 DB 后直接调 ES API 简单，但耦合高、性能差
异步通知 修改 DB 发 MQ，ES 服务消费 解耦，但引入 MQ
监听 binlog 用 Canal 监听 MySQL binlog 推到 ES 完全解耦，但增加 Canal

10.2 对比

同步调用 异步通知 监听 binlog
耦合度 高 中 低
实时性 高 中 低
复杂度 低 中 高

十一、面试常问 ⭐⭐

💡 ES 为什么搜索快？ 基于倒排索引：从词条直接定位文档，O(1)。

💡 ES 和 MySQL 的区别？ ES 基于倒排索引，适合搜索和聚合分析；MySQL 基于 B+ 树，适合事务和复杂关联。两者互补。

💡 text 和 keyword 的区别？

  • text：分词后建倒排索引（参与全文搜索）
  • keyword：不分词（精确匹配）

💡 match 和 term 的区别？

  • match：先分词再查询
  • term：不分词直接查询（keyword 字段用）

💡 bool 查询中 must 和 filter 的区别？

  • must：参与相关性算分，性能略差
  • filter：只过滤不算分，性能更好

💡 ES 深度分页怎么解决？ from + size 超过 1 万性能差，改用 search_after 或 scroll 游标。
